# incremental な方式にしたい
毎回1から読ませているので前回の結果を適当にキャッシュしておけばいいじゃんということしか考えてなかった。
あと、 LSP とか書いたりするうえでも、毎回10秒かかるのはちょっと...というだけ。
なので、中身については何も考えてないし、細かい仕様について意思決定を求められても...
仕様はコードがすっきりしていて早くなれば勝手に決めてほしい。
プランで決めてもいいけれど、実装してて難しいとわかった時にプランに愚直に従うためだけに小難しいことをするよりは、プランを捨ててほしい。

# 実装の順序と移行順序はあまり気にしてない
Phase を細かく分けても、ほしいのは完成系なのであまり中間状態でコードを読む気がない。
そもそもコードも設計も Astra の方が頭がいいので、
人間がついていくための移行中間状態を見せられるよりも、
一気に完成系までもっていった方がいいと思う。

とりあえず、 incremental checker と semantic api だけ見れればいいかな。
永続キャッシュは作ってませんが LSP は作りましたと言われても困る。
まず作ってほしいのは基盤なので。まずは semantic api を。

kernel はできる限り書き換えないし責務を増やさない方向で。
これは健全性の基盤なので、機能は少なければ少ないほどいい。
