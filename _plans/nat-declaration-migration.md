# Nat の宣言構文への移行で詰まった箇所

## 中継定義の削除

最初の移行では、既存の参照を維持するために `mod := Mod::[program]` や `modMatchesPrec` のような中継定義を残した。
これらの削除には Nat 本体だけでなく、Nat の法則、整数、有理数、ライブラリ利用例の参照更新が必要になった。
`*Prec` の仕様も correspondence の `::[set]` に移し、状態機械の呼び出しは `::[run]` にまとめている。

## 一致証明を適用するマクロ

`::[coherence]` は関数全体の等式なので、引数を適用した等式には合同則が必要になる。
これを短く書く汎用マクロを試した際、可変長トークン列を通常の関数適用に直接展開する記述が構文解析で失敗した。
再帰マクロでは、複合式を通常式として渡す波括弧も必要だった。
さらに、合同則の両方の型を `_` にすると、この用途では型推論が occurs check で失敗した。
現在は関数の型を `Add::[Type]^` などで指定して、既存の `congr!` を直接使っている。

## 補題の適用と関数引数の区別

移行スクリプトは括弧の対応を読んで補題の引数を取り出したが、式の型を考慮していなかった。
`pairIterPrecCong gcdNext^ gcdNextPrec gcdNextMatchesPrec b (natPair a b)` では、`gcdNextMatchesPrec` は関数として渡され、`b` は `pairIterPrecCong` の引数である。
スクリプトはこれを `gcdNextMatchesPrec b` と解釈し、Nat を NatPair の位置に渡す式を生成した。
この箇所は `GcdNext::[coherence]` を反復仕様全体へ合同則で写す証明に書き直した。

## 実装の反映から Set の仕様への移行

`Add::[program]^` と `Add::[set]` は `Add::[coherence]` によって等しいが、変数を含む式では定義上の変換だけで交換できない。
加算の実装は蓄積側へ successor を移す状態機械であり、Set の仕様は右引数への帰納法である。
そのため、実装に対して通った `addSuccLeft` の帰納法の枝をそのまま仕様へ移すと、帰納法の仮定を適用する引数が違い、型検査に失敗した。
仕様の証明では帰納法の仮定を `succCong` で写し、`addSuccRight` は仕様の計算則による反射律に簡約した。

乗算と累乗の仕様も、それぞれ `Add::[set]` と `Mul::[set]` を使う形に変更した。
実装との一致証明には、反復の coherence と反復する関数の coherence を合成する必要がある。
偶奇判定では Toggle と反復の二つの coherence を合成し、商と剰余の遷移では Eqb の coherence を追加している。
整数の数学側も Nat の Set 仕様を使うため、整数演算の実装との一致証明に Nat の coherence を追加している。

## GCD の計算則

`gcdZeroLeft` は、実装の状態機械なら定義上展開できた最初の遷移を使っていた。
Set の反復仕様は最後の遷移を展開するため、`PairIteration.specification #advance` を逆向きに適用して最初の遷移へ移す必要があった。
この計算順序の違いを修正すると Nat の法則全体の型検査が通った。

## 整数側への波及

Nat の法則を Set の仕様へ移した結果、整数の加算・乗算・比較・絶対値の仕様が使う Nat 演算も Set 側に合わせる必要があった。
実装は Program 側の演算を実行するため、整数の一致証明で、元の実装に対する証明と Nat の coherence を合成した。
Nat の加算と乗算に対する合同則を使い、比較の Boolean instance の変換には Choose と比較演算の二つの coherence を使った。

## 時間がかかった理由

最初に互換用の中継定義を残した設計から、その中継定義を削除する設計へ変更したため、利用側まで移行範囲が広がった。
さらに、性質を `::[set]` に移す変更は計算則の変更を伴い、参照名の更新に加えて証明の修正が必要になった。
移行用スクリプトが式の型を考慮せず、関数として渡される補題を誤って適用したことと、型を省略したマクロの試行も追加の手戻りになった。
構文解析は比較的すぐ通ったが、型検査が最初のエラーで終了するため、依存順に Nat、GCD、整数の各証明を直して検査し直した。

## 検査結果

最終変更について、標準ライブラリと `tests/projects/library` のキャッシュを使わない型検査が両方通った。
構文解析と `git diff --check` も通った。
