# Program に CBV の省略記法を追加する

## 概要

Program 側で `->`・`\fun`・カリー化された関数の適用を使えるようにする。既存の CBPV 構文への展開として実装し、新旧の記法を混在可能にする。kernel の型体系・評価規則は変更しない。

次の定義が、提示された従来の定義と同じ型・項へ展開されることを主な受け入れ条件とする。

```text
\cdefinition and: Bool -> Bool -> Bool :=
  \fun (x, y: Bool) =>
    \match x \in Bool \with {
    | false => \return(Bool::false);
    | true => \return(y);
    };
```

## 構文と互換性

- Program の値型としての解釈を `V`、計算型としての解釈を `C` とすると、`C(A -> B) = V(A) ~> \F(V(B))`、`V(A -> B) = \U(C(A -> B))` とする。矢印は既存どおり右結合。
- `\cdefinition` の型は `C`、`\vdefinition` の型と関数引数の型は `V` で解釈する。`\Box`・`\box`・`\Force` の型指定にある裸の `->` は計算型とする。関数値を指定する場合は `\U(A -> B)` と書く。
- `~>`・`\F`・`\U` は各構成要素に必要なカテゴリで再帰的に解釈する。例えば `A ~> (B -> C)` は許可する。`->` の右辺には値型が必要で、`A -> \F(B)` はエラーとする。
- 計算位置の `\fun` は外側を `\cfun` に、値位置の `\fun` はそれを包む `\thunk` に展開する。複数引数と連続した `\fun` は同じ CBV カリー化として扱い、引数間に `\return(\thunk(...))` を挿入する。
- `\fun` の最後の本体は値を返す計算とし、末尾の `\return` は明示する。任意の値・計算への一般的な `return`・`thunk` の自動挿入は追加しない。
- Set/Prop 側の構文、既存の `\cfun`、および `\cdefinition f(x: A, y: B): C` の展開は維持する。帰納型のコンストラクタ宣言にある引数列の `->` も維持し、関数値のフィールドは `(A -> B)` と書けるようにする。Program の依存関数型や refinement 束縛は追加しない。

## 適用と実装方針

- [syntax.rs](../src/front/src/syntax.rs) の Program カテゴリへの分類で、型とラムダの省略記法を受け付ける。字句・演算子の優先順位は変更しない。
- 適用の関数位置は、値参照か計算参照かを名前解決まで保留できる表現にする。ローカル変数、モジュール引数、定義、型関連項、明示的な thunk を扱い、コンストラクタ適用との区別を維持する。
- [program_term_elaborator.rs](../src/front/src/elaborator/program_term_elaborator.rs) で、通常の計算関数には直接適用し、`U(A ~> C)` の関数値には `force`、`F(U(A ~> C))` の計算結果には `bind` と `force` を挿入する。判断には展開後の型を使い、元の型注釈の記法には依存させない。
- 引数は値に限定する。`f x y`、`f (\fun ...)`、コンストラクタ値の引数は対応する。`f (g x)` の `g x` が計算である場合は、明示的な `bind` を求める。部分適用の結果も、その型が `F(U(...))` なら計算として扱う。
- 期待型をラムダ・適用の elaboration に伝え、未確定の型による適用判断は front 内の制約として保留する。既存の型制約と合わせて解決し、解釈が確定しない場合は型注釈を求めるエラーにする。未解決の省略記法は kernel に渡さない。
- 挿入する束縛は変数を捕捉しないように生成し、局所変数の添字と停止性証明の対応を保つ。定義・検査コマンド・推論コマンド・`\box` で同じ展開処理を使い、補完後の項から証明付きの反映を生成する。
- 推論・評価結果の表示は、既存の明示的な CBPV 記法を維持する。

## 検証

- 一引数・二引数・三引数・高階関数について、新旧の型と項が α 同値になることを確認する。複数引数と連続した `\fun` も比較する。
- 新型注釈と旧本体、旧型注釈と新本体、明示的な `bind`・`force` と自動補完を組み合わせ、型検査と評価結果を比較する。
- Bool の四通りの入力、部分適用、関数値の適用、変数の隠蔽、型パラメータと `_` の推論を確認する。
- `\Box`・`\box`・`\Force` の計算型既定値と明示的な `\U` を検証し、停止性証明付きの再帰を含む関数でも反映が成立することを確認する。
- 計算を引数に渡す式、非関数への適用、値型・計算型の取り違え、解釈不能な型穴、Program の依存型を拒否する。
- 既存の明示的な適用・定義ヘッダ・コンストラクタ構文の回帰テストを維持する。`cargo test --workspace` で正常系・異常系・既存ライブラリの検査を通す。
