# エラー診断の改善

大きな証明のエラーでは、制約の再検査と関連制約の表示がエラー本体の表示よりも重くなる。
診断の生成中にメモリや実行時間を使い切ると、原因の確認ができない。

## 現在使える簡潔な診断

`REF_TYPE_COMPACT_DIAGNOSTICS=1` を設定すると、型検査エラーに付随する制約診断の生成を省略する。
未解決ゴールでは、関連制約の探索と再検査を省略し、ゴールと文脈を表示する。
最初のエラーが確定した後の独立したモジュールの検査を省略し、そのエラーを返す。
構文エラーがある場合も、型検査を始める前にそのエラーを返す。
エラーの成否とソース位置は通常の診断と共通である。

```sh
REF_TYPE_COMPACT_DIAGNOSTICS=1 target/debug/cli libs/category
```

このモードは、大きな入力でエラー本体を速く確認するための常設機能とする。

## 改善する内容

1. エラー本体とソース位置を先に確定し、詳細な制約診断は必要になったときに生成する。
2. 制約の状態を保存し、診断のためだけに解決済みの制約を型検査し直す処理を減らす。
3. 関連制約の探索、表示件数、式の表示深さと出力サイズに上限を設け、省略した量を示す。
4. 共有された大きな式を何度も展開する表示を避け、名前や共有部分の参照で表示する。
5. 簡潔な診断を CLI のオプションからも選べるようにし、詳細表示への切り替えを明確にする。
6. 診断の生成時間とメモリ使用量を、宣言の検査時間から区別して計測する。
7. 大きな共有式と多数の制約を持つ失敗例で、簡潔な診断の時間と出力サイズを検証する。

## モジュール参照時の再処理

圏論ライブラリの検査では、同じモジュールを参照し直す箇所の後に、標準ライブラリや圏論の同じ宣言の検査ログが繰り返し出た。
簡潔な診断を有効にしても再処理が発生し、時間上限までにエラー本体を取得できない場合があった。
再処理を開始する条件と、通常の具体化に必要な処理なのか、失敗からの復旧による再試行なのかは未確定である。
`src/sema/src/database.rs` の `Database::query` には、失敗後に独立したスコープを新しい `Checker` で検査し直す経路がある。
この経路と観測した再処理との対応、検査済みの依存まで再検査する必要性を調べる。
簡潔なモードで後続検査を省略すると、Kan 拡張の具体化で `module arguments do not allow inference holes` が約27秒で表示された。
後続検査を続けた同じ調査では、50秒と100秒の CPU 上限に達してもエラーが表示されなかった。
これらは最適化した開発用ビルドによる観測値であり、入力を縮約した再現例と比較条件を揃えた計測を追加する。

```sh
REF_TYPE_PROFILE_DECLARATIONS=1 REF_TYPE_COMPACT_DIAGNOSTICS=1 target/debug/cli libs/category
```

1. モジュールの読込、引数の具体化、型検査、失敗後の再試行を区別して計測し、同じ宣言を再検査する呼出経路を特定する。
2. 参照元、具体化した引数、環境の版、キャッシュの命中・失敗を記録し、同じ参照に対する重複処理を確認する。
3. 親モジュール内から子を参照する場合と、検査済みの別モジュールから参照する場合を小さな入力で比較する。
4. 検査済みのモジュールと同じ引数の具体化を再利用できる範囲を調べ、失敗が確定した参照の再試行も整理する。
5. 大きな失敗例で、診断の生成とモジュールの再処理をそれぞれ計測し、終了状態とソース位置を保ったまま重複した検査を減らす。

調査に使った参照の形は次である。
`category` に依存するパッケージでこのモジュールと独立したモジュールを検査し、通常モードと簡潔なモードを比較する。

```text
\import category.Category[] \as Cat;
\import category.Functor[] \as Functors;

\module Reproduction(A, C: Cat.Category, F: Functors.Functor A C) {
  \import category.Kan[].Along[A := A, B := A, C := C,
    K := Functors.identity A, F := F] \as Extension;
}
```

## 検証条件

通常モードと簡潔なモードで終了状態、エラー本体、ソース位置が一致することを確認する。
未解決ゴールの文脈と型を保ち、制約一覧を省略しても原因を追えることを確認する。
通常モードの詳細な制約表示も引き続き検証する。
