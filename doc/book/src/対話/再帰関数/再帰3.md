# `Rf(run(f,a))` による compile-time evaluation

ここでは、Compute 側の停止が証明された計算を Set 側で compile-time evaluation として使うために、

\[
\operatorname{Rf}(\operatorname{run}(f,a))
\]

を認める方法を考える。

提案の中心は次の rule である。

\[
\dfrac{
  \Gamma\vdash \operatorname{run}_{A,B}(f,a):B:*^c
}{
  \operatorname{Rf}(\Gamma)
  \vdash
  \operatorname{Rf}(\operatorname{run}_{A,B}(f,a))
  :
  \operatorname{Rf}(B):*^s_0
}.
\]

`run` の typing premise には既に停止性の証明が含まれる。したがって、この rule は「停止が証明された Compute 項だけを Set 項として反映する」ことを表す。

この方向は定式化可能だと思われる。ただし、typability だけでは compile-time evaluation の動作は定まらない。`Rf(run(f,a))` の typing rule に加えて、その reduction、subject reduction、および accessibility から実行の停止が得られることを定式化する必要がある。

## 1. Sort

Set/Prop 側は `system.md` のままとし、階層化しない Compute sort を追加する。

\[
\begin{aligned}
\mathcal{S}'
:={}&
\{*^s_i,\square^s_i\mid i\in\mathbb{N}\} \\
&\cup\{*^p,\square^p\}
\cup\{*^c,\square^c\}.
\end{aligned}
\]

Compute 側の axiom と product rule は次だけとする。

\[
\mathcal{A}_c:=\{(*^c,\square^c)\}.
\]

\[
\mathcal{R}_c:=\{(*^c,*^c,*^c)\}.
\]

$\square^c$ は $*^c:\square^c$ を述べるためだけに使う。$\square^c$ に対する axiom や、$\square^c$ を含む product rule は追加しない。

$\mathcal{R}_c$ だけからなる純粋な PTS では、Compute 項 $x:A$ に依存する Compute 型を構成できない。そのため、$x\notin\operatorname{FV}(B)$ という side condition は追加しない。

Compute 側では、実質的に次の非依存関数型が形成される。

\[
\dfrac{
  \Gamma\vdash A:*^c
  \qquad
  \Gamma\vdash B:*^c
}{
  \Gamma\vdash A\to B:*^c
}.
\]

## 2. Compute term

Compute 側には、通常の lambda term、非依存な代数的データ型、その recursor、および `run` を置く。

\[
\begin{aligned}
m ::= {}&
x
\mid \lambda x:A.m
\mid m\,m \\
&\mid C(m_1,\ldots,m_n)
\mid \operatorname{elim}_I(m,m_1,\ldots,m_n) \\
&\mid \operatorname{run}_{A,B}(f,a).
\end{aligned}
\]

`run` を含まない Compute 項を pure Compute term と呼び、$p$ で表す。これは専用の typing judgement ではなく、raw syntax に対する構文的な性質である。

`run` の一段遷移関数と状態は pure Compute term に制限する。

\[
\operatorname{run}_{A,B}(p_f,p_a).
\]

この制限により、一段遷移自体は一般再帰を含まない。non-structural recursion は `run` だけが導入する。

## 3. Type reflection

Compute 型を Set 側の固定 universe $*^s_0$ へ写す。この写像自体は raw syntax 上のメタレベル関数とする。

| Compute type | reflected Set type |
| --- | --- |
| $*^c$ | $*^s_0$ |
| base type $X$ | corresponding Set type $\widehat X$ |
| $A\to B$ | $\operatorname{Rf}(A)\to\operatorname{Rf}(B)$ |
| $I(A_1,\ldots,A_n)$ | $\widehat I(\operatorname{Rf}(A_1),\ldots,\operatorname{Rf}(A_n))$ |

すべての Compute base type と Compute inductive type が $*^s_0$ に reflection できることを仮定する。したがって、

\[
\Gamma\vdash A:*^c
\quad\Longrightarrow\quad
\operatorname{Rf}(\Gamma)
\vdash
\operatorname{Rf}(A):*^s_0
\]

である。

Compute 変数とその reflected Set 変数を同時に扱うため、context は synchronized context とする。Compute entry $x:A:*^c$ を追加するとき、対応する Set entry $\widehat x:\operatorname{Rf}(A):*^s_0$ も追加する。

\[
\Xi
::=
\varnothing
\mid
\Xi,(x:A:*^c\leftrightarrow
      \widehat x:\operatorname{Rf}(A):*^s_0)
\mid
\Xi,y:T:s,
\]

ただし、最後の entry の $s$ は Set/Prop sort である。

synchronized context の Compute projection を $\Xi_c$、description projection を $\Xi_s$ と書く。

\[
\begin{aligned}
\varnothing_c&:=\varnothing,
&\varnothing_s&:=\varnothing,\\
\left(\Xi,(x:A\leftrightarrow\widehat x:\operatorname{Rf}(A))\right)_c
&:=\Xi_c,x:A:*^c,
&
\left(\Xi,(x:A\leftrightarrow\widehat x:\operatorname{Rf}(A))\right)_s
&:=\Xi_s,\widehat x:\operatorname{Rf}(A):*^s_0.
\end{aligned}
\]

Set/Prop entry $y:T:s$ は両方の projection にそのまま保つ。これにより、Compute 変数 $x$ に対応する $\widehat x$ を使った停止性命題や、その証明仮定を description projection に置ける。

\[
\operatorname{Rf}(\Xi)
:=
\Xi_s.
\]

以下で $\Gamma$ と書くときはこの synchronized context を意味し、Compute typing の premise では $\Gamma_c$、Set/Prop typing の premise では $\operatorname{Rf}(\Gamma)=\Gamma_s$ を使う。

## 4. `Rf` term

### 4.1 `Rf` を object term とする理由

pure Compute term だけを reflection する場合、$\operatorname{Rf}$ をメタレベルの構文変換として定義できた。しかし、`run` を含む開いた項は、compile time に必ずしも最終値まで簡約できない。

例えば、

\[
\lambda x:A.\operatorname{run}(f,x)
\]

を reflection するとき、$x$ が未知なので `run` の結果を直接 Set の値に変換できない。Set 側に残る residual term が必要になる。

そのため、項の構文に次を追加する。

| category | syntax |
| --- | --- |
| reflection | $\operatorname{Rf}(m)$ |

$\operatorname{Rf}$ は `quote` と `comp` を統合した cross-sort operator である。PTS では型も項なので、型と値の reflection に別々の operator を置く必要はない。

### 4.2 Typing

reflection 専用の judgement は導入せず、通常の typing judgement に次の rule を追加する。

\[
\dfrac{
  \Gamma\vdash m:A:*^c
}{
  \operatorname{Rf}(\Gamma)
  \vdash
  \operatorname{Rf}(m):\operatorname{Rf}(A):*^s_0
}.
\tag{Rf}
\]

`Rf` は cross-sort operator なので、その Set 側の自由変数を次のように定義する。

\[
\operatorname{FV}_s(\operatorname{Rf}(m))
:=
\{\widehat x\mid x\in\operatorname{FV}_c(m)\}.
\]

したがって、$m$ の中の Compute 変数 $x$ は、$\operatorname{Rf}(m)$ の中では synchronized context 上の Set 変数 $\widehat x$ に binding される。

特に、

\[
\Gamma\vdash\operatorname{run}_{A,B}(f,a):B:*^c
\]

が導出できるならば、

\[
\operatorname{Rf}(\Gamma)
\vdash
\operatorname{Rf}(\operatorname{run}_{A,B}(f,a))
:
\operatorname{Rf}(B):*^s_0
\]

を導出できる。`run` の typing には停止性の premise が必要なので、停止性を示せない `run` を Set 側に reflection することはできない。

## 5. Structural reflection

`run` 以外の Compute 構文の reflection は、従来どおり構文に関して準同型的に簡約する。内部の $M,N,M_i$ に `run` が現れていてもよい。structural reflection は外側の構文を Set 側へ写し、内部の `run` を $\operatorname{Rf}(\operatorname{run}(-,-))$ として residualize する。

| source | target |
| --- | --- |
| $\operatorname{Rf}(x)$ | $\widehat x$ |
| $\operatorname{Rf}(\lambda x:A.M)$ | $\lambda\widehat x:\operatorname{Rf}(A).\operatorname{Rf}(M)$ |
| $\operatorname{Rf}(M\,N)$ | $\operatorname{Rf}(M)\,\operatorname{Rf}(N)$ |
| $\operatorname{Rf}(C(M_1,\ldots,M_n))$ | $\widehat C(\operatorname{Rf}(M_1),\ldots,\operatorname{Rf}(M_n))$ |
| $\operatorname{Rf}(\operatorname{elim}_I(M,M_1,\ldots,M_n))$ | $\operatorname{elim}_{\widehat I}(\operatorname{Rf}(M),\operatorname{Rf}(M_1),\ldots,\operatorname{Rf}(M_n))$ |

これらは共通の reduction $\to$ に追加する root reduction rule である。

reflection と substitution について、general Compute term $M,N$ に対する次の補題が必要になる。

\[
\operatorname{Rf}(M[x:=N])
\equiv
\operatorname{Rf}(M)
[\widehat x:=\operatorname{Rf}(N)].
\]

例えば、reflected $\beta$-redex は次のように簡約する。

\[
\begin{aligned}
\operatorname{Rf}((\lambda x:A.M)\,N)
&\to
(\lambda\widehat x:\operatorname{Rf}(A).\operatorname{Rf}(M))
\operatorname{Rf}(N) \\
&\to
\operatorname{Rf}(M)
[\widehat x:=\operatorname{Rf}(N)] \\
&\equiv
\operatorname{Rf}(M[x:=N]).
\end{aligned}
\]

したがって、$\beta$-reduction や recursor reduction のために

\[
\dfrac{m\to m'}
      {\operatorname{Rf}(m)\to\operatorname{Rf}(m')}
\]

という一般的な primitive rule を追加する必要はない。

## 6. Accessibility と `run`

### 6.1 Accessibility

Set/Prop 側の一般的な帰納型として accessibility を使う。

\[
\operatorname{Acc}_X
:
(X\to X\to *^p)
\to
X
\to
*^p.
\]

constructor は `acc` 一つである。

\[
\operatorname{acc}_{R,x}
:
\left(
  (y:X)
  \to
  R\,y\,x
  \to
  \operatorname{Acc}_X(R,y)
\right)
\to
\operatorname{Acc}_X(R,x).
\]

### 6.2 Transition relation

pure Compute term

\[
\Gamma\vdash f:A\to A+B:*^c
\]

に対して、Set 側の関係を次のように定義する。

\[
R_f
:
\operatorname{Rf}(A)
\to
\operatorname{Rf}(A)
\to
*^p.
\]

\[
R_f(a',a)
:=
\operatorname{Rf}(f)\,a
=_{\operatorname{Rf}(A)+\operatorname{Rf}(B)}
\operatorname{left}(a').
\]

停止性は次の略記とする。

\[
\operatorname{Terminates}_{A,B}(f,a)
:=
\operatorname{Acc}_{\operatorname{Rf}(A)}
\left(R_f,\operatorname{Rf}(a)\right).
\]

### 6.3 `run` typing

\[
\dfrac{
\begin{array}{c}
\Gamma\vdash f:A\to A+B:*^c
\\[2pt]
\Gamma\vdash a:A:*^c
\\[2pt]
f,a\text{ are pure Compute terms}
\\[2pt]
\operatorname{Rf}(\Gamma)
\vDash
\operatorname{Terminates}_{A,B}(f,a)
\end{array}
}{
\Gamma
\vdash
\operatorname{run}_{A,B}(f,a):B:*^c
}.
\tag{Run}
\]

この derivation を premise として `(Rf)` rule を使うことで、$\operatorname{Rf}(\operatorname{run}(f,a))$ を Set 項として導入できる。

## 7. Reduction

Set/Prop/Compute で共通の reduction relation $\to$ を使う。$\to_c$ や $\to_s$ は導入しない。

### 7.1 `run` reduction

Compute 側の `run` に次の root reduction rule を追加する。

| category | reduction | condition |
| --- | --- | --- |
| Run-End | $\operatorname{run}_{A,B}(f,a)\to b$ | $f\,a\to^*\operatorname{right}(b)$ |
| Run-Step | $\operatorname{run}_{A,B}(f,a)\to\operatorname{run}_{A,B}(f,a')$ | $f\,a\to^*\operatorname{left}(a')$ |

$f$ と $a$ は pure なので、condition に現れる reduction の中で `run` rule が使われることはない。

### 7.2 Reflected `run` reduction

`run` 以外の構文に対する structural reflection だけでは、$\operatorname{Rf}(\operatorname{run}(f,a))$ を簡約できない。そのため、次の二つを共通 reduction $\to$ に追加する。

| category | reduction | condition |
| --- | --- | --- |
| Rf-Run-End | $\operatorname{Rf}(\operatorname{run}_{A,B}(f,a))\to\operatorname{Rf}(b)$ | $f\,a\to^*\operatorname{right}(b)$ |
| Rf-Run-Step | $\operatorname{Rf}(\operatorname{run}_{A,B}(f,a))\to\operatorname{Rf}(\operatorname{run}_{A,B}(f,a'))$ | $f\,a\to^*\operatorname{left}(a')$ |

これらは一般的な

\[
\dfrac{m\to m'}
      {\operatorname{Rf}(m)\to\operatorname{Rf}(m')}
\]

を追加するものではない。`Rf` の内部で必要なだけの Compute reduction を行う、`run` 専用の root rule である。

これにより、閉じた停止計算は次のように Set 側で計算される。

\[
\begin{aligned}
\operatorname{Rf}(\operatorname{run}(f,a_0))
&\to
\operatorname{Rf}(\operatorname{run}(f,a_1)) \\
&\to\cdots\to
\operatorname{Rf}(\operatorname{run}(f,a_n)) \\
&\to
\operatorname{Rf}(b)
\to^*
\widehat b.
\end{aligned}
\]

最後の $\widehat b$ は、pure Compute value $b$ を structural reflection した Set 値を表す。

### 7.3 Alternative: congruence under `Rf`

reduction をすべての term context の下で compatible closure として定義し、`Rf(-)` も term context に含めるならば、

\[
m\to m'
\quad\Longrightarrow\quad
\operatorname{Rf}(m)\to\operatorname{Rf}(m')
\]

は congruence として自動的に得られる。この場合、Rf-Run-End と Rf-Run-Step を個別に追加する必要はない。

ただし、これは実質的に一般の $\operatorname{Rf}(m)\to\operatorname{Rf}(m')$ を認めることになる。ここでは reduction を小さく保つため、`Rf` の引数位置を一般の reduction context に含めず、Rf-Run-End/Rf-Run-Step を明示的に与える方を採用する。

## 8. Subject reduction

### 8.1 Run-Step

Run-Step の場合には、次の accessibility descent を使う。

\[
\operatorname{Acc}_X(R,x)
\land
R(y,x)
\quad\Longrightarrow\quad
\operatorname{Acc}_X(R,y).
\]

$f\,a\to^*\operatorname{left}(a')$ と structural reflection から、

\[
\operatorname{Rf}(f)\,\operatorname{Rf}(a)
\to^*
\operatorname{left}(\operatorname{Rf}(a'))
\]

が得られる。したがって、

\[
R_f(\operatorname{Rf}(a'),\operatorname{Rf}(a))
\]

が成り立ち、

\[
\operatorname{Terminates}(f,a)
\quad\Longrightarrow\quad
\operatorname{Terminates}(f,a')
\]

である。よって、

\[
\Gamma\vdash\operatorname{run}(f,a'):B:*^c
\]

を導出できる。

### 8.2 Rf-Run-Step

Run-Step の subject reduction から `(Rf)` rule をもう一度使うことで、

\[
\operatorname{Rf}(\Gamma)
\vdash
\operatorname{Rf}(\operatorname{run}(f,a'))
:
\operatorname{Rf}(B):*^s_0
\]

を得る。したがって Rf-Run-Step も typing を保つ。

### 8.3 Rf-Run-End

$f\,a\to^*\operatorname{right}(b)$ と Compute 側の subject reduction/inversion から、

\[
\Gamma\vdash b:B:*^c
\]

を得る。`(Rf)` rule から、

\[
\operatorname{Rf}(\Gamma)
\vdash
\operatorname{Rf}(b):\operatorname{Rf}(B):*^s_0
\]

である。したがって Rf-Run-End も typing を保つ。

## 9. Typability だけで十分か

`Rf(run(f,a))` の typing rule を

\[
\Gamma\vdash\operatorname{run}(f,a):B:*^c
\]

から導くという方針は、停止性の証明を二重に要求しないという点で自然である。ただし、それだけで次が自動的に得られるわけではない。

| property | additional argument required |
| --- | --- |
| reflected execution terminates | `Acc` から Run-Step 列が有限であることを示す |
| result has the expected type | Compute subject reduction と `(Rf)` typing rule を使う |
| result is independent of termination proof | pure transition $f$ の determinism を使う |
| reduction is coherent | structural reflection と Rf-Run rules の critical pair を調べる |
| logical consistency | `Rf(run(f,a))` を well-founded iteration としてモデル化する |

つまり、typability は `Rf(run(f,a))` を導入するための正しい入口だが、停止性と健全性は別途メタ理論で示す必要がある。

## 10. 開いた context と閉じた計算

閉じた `run` については、

\[
\varnothing
\vdash
\operatorname{run}(f,a):B:*^c
\]

の derivation に含まれる停止性証明から、$\operatorname{Rf}(\operatorname{run}(f,a))$ の compile-time evaluation が停止することを示せると期待できる。

一方、開いた context では、

\[
p:
\operatorname{Terminates}(f,a)
\]

を仮定することで `run(f,a)` および `Rf(run(f,a))` を型付けできる。この context が意味的に inhabit されない場合、実際の reduction が停止するとは限らない。

これは直ちに空 context での無矛盾性を壊すものではないが、「あらゆる well-formed context で reduction が strong normalization する」という性質は別の問題になる。

最初に無矛盾性と compile-time evaluation を調べる段階では、次のどちらかに制限する方法もある。

| restriction | consequence |
| --- | --- |
| reflection of closed `run` only | compile-time evaluation の停止を直接示しやすいが、開いた関数を reflection できない |
| reflection of arbitrary typable `run` | 開いた関数を Set 側に residualize できるが、開いた context での normalization は別途検討が必要 |

ここでは表現力を優先し、後者の「任意の typable な `run` を reflection できる」rule を採用する。

## 11. モデルの候補

Set/Prop 側のモデルが与えられたとする。Compute 型 $A$ は reflected Set $\llbracket\operatorname{Rf}(A)\rrbracket$ と同じ集合として解釈する。pure Compute term も、その structural reflection と同じ関数として解釈する。

\[
\llbracket A\rrbracket_c
:=
\llbracket\operatorname{Rf}(A)\rrbracket_s.
\]

\[
\llbracket p\rrbracket_c
:=
\llbracket\operatorname{Rf}(p)\rrbracket_s.
\]

`run(f,a)` は、typing derivation に含まれる

\[
\operatorname{Acc}(R_f,\operatorname{Rf}(a))
\]

の証拠に従って $f$ を well-founded iteration し、最初に得られる $\operatorname{right}(b)$ の $b$ として解釈する。

\[
\llbracket\operatorname{run}(f,a)\rrbracket_c
:=
\operatorname{wfRun}
\left(
  \llbracket f\rrbracket_c,
  \llbracket a\rrbracket_c
\right).
\]

reflected run も同じ値として解釈する。

\[
\llbracket
  \operatorname{Rf}(\operatorname{run}(f,a))
\rrbracket_s
:=
\llbracket\operatorname{run}(f,a)\rrbracket_c.
\]

一段遷移 $f$ は決定的な関数なので、停止性の証拠が異なっても結果 $b$ は同じである。これにより、`Rf(run(f,a))` の解釈は typing derivation の選び方に依存しないと期待できる。

このモデルを構成できれば、`Rf(run(f,a))` を追加した拡張の無矛盾性を、Set/Prop 側のモデルの存在に相対的に示せる。

## 12. 必要なメタ定理

| property | statement |
| --- | --- |
| Compute subject reduction | $\Gamma\vdash m:A:*^c$ かつ $m\to m'$ ならば $\Gamma\vdash m':A:*^c$ |
| reflection substitution | reflection が Compute substitution を Set substitution へ写す |
| structural reflection preservation | pure Compute reduction が reflected Set reduction によって simulation される |
| accessibility descent | $\operatorname{Acc}(R,x)$ かつ $R(y,x)$ ならば $\operatorname{Acc}(R,y)$ |
| run termination | `Run` rule の accessibility premise から Run-Step 列の有限性を示す |
| reflected-run subject reduction | Rf-Run-End/Rf-Run-Step が Set typing を保つ |
| reflected-run normalization | 閉じた typable な `Rf(run(f,a))` が reflected value に到達する |
| determinism | pure transition と `run` の結果が一意である |
| model soundness | typing と reduction の各 rule が上のモデルで健全である |

## 13. 追加される構文の整理

| name | status |
| --- | --- |
| $*^c,\square^c$ | 非階層の Compute sort として追加する |
| `left`, `right` | 通常の sum 型として共有する |
| `Acc`, `acc` | 一般的な accessibility として追加する |
| `run` | non-structural recursion 用の Compute term として追加する |
| `Rf` | Compute 項を Set 側に持ち上げる cross-sort term として追加する |
| `terminates` | $\operatorname{Acc}(R_f,-)$ の略記とし、追加しない |
| `End`, `Step` | 追加しない |
| `quote`, `comp` | `Rf` に統合し、追加しない |
| `return` | 追加しない |
| `Nat`, `0`, `Succ`, `iter` | 停止性のためには追加しない |
| $\vdash_{\operatorname{Rf}}$ | 追加しない |
| $\to_c,\to_s$ | 追加しない |

この定式化で object-language に追加される主な機構は次である。

\[
\boxed{
  *^c,
  \quad
  \operatorname{Acc}/\operatorname{acc},
  \quad
  \operatorname{run},
  \quad
  \operatorname{Rf}
}.
\]

`Rf` を object term に戻すため `再帰2.md` より構文は一つ増える。その代わり、停止が証明された Compute 計算を Set 側で実際に計算し、その結果を description や型の構成に使える。
