# Church encoding から見た accessibility、sum、`runCase`

## 体系定義

`再帰6.md` の体系を基準にして、まず現在の Prop だけで定義できる Church encoding を与える。
その後、Compute sum の Church encoding に必要な別体系を比較対象として定義する。

### 構文定義

#### Church encoding された accessibility

\(X:*^s_i\) と

\[
R:X\to X\to *^p
\]

を仮定する。\(X\) 上の predicate family と、\(R\)-progressive であることを次の略記で表す。

\[
\operatorname{Pred}(X)
:=
(x^{*^s_i}:X)\to *^p.
\]

\[
\operatorname{Prog}_R(P)
:=
(x:X)\to
\left(
  (y:X)\to R@y@x\to P@y
\right)
\to P@x.
\]

Church encoding された accessibility を次で定義する。

\[
\operatorname{Acc}^{\mathsf{Ch}}_X(R,a)
:=
\left(P^{\square^p}:\operatorname{Pred}(X)\right)
\to
\operatorname{Prog}_R(P)
\to
P@a.
\tag{Acc-Ch}
\]

これは raw constructor ではなく、product、application、既存の sort からなる略記である。

対応する introduction term を次で定義する。

\[
\begin{aligned}
\operatorname{acc}^{\mathsf{Ch}}_{X,R,a}(h)
:={}&
\lambda P.\lambda s.\,
s@a@
\left(
  \lambda y.\lambda r.\,
  h@y@r@P@s
\right).
\end{aligned}
\tag{acc-Ch}
\]

ここで \(h\) の型は

\[
(y:X)\to
R@y@a\to
\operatorname{Acc}^{\mathsf{Ch}}_X(R,y)
\]

である。

#### 比較用の polymorphic Compute

Compute sum を Church encoding する別体系を \(\mathcal T_{\mathsf{ChSum}}\) とする。この体系では
Compute product rule に次を加える。

\[
(\square^c,*^c,*^c).
\tag{Compute-Poly}
\]

これにより Compute type 上の impredicative polymorphism が形成できる。比較用の Church sum は

\[
A+^{\mathsf{Ch}}B
:=
\left(C^{\square^c}:*^c\right)
\to
(A\to C)
\to
(B\to C)
\to
C
\tag{Sum-Ch}
\]

である。二つの injection は lambda 項として定義する。

\[
\begin{aligned}
\operatorname{left}^{\mathsf{Ch}}_{A,B}(a)
&:=
\lambda C.\lambda l.\lambda r.\,l@a,\\
\operatorname{right}^{\mathsf{Ch}}_{A,B}(b)
&:=
\lambda C.\lambda l.\lambda r.\,r@b.
\end{aligned}
\tag{Sum-Ch-Intro}
\]

### Judgement 定義

judgement は `system.md` および `再帰6.md` と同じ四種類である。

\[
\operatorname{WF}(\Gamma),
\qquad
\Gamma\vdash t:s,
\qquad
\Gamma\vdash t:T:s,
\qquad
\Gamma\vDash P.
\]

Church accessibility は現在の judgement だけで型付けする。Church sum の比較時にも judgement は
増やさず、違いは product rule `(Compute-Poly)` だけに置く。

### Derivation 定義

\(\Gamma\vdash X:*^s_i\) ならば、既存の product rule

\[
(*^s_i,\square^p,\square^p),
\qquad
(\square^p,*^p,*^p)
\]

により

\[
\Gamma\vdash\operatorname{Pred}(X):\square^p
\]

および

\[
\Gamma\vdash
\operatorname{Acc}^{\mathsf{Ch}}_X(R,a):*^p
\]

を得る。

`acc-Ch` は次の型を持つ。

\[
\operatorname{acc}^{\mathsf{Ch}}_{X,R,a}
:
\left(
  (y:X)\to
  R@y@a\to
  \operatorname{Acc}^{\mathsf{Ch}}_X(R,y)
\right)
\to
\operatorname{Acc}^{\mathsf{Ch}}_X(R,a).
\]

比較用体系 \(\mathcal T_{\mathsf{ChSum}}\) では、`Compute-Poly` により

\[
\Gamma\vdash A+^{\mathsf{Ch}}B:*^c
\]

となり、二つの injection は

\[
\begin{aligned}
\Gamma\vdash
\operatorname{left}^{\mathsf{Ch}}_{A,B}(a)
&:A+^{\mathsf{Ch}}B:*^c,\\
\Gamma\vdash
\operatorname{right}^{\mathsf{Ch}}_{A,B}(b)
&:A+^{\mathsf{Ch}}B:*^c
\end{aligned}
\]

と型付けされる。

### Reduction 定義

Church accessibility に固有の root reduction はなく、略記の展開と既存の beta reductionを使う。
特に、

\[
\begin{aligned}
&\operatorname{acc}^{\mathsf{Ch}}_{X,R,a}(h)@P@s\\
&\qquad\to^*
s@a@
\left(
  \lambda y.\lambda r.\,
  h@y@r@P@s
\right).
\end{aligned}
\tag{acc-Ch-Beta}
\]

比較用の Church sum も beta reduction だけで branch を選択する。

\[
\begin{aligned}
\operatorname{left}^{\mathsf{Ch}}(a)@C@l@r
&\to^* l@a,\\
\operatorname{right}^{\mathsf{Ch}}(b)@C@l@r
&\to^* r@b.
\end{aligned}
\tag{Sum-Ch-Beta}
\]

`再帰6.md` の `run` と `runCase` は次の root reduction を持つ。

\[
\operatorname{run}_{A,B}(f,a)
\to
\operatorname{runCase}_{A,B}(f,a,f@a).
\tag{Run-Enter}
\]

\[
\begin{aligned}
\operatorname{runCase}_{A,B}
(f,a,\operatorname{right}_{A,B}(b))
&\to b,\\
\operatorname{runCase}_{A,B}
(f,a,\operatorname{left}_{A,B}(a'))
&\to\operatorname{run}_{A,B}(f,a').
\end{aligned}
\tag{RunCase-Branch}
\]

第三引数は compatible reduction により進む。typing derivation には

\[
\operatorname{RunInv}_{A,B}(f,a,u)
:=
\operatorname{RfTerm}_{A+B}(f@a)
=
\operatorname{RfTerm}_{A+B}(u)
\]

を premise として保持する。

以下では Compute state \(a',a:A\) に対する reflected relation を

\[
a'\prec_f a
:=
R_f@
\operatorname{RfTerm}_A(a')@
\operatorname{RfTerm}_A(a)
\tag{Reflected-Step}
\]

と略記する。

## `Acc` は induction principle そのものである

`Acc-Ch` は

> \(R\)-progressive な任意の predicate \(P\) が \(a\) で成立する

という命題である。したがって、primitive な accessibility に対する well-founded induction principle
を一つの proof term に package したものと読める。

primitive な `Acc` とその Prop eliminatorを仮定する場合、

\[
\operatorname{accFold}
:
(p:\operatorname{Acc}_X(R,a))
\to
(P:\operatorname{Pred}(X))
\to
\operatorname{Prog}_R(P)
\to
P@a
\]

が得られる。従って

\[
\operatorname{encode}(p)
:=
\lambda P.\lambda s.\,
\operatorname{accFold}@p@P@s
:
\operatorname{Acc}^{\mathsf{Ch}}_X(R,a)
\]

である。これは `acc_ind` が Church encoding の中身になっていることを直接表している。

逆向きには、Church proof \(q\) を primitive `Acc` 自身と `acc` algebra に適用して

\[
\begin{aligned}
\operatorname{decode}(q)
:={}&
q@
\left(\lambda x.\operatorname{Acc}_X(R,x)\right)@
\left(
  \lambda x.\lambda h.\operatorname{acc}_{X,R,x}(h)
\right)\\
&:
\operatorname{Acc}_X(R,a)
\end{aligned}
\]

を得る。従って primitive `Acc` と Church `Acc` は Prop 内の利用について相互に移せる。

## Church `Acc` からの一段降下

Church encoding から `Acc-Descent` を導くには、一段分の destructor を fold として構成する。
predicate \(D\) を

\[
D(x)
:=
(y:X)\to
R@y@x\to
\operatorname{Acc}^{\mathsf{Ch}}_X(R,y)
\]

と定義する。\(D(x)\) は「\(x\) のすべての predecessor が accessible である」という命題である。

次の Church algebra が作れる。

\[
\begin{aligned}
\delta_R
:={}&
\lambda x.\lambda ih.\lambda y.\lambda r.\,
\operatorname{acc}^{\mathsf{Ch}}_{X,R,y}(ih@y@r),\\
\delta_R
:{}&\operatorname{Prog}_R(D).
\end{aligned}
\]

実際、\(ih@y@r:D(y)\) なので、これを `acc-Ch` に渡すと
\(\operatorname{Acc}^{\mathsf{Ch}}(R,y)\) が得られる。

従って

\[
\operatorname{outAcc}^{\mathsf{Ch}}(p)
:=
p@D@\delta_R
:
D(a)
\]

と定義できる。特に

\[
p:\operatorname{Acc}^{\mathsf{Ch}}(R,a),
\qquad
q:R@y@a
\]

から

\[
\operatorname{outAcc}^{\mathsf{Ch}}(p)@y@q
:
\operatorname{Acc}^{\mathsf{Ch}}(R,y)
\]

を得る。従って現在の `Acc-Descent` は admissible rule として再現できる。

`outAcc` と `acc-Ch` の間には次の reduction がある。

\[
\begin{aligned}
&\operatorname{outAcc}^{\mathsf{Ch}}
\left(\operatorname{acc}^{\mathsf{Ch}}(h)\right)\\
&\qquad\to^*
\lambda y.\lambda r.\,
\operatorname{acc}^{\mathsf{Ch}}_{X,R,y}
\left(
  (h@y@r)@D@\delta_R
\right).
\end{aligned}
\]

これは judgmental に \(h\) へ戻るのではなく、\(h@y@r\) を一度 fold してから
`acc-Ch` で再構成する。`run` は accessibility proof の構造を実行時に観察せず、`Acc-Descent` も
Prop 内でしか使わないため、現在の用途ではこの差は表面化しない。

## 最小不動点との一致

集合 \(X\) 上の relation \(R\) に対して

\[
\Phi_R(S)
:=
\left\{
  x\in X
  \mathrel{\middle|}
  \forall y\in X.\,R(y,x)\Rightarrow y\in S
\right\}
\]

と置く。Church accessibility の full predicate interpretation は

\[
\begin{aligned}
a\in\llbracket\operatorname{Acc}^{\mathsf{Ch}}(R,-)\rrbracket
\quad\Longleftrightarrow\quad
\forall S\subseteq X.\,
\Phi_R(S)\subseteq S\Rightarrow a\in S.
\end{aligned}
\]

従って

\[
\llbracket\operatorname{Acc}^{\mathsf{Ch}}(R,-)\rrbracket
=
\bigcap
\left\{
  S\subseteq X
  \mathrel{\middle|}
  \Phi_R(S)\subseteq S
\right\}
=
\mu\Phi_R.
\]

これは `再帰6.md` で primitive `Acc` に与えた最小不動点解釈と同じである。

この同一視は predicate quantification をすべての部分集合にわたるものとして解釈した場合に直接
得られる。Henkin 的に predicate の範囲を制限するモデルでは intersection の範囲も狭くなるため、
least fixed point との一致には model 側の fullness または Church term の parametricity に対応する
条件が必要になる。

## Compute sum の Church encoding

### 現在の Compute rule で型付けできない理由

現在の Compute product rule は

\[
(*^c,*^c,*^c)
\]

だけである。\(C:*^c\) という type variable を bind するとき、binder domain \(*^c\) の sort は
\(\square^c\) である。従って

\[
(C:*^c)\to(A\to C)\to(B\to C)\to C
\]

を形成するには `(Compute-Poly)` が必要になる。

この拡張を行うと、Compute は単純型付き fragment ではなく System F に相当する type polymorphism
を持つ。これに伴い、少なくとも次の部分を拡張する必要がある。

- Compute reducibility の type abstraction/application case
- Compute non-dependency の statement と proof
- polymorphic Compute type に対する `RfType`
- Compute type variable と reflected Set type variable の対応
- Church sum の canonicity または parametricity
- primitive sum の no-confusion を使っている model と confluence proof

primitive な `left` / `right` の inversion は、Church encoding では polymorphic term の
canonicity または abstraction theorem に置き換わる。

### Answer type を \(B\) に固定する案

`run` の最終結果だけを目的にするなら、polymorphism を使わず

\[
\operatorname{Step}^{B}_{A,B}
:=
(A\to B)\to(B\to B)\to B
\]

と定義できる。対応する二つの term は

\[
\begin{aligned}
\operatorname{left}^{B}(a)
&:=\lambda k.\lambda h.\,k@a,\\
\operatorname{right}^{B}(b)
&:=\lambda k.\lambda h.\,h@b.
\end{aligned}
\]

である。しかし、この型には continuation を無視、複製、合成する一般の lambda 項も inhabit する。
従って一段結果が `left` または `right` のどちらかであるという sum canonicity は得られない。

## Church sum を直接 `run` に使うときの typing obstruction

一段関数を Church 変換したものを \(\bar f\) とする。計算方程式だけを見ると、次が期待される。

\[
\operatorname{run}(f,a)
\mathrel{\longrightarrow?}
\bar f@a@B@
\left(\lambda a':A.\operatorname{run}(f,a')\right)@
\left(\lambda b:B.b\right).
\tag{Church-Run?}
\]

ところが、左 continuation の lambda introduction には

\[
\Gamma,a':A
\vdash
\operatorname{run}(f,a'):B:*^c
\]

が必要である。Run rule を適用するには、任意の \(a'\) について

\[
\Gamma,a':A
\vDash
\operatorname{Terminates}_{A,B}(f,a')
\]

を示さなければならない。

現在状態についての

\[
\Gamma\vDash
\operatorname{Terminates}_{A,B}(f,a)
\]

から得られるのは、

\[
a'\prec_f a
\]

が判明した特定の \(a'\) に対する accessibility だけである。Church handler
\(A\to B\) は \(a'\) だけを受け取り、\(f@a=\operatorname{left}(a')\) という branch equation を
受け取らない。従って `Church-Run?` は型を保存する reduction にならない。

これは通常の sum eliminatorを使った

\[
\operatorname{case}
(f@a,
 \lambda a'.\operatorname{run}(f,a'),
 \lambda b.b)
\]

が型付けできなかった問題と同じである。Church encoding は eliminatorを lambda/application に
展開するが、branch equation の不足は解消しない。

すべての状態について

\[
\Gamma\vDash
\left(x:\operatorname{RfType}(A)\right)
\to
\operatorname{Acc}_{\operatorname{RfType}(A)}(R_f,x)
\]

を仮定すれば、これを \(\operatorname{RfTerm}_A(a')\) に適用して左 continuation を型付けできる。
しかしこれは、到達可能な状態だけが accessible であればよい現在の Run rule より強い。内部状態型
\(A\) に到達不能な非停止状態が含まれる関数も、現在の局所的な accessibility なら実行できる。

### Proof-carrying な Church branch

左 continuation に relation proof も渡すなら、必要な型は概念的には

\[
\left(C:*^c\right)
\to
\left(
  (a':A)\to (a'\prec_f a)\to C
\right)
\to
(B\to C)
\to C
\]

となる。この型は現在状態 \(a\) に依存し、Prop proof を Compute continuation に渡す。
現在の Compute product rule と sort separation の下では形成されない。また、停止証明を runtime
term から分離する現在の設計とも異なる。

`RunInv` は、この relation proof を Compute payload に含めず、typing derivation の premise として
branch 決定時まで保存するための機構になっている。

## Church continuation を直接代入することの operational obstruction

Church term は continuation を一度だけ使うとは限らない。例えば

\[
u
:=
\lambda C.\lambda l.\lambda r.\,
(\lambda z:C.\,l@a_1)@(l@a_2)
\]

は Church sum の型を持ち、beta normalization すれば
\(\operatorname{left}^{\mathsf{Ch}}(a_1)\) と同じ結果になる。

しかし `Church-Run?` によって \(l\) へ recursive continuation を代入すると、途中項には

\[
(\lambda z:B.\operatorname{run}(f,a_1))
@
\operatorname{run}(f,a_2)
\]

が現れる。全 term constructor の下で進む compatible reduction では、外側の beta redex が
\(a_2\) 側を捨てる前に \(\operatorname{run}(f,a_2)\) を簡約する path も存在する。

一段関数 \(f@a\) を先に Church normal form へ評価すれば \(a_2\) は消えるが、recursive continuation
を先に代入すると余分な recursive call が露出する。relation \(R_f\) が最終的な
`left(a_1)` だけを記録している場合、\(a_2\) の accessibility は保証されない。

従って Church application を直接 operational rule にするには、次のいずれかに相当する追加条件が
必要になる。

- continuation を代入する前に一段結果を正規化する評価順序
- continuation の linear または affine な利用制限
- Church term の operational な canonical-form 制限
- すべての continuation 呼び出しを追跡する別の accessibility relation

現在の `runCase` は一段計算 \(f@a\) を第三引数として隔離し、その計算が constructor に到達した後で
一つの recursive call を生成する。この staging により、再帰を一段計算の内部へ先に代入する問題を
避けている。

## `runCase` は equality-aware な Church elimination である

Church sum の elimination は

\[
u@C@l@r
\]

であり、\(u\) がどちらの continuation を呼ぶかによって branch が決まる。

`runCase` の計算内容だけを見ると、二つの continuation は

\[
\begin{aligned}
l&:=\lambda a'.\operatorname{run}(f,a'),\\
r&:=\lambda b.b
\end{aligned}
\]

である。従って operational な対応は

\[
\operatorname{runCase}(f,a,u)
\quad\leftrightsquigarrow\quad
u@B@l@r
\]

となる。

ただし `runCase` は \(f\)、\(a\)、\(u\) を administrative form の中に保持し、derivation premise

\[
\operatorname{RunInv}(f,a,u)
\]

も保存する。\(u=\operatorname{left}(a')\) になった時点で、この invariant が

\[
a'\prec_f a
\]

へ変換され、そこで初めて `Acc-Descent` が適用される。

通常の dependent pattern matching の言葉では、これは scrutinee \(u\) と元の計算 \(f@a\) の
equation を branch に持ち込む dependent eliminator に対応する。現在の体系では equation proof を
raw runtime argument にせず、`RunCase` rule の provability premise に置くことで proof erasure を
保っている。

この意味で `runCase` は

> sum の Church elimination を defunctionalize し、branch equation を保持するように強化した
> administrative frame

と見なせる。

## `run` の fixed-point equation

一段遷移

\[
f:A\to A+B
\]

を Church 変換したものを

\[
\bar f
:
A\to
\left(C:*^c\right)
\to
(A\to C)
\to
(B\to C)
\to C
\]

と書く。\(f@a=\operatorname{left}(a')\) の場合は左 continuation に \(a'\) を渡し、
\(f@a=\operatorname{right}(b)\) の場合は右 continuation に \(b\) を渡すものとする。

関数 \(r:A\to B\) に対する作用素を

\[
T_f(r)
:=
\lambda a.\,
\bar f@a@B@r@\operatorname{id}_B
\]

と置くと、`run` の満たす方程式は

\[
\operatorname{run}_f
=
T_f(\operatorname{run}_f)
\]

すなわち点ごとには

\[
\operatorname{run}_f(a)
=
\bar f@a@B@\operatorname{run}_f@\operatorname{id}_B
\tag{Run-Fix}
\]

である。

- `left(a')` は次状態 \(a'\) を recursive continuationへ渡す。
- `right(b)` は結果 \(b\) を return continuationへ渡す。

従って `run` は、accessibility が成り立つ領域上での \(T_f\) の well-founded fixed point として
理解できる。

`再帰6.md` の

\[
G_f=\mu\Psi_f
\]

は `Run-Fix` の relational な最小解である。\(G_f\) の domain が
\(\operatorname{AccPart}(f)\) と一致することは、fixed-point equation の解が定義される領域と
accessibility の領域が一致することを述べている。

## `run` は specialized な accessibility recursor である

proof を明示して Set/Compute へ elimination できる通常の dependent type theory なら、`run` は概念的に

\[
\begin{aligned}
\operatorname{run}_f(a,p)
:={}&
\operatorname{AccRec}
\left(
  a,
  p,
  \lambda x.\lambda ih.\,
  \operatorname{caseEq}
  \left(
    f@x,
    \lambda y.\lambda e.\,ih@y@e,
    \lambda b.b
  \right)
\right)
\end{aligned}
\]

という accessibility recursion に相当する。ここで \(ih\) は

\[
(y:A)\to (y\prec_f x)\to B
\]

であり、`caseEq` は branch equation を渡す sum eliminatorである。

現在の体系では `Acc` の一般的な Set/Compute elimination を与えず、決定的な一段関数に対するこの形だけを
`run` として primitive にしている。停止 proof は typing premise に置かれ、計算結果は \(f\) の graph
だけで決まる。従って `run` は proof-erased かつ proof-independent な specialized `Acc` recursor と
解釈できる。

## Continuation の functionalization と defunctionalization

この構成には二つの逆向きの変換が現れている。

### Sum の Church encoding

\[
A+B
\quad\leadsto\quad
(C:*^c)\to(A\to C)\to(B\to C)\to C
\]

は、branch tag と payload を「どちらの continuation をどう呼ぶか」という関数へ変換する。
これは data の functionalization である。

### 状態機械への elaboration

non-tail recursion や nested recursion を

\[
A
=
\text{control state}
\times
\text{local variables}
\times
\text{continuation stack}
\]

という状態へ変換する操作は、実行中の continuation を first-order data に変換する。これは
continuation の defunctionalization である。

現在の `left` / `right` / `runCase` はその中間にある。

1. `left` / `right` は一段後の control choice を first-order data として保持する。
2. `runCase` はその data を branch continuation の選択へ戻す。
3. `RunInv` は選択された左 branch が accessibility relation に沿うことを保証する。
4. `run` は左 branch に自分自身を continuation として与える fixed point になる。

Church encoding はこの control flow を高階関数として一行で表す。一方、現在の administrative form は
同じ control flow を、compatible reduction、subject reduction、proof erasure に適した first-order な
段階へ分解している。

## Payload 自体を continuation encoding する場合

Church sum の外側だけでなく、`left` と `right` が運ぶ payload 自体も continuation として表すことを
考える。このとき、内側の answer type を外側とは独立に量化する場合と、同じ answer type を共有する
場合を区別する必要がある。

### 独立に polymorphic な payload

比較用体系 \(\mathcal T_{\mathsf{ChSum}}\) の中で、Compute type \(A\) の continuation encoding を

\[
K(A)
:=
\left(D^{\square^c}:*^c\right)
\to
(A\to D)
\to D
\tag{Payload-Ch}
\]

と定義する。外側の Church sum とは異なる type variable \(D\) を使っている。

値を continuation encoding へ入れる term は

\[
\eta_A(a)
:=
\lambda D.\lambda k.\,k@a
:
K(A)
\]

である。逆に、\(q:K(A)\) から

\[
\operatorname{extract}_A(q)
:=
q@A@\operatorname{id}_A
:
A
\]

を得る。片方向は beta reduction だけで計算する。

\[
\operatorname{extract}_A(\eta_A(a))
\to^* a.
\tag{Payload-Extract}
\]

逆方向の

\[
\eta_A(\operatorname{extract}_A(q))=q
\]

は任意の raw termについて judgmental には成り立たない。\(q\) の answer-type parametricity から

\[
q@D@k
=
k@
\left(q@A@\operatorname{id}_A\right)
\tag{Payload-Naturality}
\]

という naturality を得た場合に、両者は extensionally に一致する。従って parametric fragment では

\[
K(A)\simeq A.
\]

これは fixed answer type に対する continuation effect ではなく、identity functor の
Codensity/Yoneda encoding に相当する。

### 二段 Church encoding された sum

payload に \(K(A)\) と \(K(B)\) を使う Church sum を

\[
S_K(A,B)
:=
\left(C^{\square^c}:*^c\right)
\to
(K(A)\to C)
\to
(K(B)\to C)
\to C
\tag{Double-Church-Sum}
\]

と定義する。canonical injection は

\[
\begin{aligned}
\operatorname{left}^K_{A,B}(a)
&:=
\lambda C.\lambda l.\lambda r.\,
l@(\eta_A(a)),\\
\operatorname{right}^K_{A,B}(b)
&:=
\lambda C.\lambda l.\lambda r.\,
r@(\eta_B(b)).
\end{aligned}
\tag{Double-Church-Intro}
\]

この表現には二種類の continuation が現れる。

1. 外側の continuation \(K(A)\to C\) と \(K(B)\to C\) が branch を選択する。
2. 内側の continuation encoding \(K(A)\) と \(K(B)\) が payload を利用者へ渡す。

`Payload-Naturality` を仮定すれば

\[
S_K(A,B)
\simeq
K(A)+K(B)
\simeq
A+B
\]

である。従って内側の answer typeを独立に polymorphic にした二段 Church encoding は、意味論的には
branch と payload の両方をそれぞれの eliminatorとして表した通常の sum になる。

### 二段 Church encoding と `run`

一段関数の二段 Church 変換を

\[
\bar f^K
:
A\to S_K(A,B)
\]

とする。計算方程式は

\[
\begin{aligned}
\operatorname{run}_f(a)
={}&
\bar f^K@a@B\\
&@
\left(
  \lambda q_A:K(A).\,
  q_A@B@\operatorname{run}_f
\right)\\
&@
\left(
  \lambda q_B:K(B).\,
  q_B@B@\operatorname{id}_B
\right).
\end{aligned}
\tag{Double-Church-Run}
\]

canonical な left payload は

\[
\eta_A(a')@B@\operatorname{run}_f
\to^*
\operatorname{run}_f(a')
\]

と計算し、canonical な right payload は

\[
\eta_B(b)@B@\operatorname{id}_B
\to^* b
\]

と計算する。従って通常の

\[
\operatorname{left}(a')
\mapsto
\operatorname{run}(f,a'),
\qquad
\operatorname{right}(b)
\mapsto b
\]

が、外側の branch selection と内側の payload continuation application の二段階に分解される。

この形でも、左 handler の内部には

\[
\lambda a':A.\operatorname{run}(f,a')
:
A\to B
\]

が必要である。\(q_A:K(A)\) は relation proof を渡さないため、任意の \(a'\) に対する
termination premise は得られない。従って一段の Church sum で生じた typing obstruction は、payload を
さらに Church encoding しても残る。

relation を canonical payload によって

\[
y\prec_{\bar f^K}x
\quad:\Longleftrightarrow\quad
\bar f^K@x
=
\operatorname{left}^K_{A,B}(y)
\]

と定めた場合、branch から得られる一般の \(q_A:K(A)\) を canonical な

\[
\eta_A(\operatorname{extract}_A(q_A))
\]

へ戻すためにも `Payload-Naturality` が必要になる。primitive sum の constructor inversion だけで済んで
いた箇所が、二段 Church encoding では payload parametricity に移る。

### 外側と内側で answer type を共有する場合

内側の answer typeを独立な \(D\) とせず、外側の \(C\) と共有すると、型は

\[
\begin{aligned}
S_{\mathsf{shared}}(A,B)
:=
\left(C^{\square^c}:*^c\right)
&\to
\left(((A\to C)\to C)\to C\right)\\
&\to
\left(((B\to C)\to C)\to C\right)
\to C
\end{aligned}
\tag{Shared-Answer-Sum}
\]

となる。この型では、左 payload \((A\to C)\to C\) を作る項が、同じ scope にある外側の
handler を利用できる。例えば \(a:A\) があるとき、概略

\[
\lambda C.\lambda l.\lambda r.\,
l@
\left(
  \lambda k.\,
  l@
  \left(
    \lambda k'.\,k@a
  \right)
\right)
\]

のように外側の left handler を payload の内部から再び呼べる。

独立な \(D\) 上で polymorphic な \(K(A)\) の場合、外側の handler は \(C\) を返すだけなので、任意の
\(D\) を返さなければならない payload の内部から一般には利用できない。answer type の独立な量化が
payload を外側の control context から封じ、parametric な値として振る舞わせている。

一方 `Shared-Answer-Sum` では、次の操作が型によって排除されない。

- branch handler を payload の内部から再び呼ぶ
- handler を複数回呼ぶ
- handler の呼び出しを破棄する
- 外側と内側の continuation を nest する

従って `Shared-Answer-Sum` は通常の \(A+B\) の encoding ではなく、branch selection と payload
evaluation が相互作用する higher-order control structure になる。こちらを `run` に用いる場合は、
`runCase` の別表現というより、再帰 operator 自体を continuation effect の handler として再設計する
ことになる。

### 二つの場合の対応

| payload encoding | behavior |
| --- | --- |
| \(K(A)=(D:*^c)\to(A\to D)\to D\) | parametricity により \(A\) と同値になる |
| outer sum of \(K(A)\), \(K(B)\) | branch と payload を別々に Church encoding した通常の sum になる |
| \((A\to C)\to C\) with shared outer \(C\) | 外側の handler と相互作用する continuation effect が残る |

独立に polymorphic な payload は value を eliminator の形へ変換したものである。同じ answer typeを
共有する payload は、value の encoding を越えて control behavior 自体を保持する。

## 現在の定式化への反映

Church accessibility は現在の impredicative Prop だけで形成でき、`acc` と `Acc-Descent` も lambda 項と
beta reduction から再現できる。従って `Acc` の primitive inductive interface は、少なくとも
`再帰6.md` が利用している範囲では `Acc-Ch` へ置き換えられる。

この置き換えでは、次の二点をメタ理論で確認する必要がある。

- 採用する Prop model で Church encoding が \(\mu\Phi_R\) と一致すること
- 閉項の停止証明で primitive `Acc` derivation に対する構造帰納を使っていた箇所を、Church fold、
  parametricity、または最小不動点 semantics に置き換えること

Compute sum の Church encodingには type polymorphism と reflection の拡張が必要である。さらに、
Church applicationを直接 `run` にすると branch equation と一段計算の staging が失われる。
現在の primitive sum と `runCase` は、sum canonicity、confluence、局所的な accessibility による
subject reductionを直接表している。

従って現在の方向では、次の分担が自然である。

| component | interpretation |
| --- | --- |
| \(\operatorname{Acc}^{\mathsf{Ch}}\) | impredicative Prop による最小不動点の encoding |
| `acc-Ch` | accessibility algebra の introduction |
| `outAcc-Ch` | Church fold から導く一段 destructor |
| `left` / `right` | branch continuation を defunctionalize した一段結果 data |
| `runCase` | `RunInv` を保持する equality-aware な Church elimination |
| `run` | accessibility 上での proof-erased fixed point |
| \(G_f=\mu\Psi_f\) | `run` の fixed-point equation の relational な最小解 |
