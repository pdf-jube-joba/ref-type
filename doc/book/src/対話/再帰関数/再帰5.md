# Compute の `run` と Set への一方向 reflection

## 1. 体系の定義

この節に、`system.md` へ追加する構文、judgement、derivation、reduction をまとめる。
後の節では、ここで導入した rule の動機と必要なメタ定理を個別に検討する。

### 1.1 構文

#### Sort

`system.md` の sort に Compute 用の sort を追加する。

\[
\begin{aligned}
\mathcal S'
:={}&
\{*^s_i,\square^s_i\mid i\in\mathbb N\}
\cup\{*^p,\square^p\}
\cup\{*^c,\square^c\},\\
\mathcal A'
:={}&
\mathcal A\cup\{(*^c,\square^c)\},\\
\mathcal R'
:={}&
\mathcal R\cup\{(*^c,*^c,*^c)\}.
\end{aligned}
\]

\(\square^c\) は \(*^c:\square^c\) を述べるために使う。Compute の product は
\((*^c,*^c,*^c)\) から生成する。

#### Context

term grammar と context grammar は Set/Prop/Compute に分けない。context は `system.md` と同じである。

\[
\Gamma
::=
\varnothing
\mid
\Gamma,x:T:s.
\]

一つの context に異なる sort の binding が混在してよい。

#### Term

`system.md` の term grammar に次を追加する。

\[
\begin{aligned}
t::=\cdots
&\mid A+B\\
&\mid\operatorname{left}_{A,B}(a)
\mid\operatorname{right}_{A,B}(b)\\
&\mid\operatorname{Acc}_X(R,a)\\
&\mid\operatorname{acc}_{X,R,a}(h)\\
&\mid\operatorname{run}_{A,B}(f,a)\\
&\mid\operatorname{RfType}(A)\\
&\mid\operatorname{RfTerm}_A(m).
\end{aligned}
\]

`left` と `right` は、`run` の一段結果を作る raw term constructor である。
`RfType` と `RfTerm` は同じ term grammar に属する別々の raw constructor である。
`RfTerm` の添字 \(A\) は payload \(m\) の Compute type を表し、raw syntax の一部である。

### 1.2 Judgement と derivation rule

#### Judgement

judgement は `system.md` のものをそのまま使う。

\[
\operatorname{WF}(\Gamma),
\qquad
\Gamma\vdash t:s,
\qquad
\Gamma\vdash t:T:s,
\qquad
\Gamma\vDash P.
\]

\(\Gamma\vdash t:T:*^c\) を満たす項を Compute 項と呼ぶ。これは raw syntax の category ではなく、
typing による分類である。

#### PTS extension

\((*^c,*^c,*^c)\) しかないため、Compute の product は非依存関数型として使う。

\[
\dfrac{
  \Gamma\vdash A:*^c
  \qquad
  \Gamma\vdash B:*^c
}{
  \Gamma\vdash A\to B:*^c
}.
\]

#### 一段結果型

`run` の一段結果型と constructor に次の rule を置く。

| category | conclusion | premises |
| --- | --- | --- |
| step-result form | \(\Gamma\vdash A+B:*^c\) | \(\Gamma\vdash A:*^c\)<br>\(\Gamma\vdash B:*^c\) |
| left intro | \(\Gamma\vdash\operatorname{left}_{A,B}(a):A+B:*^c\) | \(\Gamma\vdash a:A:*^c\)<br>\(\Gamma\vdash B:*^c\) |
| right intro | \(\Gamma\vdash\operatorname{right}_{A,B}(b):A+B:*^c\) | \(\Gamma\vdash A:*^c\)<br>\(\Gamma\vdash b:B:*^c\) |

#### Accessibility

\(X:*^s_i\) 上の Set/Prop relation

\[
R:X\to X\to *^p
\]

に対し、次を置く。

\[
\dfrac{
  \Gamma\vdash X:*^s_i
  \qquad
  \Gamma\vdash R:X\to X\to *^p:\square^p
  \qquad
  \Gamma\vdash a:X:*^s_i
}{
  \Gamma\vdash\operatorname{Acc}_X(R,a):*^p
}.
\tag{Acc-Form}
\]

constructor は次の型を持つ。

\[
\operatorname{acc}_{X,R,a}
:
\left((y:X)\to R@y@a\to\operatorname{Acc}_X(R,y)\right)
\to
\operatorname{Acc}_X(R,a).
\tag{acc}
\]

accessibility の一段降下を provability の derivation rule として置く。

\[
\dfrac{
  \Gamma\vDash\operatorname{Acc}_X(R,a)
  \qquad
  \Gamma\vDash R@y@a
}{
  \Gamma\vDash\operatorname{Acc}_X(R,y)
}.
\tag{Acc-Descent}
\]

#### Reflection

Compute type \(A\) に対応する Set type を \(\operatorname{RfType}(A)\) と書く。

\[
\dfrac{
  \Gamma\vdash A:*^c
}{
  \Gamma\vdash\operatorname{RfType}(A):*^s_0
}.
\tag{Rf-Type}
\]

Compute term の reflection は次である。

\[
\dfrac{
  \Gamma\vdash m:A:*^c
}{
  \Gamma\vdash
  \operatorname{RfTerm}_A(m)
  :
  \operatorname{RfType}(A):*^s_0
}.
\tag{Rf-Term}
\]

同じ context \(\Gamma\) を使う。Compute variable \(x:A:*^c\) は Set 項の通常の位置には現れないが、
\(\operatorname{RfTerm}_A(x)\) の payload として参照できる。

Rf-Type と Rf-Term は Compute から Set への一方向の reflection を与える。

Compute の base type を宣言するときは、Set 側に対応する type を生成する。

#### 一段遷移と `run`

次を仮定する。

\[
\Gamma\vdash A:*^c,
\qquad
\Gamma\vdash B:*^c,
\qquad
\Gamma\vdash f:A\to A+B:*^c,
\qquad
\Gamma\vdash a:A:*^c.
\]

Compute の `left` constructor を関数として次のように略記する。

\[
\operatorname{leftFun}_{A,B}
:=
\lambda z:A.\operatorname{left}_{A,B}(z)
:
A\to A+B.
\]

Set/Prop 側の relation \(R_f\) を次で定義する。

\[
\begin{aligned}
R_f
&:
\operatorname{RfType}(A)
\to
\operatorname{RfType}(A)
\to *^p,\\
R_f@y@x
&:=
\operatorname{RfTerm}_{A\to A+B}(f)@x
=_{\operatorname{RfType}(A+B)}
\operatorname{RfTerm}_{A\to A+B}(\operatorname{leftFun}_{A,B})@y.
\end{aligned}
\]

停止性は次の略記とする。

\[
\operatorname{Terminates}_{A,B}(f,a)
:=
\operatorname{Acc}_{\operatorname{RfType}(A)}
(R_f,\operatorname{RfTerm}_A(a)).
\]

`run` の typing rule は次である。

\[
\dfrac{
\begin{array}{c}
\Gamma\vdash A:*^c
\qquad
\Gamma\vdash B:*^c\\
\Gamma\vdash f:A\to A+B:*^c
\qquad
\Gamma\vdash a:A:*^c\\
\Gamma\vDash
\operatorname{Acc}_{\operatorname{RfType}(A)}
(R_f,\operatorname{RfTerm}_A(a))
\end{array}
}{
\Gamma\vdash
\operatorname{run}_{A,B}(f,a):B:*^c
}.
\tag{Run}
\]

停止証明は Run rule の provability premise で与える。

### 1.3 Reduction rule

全項に共通の reduction \(\to\) を使う。既存の \(\beta\) reduction とその compatible closure を含める。
`RfTerm` の source type annotation と payload も compatible closure の対象とする。

#### Type reflection

type reflection の構造は次の root reduction で与える。

\[
\begin{aligned}
\operatorname{RfType}(X^c)&\to\widehat X,\\
\operatorname{RfType}(A\to B)
&\to\operatorname{RfType}(A)\to\operatorname{RfType}(B).
\end{aligned}
\tag{Rf-Type-Reduce}
\]

#### Term reflection

`RfTerm` は reflected Compute syntax を一つの glued form として保持する。
application では二つの reflected 項を一つの payload にくっつける。

\[
\operatorname{RfTerm}_{A\to B}(f)
@
\operatorname{RfTerm}_A(a)
\to
\operatorname{RfTerm}_B(f@a).
\tag{Rf-App}
\]

Compute payload 自体が reduction するときは、その reduction を `RfTerm` の内側でも進める。

\[
\dfrac{
  m\to m'
}{
  \operatorname{RfTerm}_A(m)
  \to
  \operatorname{RfTerm}_A(m')
}.
\tag{Rf-Cong}
\]

#### `run`

\[
\dfrac{
  f@a\to^*\operatorname{right}_{A,B}(b)
}{
  \operatorname{run}_{A,B}(f,a)\to b
}.
\tag{Run-End}
\]

\[
\dfrac{
  f@a\to^*\operatorname{left}_{A,B}(a')
}{
  \operatorname{run}_{A,B}(f,a)
  \to
  \operatorname{run}_{A,B}(f,a')
}.
\tag{Run-Step}
\]

condition に現れる \(\to^*\) は同じ reduction の反射推移閉包である。開いた \(f\) または \(a\) に
ついて condition が導けなければ `run(f,a)` は stuck でよい。

### 1.4 Definitional equality

上のすべての reduction の対称・反射・推移閉包を definitional equality に含める。
`system.md` の conversion rule で使われている \(\equiv^\beta\) を、この equality に拡張する。

## 2. Sort separation

Set/Prop/Compute に別々の raw grammar や context を用意しなくても、rule の sort を制限すれば
次が成り立つ。

> **Sort separation.**
>
> \(\Gamma\vdash t:T:*^c\) ならば、\(t\) と \(T\) の型付き部分項には `Take`、`Power`、`Proof`、
> refinement など、Set/Prop にだけ introduction rule を持つ項は現れない。

証明は typing derivation に関する帰納法で行う。

- Compute product は \((*^c,*^c,*^c)\) だけを使う。
- 一段結果型の constructor の引数は \(*^c\) に制限する。
- Run の \(A,B,f,a\) はすべて \(*^c\) である。
- Rf-Term の結論は \(*^s_0\) であり、Compute 項を構成する rule の premise にはならない。
- `Take`、`Power`、`Ty` などの結論は \(*^s_i\) または \(*^p\) である。
- reduction と conversion は sort を保存する。

停止性証明は Run の provability premise に現れるが、raw term `run(f,a)` の部分項ではない。
したがって停止性証明では Set の数学全体と `Take` を利用できる。

## 3. Reflection の向き

### 3.1 Rf 関連 reduction の全一覧

この体系で Rf に関係する reduction は、次の二群である。

| group | rules | direction |
| --- | --- | --- |
| type reflection | Rf-Type-Reduce | type structure を分解する |
| term reflection | Rf-App、Rf-Cong | `RfTerm` の payload を保持・結合する |

両群の root constructor はそれぞれ `RfType` と `RfTerm` なので、raw syntax だけから適用する
reduction rule を判定できる。

### 3.2 Type reflection と term reflection

type reflection は、Compute type の構造に対応する Set type を得るために分解する。例えば

\[
\operatorname{RfType}(A\to B)
\to
\operatorname{RfType}(A)\to\operatorname{RfType}(B)
\]

によって、reflected function を Set application の関数位置に置ける。

一方、term reflection は Compute 計算を payload として保持する。Set 側で reflected function と
reflected argument を別々に持っているとき、

\[
\operatorname{RfTerm}_{A\to B}(g)@\operatorname{RfTerm}_A(a)
\]

を Compute application の reflection に戻して計算する必要がある。Rf-App によって

\[
\operatorname{RfTerm}_{A\to B}(g)@\operatorname{RfTerm}_A(a)
\to
\operatorname{RfTerm}_B(g@a)
\]

とし、その後は Rf-Cong が payload の \(\beta\) reduction や `run` reduction を進める。

### 3.3 Rf-Cong

Rf-Cong は Compute payload の reduction を Set 側でも追跡する congruence である。

\[
m\to m'
\quad\Longrightarrow\quad
\operatorname{RfTerm}_A(m)\to\operatorname{RfTerm}_A(m').
\]

特に、

\[
\operatorname{run}(f,a)\to^*b
\quad\Longrightarrow\quad
\operatorname{RfTerm}_B(\operatorname{run}(f,a))
\to^*\operatorname{RfTerm}_B(b).
\]

これが停止した Compute 計算を Set 側でも compile-time evaluation する規則である。

## 4. Run-Step の subject reduction

Run の typing premise と

\[
f@a\to^*\operatorname{left}(a')
\]

を仮定する。Compute subject reduction と一段結果型の inversion から

\[
\Gamma\vdash a':A:*^c
\]

を得る。

Rf-App と Rf-Cong により relation の左辺は

\[
\begin{aligned}
\operatorname{RfTerm}_{A\to A+B}(f)@\operatorname{RfTerm}_A(a)
&\to\operatorname{RfTerm}_{A+B}(f@a)\\
&\to^*\operatorname{RfTerm}_{A+B}(\operatorname{left}(a')).
\end{aligned}
\]

右辺も

\[
\begin{aligned}
\operatorname{RfTerm}_{A\to A+B}(\operatorname{leftFun})
@\operatorname{RfTerm}_A(a')
&\to
\operatorname{RfTerm}_{A+B}(\operatorname{leftFun}@a')\\
&\to^*
\operatorname{RfTerm}_{A+B}(\operatorname{left}(a')).
\end{aligned}
\]

となる。したがって equality introduction と conversion から

\[
\Gamma\vDash
R_f@\operatorname{RfTerm}_A(a')@\operatorname{RfTerm}_A(a)
\]

を得る。Acc-Descent により

\[
\Gamma\vDash
\operatorname{Acc}(R_f,\operatorname{RfTerm}_A(a'))
\]

なので、もう一度 Run rule を使って

\[
\Gamma\vdash
\operatorname{run}(f,a'):B:*^c
\]

を導出できる。

Run-End は \(f@a\to^*\operatorname{right}(b)\) と一段結果型の inversion から \(b:B:*^c\) を得ればよい。

## 5. 閉項の progress と停止

### 5.1 要求する progress

要求するのは閉じた `run` に対する次の性質である。

\[
\varnothing\vdash\operatorname{run}_{A,B}(f,a):B:*^c
\quad\Longrightarrow\quad
\exists t.\ \operatorname{run}_{A,B}(f,a)\to t.
\tag{Closed Run Progress}
\]

開いた \(f\) または \(a\) について、\(f@a\) の constructor が判定できなければ `run(f,a)` は
stuck でよい。

### 5.2 Nested `run`

一段遷移 \(f\) の本体では、既に typing された `run` を利用できる。

現在の構文に現れる `run` の個数や nesting depth は、\(\beta\)-substitution によって増え得る。
停止性の証明には、syntax measure ではなく reducibility を使う。

nested `run` は Compute typing の fundamental reducibility theorem で扱う。Run rule の場合は、\(f\) と
\(a\) の typing derivation に対する帰納法の仮定から、\(f\) が reducible な関数、\(a\) が reducible
な引数であることを得る。現在の `run(f,-)` の Run-Step の反復は、同じ Run rule の場合分けの中で
\(\operatorname{Acc}(R_f,-)\) に関する well-founded induction を使って示す。

したがって fundamental theorem の Run rule では、次を同時に示す。

1. \(f@a\) が normalize して `left(a')` または `right(b)` になる。
2. `left(a')` の場合、\(a'\) は reducible で accessibility が一段降下する。
3. Run-Step を有限回繰り返した後、`right(b)` に到達する。

この reducibility theorem と一段結果型の canonicity から Closed Run Progress を得る。

## 6. 他の一般再帰関数を利用する

Run rule を使って typing された閉項 \(d_g\) を仮定する。

\[
\varnothing\vdash d_g:X\to Y:*^c.
\]

\(g:X\to Y:*^c\) を仮定した context で、別の `run` を含む項 \(d_h\) を構成する。

\[
g:X\to Y:*^c
\vdash
d_h:U\to V:*^c.
\]

\(d_h\) の一段遷移では、例えば

\[
(\lambda y:Y.\ M(c,y))@(g@(k@c))
\]

の形で \(g\) を呼べる。この例の premise は

\[
\varnothing\vdash k:C\to X:*^c,
\qquad
c:C:*^c,y:Y:*^c\vdash M(c,y):C+V:*^c
\]

を仮定する。lambda introduction と application により

\[
(\lambda g:X\to Y.\ d_h)@d_g:U\to V:*^c
\]

を得て、\(\beta\) reduction により \(d_h[g:=d_g]\) へ進む。fundamental reducibility theorem の
substitution case から \(d_g@(k@c)\) の normalization を得て、外側の Run-Step の反復は \(d_h\) に
与えた accessibility proof で扱う。

## 7. Set 側での利用

Run rule と Rf-Term から

\[
\Gamma\vdash
\operatorname{RfTerm}_B(\operatorname{run}(f,a))
:
\operatorname{RfType}(B):*^s_0
\]

を得る。この項は通常の Set 項なので、equality、refinement predicate、別の Set 関数や型の中で
使える。閉じた Compute 計算が \(b\) を返すなら、Rf-Cong により
\(\operatorname{RfTerm}_B(b)\) まで進む。

一般再帰関数 \(g:X\to Y:*^c\) 自体も

\[
\operatorname{RfTerm}_{X\to Y}(g)
:
\operatorname{RfType}(X)\to\operatorname{RfType}(Y):*^s_0
\]

として Set 側で使える。Compute 引数 \(a:X\) に対して

\[
\operatorname{RfTerm}_{X\to Y}(g)@\operatorname{RfTerm}_X(a)
\to
\operatorname{RfTerm}_Y(g@a)
\to^*
\operatorname{RfTerm}_Y(b)
\]

となる。

Set 側の任意の

\[
t:\operatorname{RfType}(X)
\]

に対する \(\operatorname{RfTerm}_{X\to Y}(g)@t\) は型付けできるが、\(t\) が reflected Compute 項でなければ
Rf-App は発火しない。特に `Take` で作った \(t\) の reduction は保証しない。Run rule の引数 premise
は \(\Gamma\vdash a:A:*^c\) なので、Set 項 \(t\) を置いた \(\operatorname{run}(f,t)\) は型付けされない。

## 8. 例: Euclidean algorithm

Compute 側で

\[
A:=\mathbb N^c\times\mathbb N^c,
\qquad
B:=\mathbb N^c
\]

とし、一段遷移を定義する。

\[
\begin{aligned}
\operatorname{eucStep}(n,0)
&:=\operatorname{right}(n),\\
\operatorname{eucStep}(n,m)
&:=\operatorname{left}(m,n\bmod m)
&& (m\ne0).
\end{aligned}
\]

Set/Prop 側で \(m\ne0\) のとき \(n\bmod m<m\) であることを使い、

\[
(n:\mathbb N^c)\to(m:\mathbb N^c)\to
\operatorname{Acc}
\left(
R_{\operatorname{eucStep}},
\operatorname{RfTerm}_A((n,m))
\right)
\]

を証明する。\(n,m\) は \(*^c\) の variable であり、その reflection について Set/Prop の命題を
述べている。

\[
\operatorname{gcd}^c
:=
\lambda n:\mathbb N^c.
\lambda m:\mathbb N^c.
\operatorname{run}
(\operatorname{eucStep},(n,m))
:
\mathbb N^c\to\mathbb N^c\to\mathbb N^c.
\]

閉じた Compute 自然数 \(n,m\) に対して、Set 項

\[
\operatorname{RfTerm}_{\mathbb N^c}(\operatorname{gcd}^c@n@m)
:
\widehat{\mathbb N}
\]

を作ることができ、これは
\(\operatorname{RfTerm}_{\mathbb N^c}(\gcd(n,m))\) まで簡約する。

## 9. Subject reduction、confluence、model

### 9.1 Subject reduction

追加 rule について次を示す。

\[
\Gamma\vdash t:T:s,
\qquad
t\to t'
\quad\Longrightarrow\quad
\Gamma\vdash t':T:s.
\]

Run-End/Run-Step は Section 4 の議論を使う。Rf-Cong は Compute subject reduction、Rf-App は
application typing と type reflection を使う。

### 9.2 Confluence

Rf-Type-Reduce の redex は `RfType`、Rf-App の redex は `RfTerm` を root に持つ。例えば
\(\operatorname{RfTerm}_C(f)@\operatorname{RfType}(A\to B)\) は Rf-App の left-hand side と
一致しないため、type reflection と term reflection の間には raw syntax 上の root overlap がない。

Rf-App と Rf-Cong の critical pair は合流する。例えば \(f\to f'\) なら

\[
\begin{aligned}
\operatorname{RfTerm}_{A\to B}(f)@\operatorname{RfTerm}_A(a)
&\to
\operatorname{RfTerm}_{A\to B}(f')@\operatorname{RfTerm}_A(a)
\to
\operatorname{RfTerm}_B(f'@a),\\
\operatorname{RfTerm}_{A\to B}(f)@\operatorname{RfTerm}_A(a)
&\to
\operatorname{RfTerm}_B(f@a)
\to
\operatorname{RfTerm}_B(f'@a).
\end{aligned}
\]

Rf-Type-Reduce についても type constituent の reduction と合流することを示す。

Run-End と Run-Step の排他性には、Compute reduction の confluence と一段結果型の no-confusion を使う。
全体の confluence proof は parallel reduction または reducibility と typing derivation に関する
帰納法で与える必要がある。

### 9.3 Model

基礎の Set/Prop calculus と `run` なし Compute fragment のモデルがあるとする。

- Compute type と corresponding Set type は同じ carrier、または指定された reflection map で結ぶ。
- \(\operatorname{RfTerm}_A(m)\) は \(m\) の denotation を Set 側へ写したものとして解釈する。
- Rf-App は reflection が application を保存することを表す。
- `run` は accessibility に基づく well-founded recursion として解釈する。

\(f\) は決定的なので、異なる accessibility proof を使っても到達する結果は同じである。
基礎モデルからこの解釈を構成できれば、拡張の無矛盾性を基礎体系の無矛盾性に相対化できる。

## 10. 必要なメタ定理

`system.md` に取り込む前に、少なくとも次を示す必要がある。

- sort separation
- substitution と subject reduction
- type/term reflection の typing preservation
- Acc-Descent rule の soundness
- Compute typing の fundamental reducibility theorem
- reducibility と一段結果型の canonicity による Closed Run Progress
- reducibility と accessibility induction による閉じた `run` の停止
- reflected computation の normalization
- Rf-App/Rf-Cong の critical-pair analysis
- Run-End/Run-Step の排他性と全体の confluence
- accessibility proof に依存しない結果の一意性
- 基礎体系に対する相対的な model soundness

## 11. 要求との対応

| requirement | realization |
| --- | --- |
| \(f\) と \(a\) に Set 項を入れない | Run の \(f,a\) premise と sort separation |
| 証明済みの他の一般再帰を使う | lambda binding、substitution、reducibility theorem |
