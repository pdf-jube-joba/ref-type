# `runCase` による一般再帰

## 体系定義

この節で `system.md` に加える構文、judgement、derivation、reduction を定義する。
`run` の一段実行は、到達可能性を side condition に持つ `Run-End` / `Run-Step` ではなく、
administrative form `runCase` と通常の compatible reduction によって表す。

### 構文定義

#### Sort

Compute 用の二つの sort を加える。

\[
\begin{aligned}
\mathcal S'
:={}&
\{*^s_i,\square^s_i\mid i\in\mathbb N\}
\cup\{*^p,\square^p\}
\cup\{*^c,\square^c\},\\
\mathcal A'
:={}&
\mathcal A\cup\{(*^c,\square^c)\},\\
\mathcal R'
:={}&
\mathcal R\cup\{(*^c,*^c,*^c)\}.
\end{aligned}
\]

Compute product を形成する sort rule は \((*^c,*^c,*^c)\) だけである。

#### Context

context grammar は `system.md` と共通である。

\[
\Gamma
::=
\varnothing
\mid
\Gamma,x:T:s.
\]

一つの context に Set、Prop、Compute の binding が混在してよい。

#### 非依存 arrow の表記

term grammar にある product は常に sort annotation 付きの binder を持つ

\[
(x^s:A)\to B
\]

である。\(\Gamma\vdash A:s\) のとき、\(x^s\notin\operatorname{FV}(B)\) を満たす fresh な
name \(x\) を取って

\[
A\to B
:=
(x^s:A)\to B
\qquad
(x^s\notin\operatorname{FV}(B))
\]

と略記する。この表記の raw syntax は右辺の product である。

#### Term

`system.md` の term grammar に次を加える。

\[
\begin{aligned}
t::=\cdots
&\mid A+B\\
&\mid\operatorname{left}_{A,B}(a)
\mid\operatorname{right}_{A,B}(b)\\
&\mid\operatorname{Acc}_X(R,a)\\
&\mid\operatorname{acc}_{X,R,a}(h)\\
&\mid\operatorname{run}_{A,B}(f,a)\\
&\mid\operatorname{runCase}_{A,B}(f,a,u)\\
&\mid\operatorname{RfType}(A)\\
&\mid\operatorname{RfTerm}_A(m).
\end{aligned}
\]

`left` と `right` は引数を含む raw constructor である。`runCase` は `run` の reduction が生成する
一段結果専用の administrative eliminator であり、
第三引数 \(u\) に現在の一段計算を保持する。

`RfType` と `RfTerm` は別の raw constructor である。`RfTerm` の source type annotation \(A\) と
Compute payload \(m\) は raw syntax の一部である。

### Judgement 定義

judgement は `system.md` と同じ四種類である。

\[
\operatorname{WF}(\Gamma),
\qquad
\Gamma\vdash t:s,
\qquad
\Gamma\vdash t:T:s,
\qquad
\Gamma\vDash P.
\]

\(\Gamma\vdash t:T:*^c\) を満たす項を Compute 項と呼ぶ。この分類は typing による。

### Derivation 定義

#### Compute sum

Compute の一段結果型と constructor を次で型付けする。

| category | conclusion | premises |
| --- | --- | --- |
| sum form | \(\Gamma\vdash A+B:*^c\) | \(\Gamma\vdash A:*^c\)<br>\(\Gamma\vdash B:*^c\) |
| left intro | \(\Gamma\vdash\operatorname{left}_{A,B}(a):A+B:*^c\) | \(\Gamma\vdash a:A:*^c\)<br>\(\Gamma\vdash B:*^c\) |
| right intro | \(\Gamma\vdash\operatorname{right}_{A,B}(b):A+B:*^c\) | \(\Gamma\vdash A:*^c\)<br>\(\Gamma\vdash b:B:*^c\) |

#### Accessibility

\(X:*^s_i\) 上の relation

\[
R:X\to X\to *^p
\]

に対して accessibility を形成する。

\[
\dfrac{
  \Gamma\vdash X:*^s_i
  \qquad
  \Gamma\vdash R:X\to X\to *^p:\square^p
  \qquad
  \Gamma\vdash a:X:*^s_i
}{
  \Gamma\vdash\operatorname{Acc}_X(R,a):*^p
}.
\tag{Acc-Form}
\]

constructor は次の型を持つ。

\[
\operatorname{acc}_{X,R,a}
:
\left((y:X)\to R@y@a\to\operatorname{Acc}_X(R,y)\right)
\to
\operatorname{Acc}_X(R,a).
\tag{acc}
\]

accessibility の一段降下を次の admissible rule として用いる。

\[
\dfrac{
  \Gamma\vDash\operatorname{Acc}_X(R,a)
  \qquad
  \Gamma\vDash R@y@a
}{
  \Gamma\vDash\operatorname{Acc}_X(R,y)
}.
\tag{Acc-Descent}
\]

これは `Acc` の Prop 内への eliminator から導出する。

#### Reflection

Compute type と Compute term の reflection rule は次である。

\[
\dfrac{
  \Gamma\vdash A:*^c
}{
  \Gamma\vdash\operatorname{RfType}(A):*^s_0
}.
\tag{Rf-Type}
\]

\[
\dfrac{
  \Gamma\vdash m:A:*^c
}{
  \Gamma\vdash
  \operatorname{RfTerm}_A(m)
  :
  \operatorname{RfType}(A):*^s_0
}.
\tag{Rf-Term}
\]

同じ context \(\Gamma\) を両方の premise と conclusion で使う。Compute variable \(x:A:*^c\) は
\(\operatorname{RfTerm}_A(x^{*^c})\) の payload として Set 項から参照できる。

各 Compute base type \(X^c\) の宣言には対応する fresh な Set type \(\widehat X\) を指定する。

#### 一段遷移 relation

次を仮定する。

\[
\Gamma\vdash A:*^c,
\qquad
\Gamma\vdash B:*^c,
\qquad
\Gamma\vdash f:A\to A+B:*^c,
\qquad
\Gamma\vdash a:A:*^c.
\]

`left` constructor の eta expansion を

\[
\operatorname{leftFun}_{A,B}
:=
\lambda z^{*^c}:A.\operatorname{left}_{A,B}(z^{*^c})
:
A\to A+B
\]

とする。`left` は引数を含む constructor なので、関数位置で reflection するためにこの略記を使う。

reflected state 上の relation \(R_f\) を次で定義する。

\[
\begin{aligned}
R_f
&:
\operatorname{RfType}(A)
\to
\operatorname{RfType}(A)
\to *^p,\\
R_f@y@x
&:=
\operatorname{RfTerm}_{A\to A+B}(f)@x
=
\operatorname{RfTerm}_{A\to A+B}(\operatorname{leftFun}_{A,B})@y.
\end{aligned}
\]

等号の型は equality formation の typing premise から決まり、raw equality constructor に型添字は
付かない。

停止性を次の略記で表す。

\[
\operatorname{Terminates}_{A,B}(f,a)
:=
\operatorname{Acc}_{\operatorname{RfType}(A)}
\left(R_f,\operatorname{RfTerm}_A(a)\right).
\]

#### `run`

\[
\dfrac{
\begin{array}{c}
  \Gamma\vdash A:*^c
  \qquad
  \Gamma\vdash B:*^c\\
  \Gamma\vdash f:A\to A+B:*^c
  \qquad
  \Gamma\vdash a:A:*^c\\
  \Gamma\vDash\operatorname{Terminates}_{A,B}(f,a)
\end{array}
}{
  \Gamma\vdash
  \operatorname{run}_{A,B}(f,a):B:*^c
}.
\tag{Run}
\]

#### `runCase`

`runCase` の第三引数が現在の一段計算を表すことを、Set/Prop 側の proposition として記録する。

\[
\begin{aligned}
\operatorname{RunInv}_{A,B}(f,a,u)
:={}&
\operatorname{RfTerm}_{A+B}(f@a)
=
\operatorname{RfTerm}_{A+B}(u).
\end{aligned}
\]

`runCase` の typing rule は次である。

\[
\dfrac{
\begin{array}{c}
  \Gamma\vdash A:*^c
  \qquad
  \Gamma\vdash B:*^c\\
  \Gamma\vdash f:A\to A+B:*^c
  \qquad
  \Gamma\vdash a:A:*^c\\
  \Gamma\vdash u:A+B:*^c\\
  \Gamma\vDash\operatorname{Terminates}_{A,B}(f,a)\\
  \Gamma\vDash\operatorname{RunInv}_{A,B}(f,a,u)
\end{array}
}{
  \Gamma\vdash
  \operatorname{runCase}_{A,B}(f,a,u):B:*^c
}.
\tag{RunCase}
\]

`RunInv` は `RunCase` derivation の provability premise であり、raw constructor の引数は
\(A,B,f,a,u\) である。
第三引数が compatible reduction で変化したときは、equality proposition 自身の subject reduction
によって invariant を輸送する。

### Reduction 定義

reduction \(\to\) は、以下の root rule、既存の beta rule、および全 term constructor に対する
compatible closure から生成される最小の関係とする。特に `runCase` の \(A,B,f,a,u\)、
`RfType` の引数、`RfTerm` の source type annotation と payload の内部で reduction が進む。

#### Type reflection

base type reflection と非依存 product reflection を次で与える。

\[
\operatorname{RfType}(X^c)
\to
\widehat X.
\tag{Rf-Base}
\]

\[
\operatorname{RfType}((x^{*^c}:A)\to B)
\to
 (z^{*^s_0}:\operatorname{RfType}(A))
 \to\operatorname{RfType}(B)
\qquad
x^{*^c}\notin\operatorname{FV}(B),
\quad
z\notin
\operatorname{Names}
\left(
  \operatorname{FV}(A)\cup\operatorname{FV}(B)
\right).
\tag{Rf-Arrow}
\]

`Rf-Arrow` の source binder は Compute variable であり、target binder には fresh な Set variable を
取る。二つの side condition により、source binder を消しても \(x^{*^c}\) が free にならず、target
binder も既存の variable を capture しない。

#### Term reflection

reflected function と reflected argument を Compute application の reflection に戻す。

\[
\operatorname{RfTerm}_{A\to B}(f)
@
\operatorname{RfTerm}_A(a)
\to
\operatorname{RfTerm}_B(f@a).
\tag{Rf-App}
\]

二つの source type annotation に現れる \(A\) は同じ metavariable であり、raw syntax 上で一致する。

compatible closure のうち payload に関する instance を次の名前で参照する。

\[
\dfrac{m\to m'}{
  \operatorname{RfTerm}_A(m)
  \to
  \operatorname{RfTerm}_A(m')
}.
\tag{Rf-Cong}
\]

#### `run` と `runCase`

\[
\operatorname{run}_{A,B}(f,a)
\to
\operatorname{runCase}_{A,B}(f,a,f@a).
\tag{Run-Enter}
\]

第三引数の compatible reduction を明示すると次である。

\[
\dfrac{
  m\to m'
}{
  \operatorname{runCase}_{A,B}(f,a,m)
  \to
  \operatorname{runCase}_{A,B}(f,a,m')
}.
\tag{RunCase-Cong}
\]

\[
\operatorname{runCase}_{A,B}
(f,a,\operatorname{right}_{A,B}(b))
\to
b.
\tag{RunCase-Right}
\]

\[
\operatorname{runCase}_{A,B}
(f,a,\operatorname{left}_{A,B}(a'))
\to
\operatorname{run}_{A,B}(f,a').
\tag{RunCase-Left}
\]

Run-Enter、RunCase-Right、RunCase-Left は無条件の root reduction であり、RunCase-Cong が一段計算を
第三引数の中で進める。例えば \(f@a\to^n\operatorname{left}(a')\) なら、

\[
\begin{aligned}
\operatorname{run}(f,a)
&\to
\operatorname{runCase}(f,a,f@a)\\
&\to^n
\operatorname{runCase}(f,a,\operatorname{left}(a'))\\
&\to
\operatorname{run}(f,a').
\end{aligned}
\]

右の場合も同様に \(b\) へ進む。

### Definitional equality

上の共通 reduction の反射・対称・推移閉包を definitional equality \(\equiv\) とする。
`system.md` の conversion rule に現れる \(\equiv^\beta\) をこの \(\equiv\) に置き換える。

## Compute product の非依存性

`Rf-Arrow` を well-typed な Compute type に適用できることには、次の補題を使う。

> **Compute non-dependency.**  
> \(\Gamma,x:A:*^c\vdash B:*^c\) が導出でき、\(x\) が Compute term variable ならば、
> \(x\notin\operatorname{FV}(B)\) である。

証明は \(B:*^c\) の sorting derivation に関する帰納法で行う。

- Compute product を形成する rule は \((*^c,*^c,*^c)\) だけである。
- \((*^c,\square^c,-)\) がないため、Compute term を引数に取って Compute type を返す type family を
  形成できない。
- 追加した formation rule のうち Compute type を作る sum と base type は、Compute term を type
  index として受け取らない。`RfType` は Set type を作り、`run` と `runCase` は指定された Compute
  type の element を作る。
- variable case では \(x:A:*^c\) から \(x:*^c\) は導出できない。後者には \(A\equiv *^c\) が必要だが、
  \(A\) と \(*^c\) の sort が異なる。

従って well-typed な Compute product は alpha 同値を除いて非依存 arrow の形になる。
ill-typed な dependent raw product は `Rf-Arrow` の side condition を満たさず、binder を保った
neutral な `RfType` 項になる。

## 一段結果の elimination

`runCase` は一段結果と現在状態の関係を RunInv として保存する specialized eliminator である。
第三引数が `left(a')` になった時点で RunInv から必要な relation を回収し、Acc-Descent によって
recursive call を型付けする。第三引数が `right(b)` になった場合は \(b:B\) を返す。

## `runCase` の subject reduction

### Run-Enter

\(\Gamma\vdash\operatorname{run}_{A,B}(f,a):B:*^c\) の Run derivation を仮定する。
function application から

\[
\Gamma\vdash f@a:A+B:*^c
\]

を得る。また equality introduction により

\[
\Gamma\vDash
\operatorname{RfTerm}_{A+B}(f@a)
=
\operatorname{RfTerm}_{A+B}(f@a)
\]

である。これは \(\operatorname{RunInv}_{A,B}(f,a,f@a)\) なので RunCase rule から

\[
\Gamma\vdash
\operatorname{runCase}_{A,B}(f,a,f@a):B:*^c
\]

を得る。従って Run-Enter は型を保存する。

### `runCase` の compatible reduction

例えば第三引数が \(u\to u'\) と進む場合、Compute subject reduction から

\[
\Gamma\vdash u':A+B:*^c
\]

を得る。invariant proposition も

\[
\operatorname{RunInv}(f,a,u)
\to
\operatorname{RunInv}(f,a,u')
\]

と進むため、provability の subject reduction で新しい invariant を得る。

\(f\)、\(a\)、source type annotation が進む場合も、Compute subject reduction、Rf-Cong、context
conversion と provability の subject reductionで RunCase の premise を輸送する。

### RunCase-Right

\[
\Gamma\vdash
\operatorname{runCase}_{A,B}
(f,a,\operatorname{right}_{A,B}(b)):B:*^c
\]

を仮定する。RunCase generation から

\[
\Gamma\vdash
\operatorname{right}_{A,B}(b):A+B:*^c
\]

を回収し、sum introduction の inversion により

\[
\Gamma\vdash b:B:*^c
\]

を得る。従って RunCase-Right は型を保存する。

### RunCase-Left

\[
\Gamma\vdash
\operatorname{runCase}_{A,B}
(f,a,\operatorname{left}_{A,B}(a')):B:*^c
\]

を仮定する。sum introduction の inversion から

\[
\Gamma\vdash a':A:*^c
\]

を得る。RunCase の invariant premise は

\[
\Gamma\vDash
\operatorname{RfTerm}_{A+B}(f@a)
=
\operatorname{RfTerm}_{A+B}(\operatorname{left}_{A,B}(a'))
\tag{1}
\]

である。

一方、\(R_f\) の relation を \(\operatorname{RfTerm}_A(a')\) と
\(\operatorname{RfTerm}_A(a)\) に適用した proposition の両辺は、Rf-App と Rf-Cong により

\[
\begin{aligned}
\operatorname{RfTerm}_{A\to A+B}(f)
@\operatorname{RfTerm}_A(a)
&\to
\operatorname{RfTerm}_{A+B}(f@a),\\
\operatorname{RfTerm}_{A\to A+B}(\operatorname{leftFun}_{A,B})
@\operatorname{RfTerm}_A(a')
&\to
\operatorname{RfTerm}_{A+B}(\operatorname{leftFun}_{A,B}@a')\\
&\to^*
\operatorname{RfTerm}_{A+B}(\operatorname{left}_{A,B}(a')).
\end{aligned}
\]

従って proposition \(R_f@\operatorname{RfTerm}_A(a')@\operatorname{RfTerm}_A(a)\) は
式 (1) と definitionally equal である。proof term に conversion を使って

\[
\Gamma\vDash
R_f@\operatorname{RfTerm}_A(a')@\operatorname{RfTerm}_A(a)
\]

を得る。RunCase の termination premise と Acc-Descent から

\[
\Gamma\vDash
\operatorname{Terminates}_{A,B}(f,a')
\]

なので、Run rule により

\[
\Gamma\vdash\operatorname{run}_{A,B}(f,a'):B:*^c
\]

を導出できる。これで RunCase-Left の subject reduction が成り立つ。

## Reflection の選択

### `RfTerm` の lambda と variable

`RfTerm` は Compute payload を glued form として保持する。lambda と variable の operational behavior
も Rf-App と Rf-Cong で定まり、例えば reflected argument に対する lambda application は

\[
\begin{aligned}
\operatorname{RfTerm}_{A\to B}(\lambda x:A.m)
@\operatorname{RfTerm}_A(a)
&\to
\operatorname{RfTerm}_B((\lambda x:A.m)@a)\\
&\to
\operatorname{RfTerm}_B(m[x:=a])
\end{aligned}
\]

と計算する。

変数は \(\operatorname{RfTerm}_A(x)\) という neutral な Set 項になる。この設計では Compute binder
と Set binder の同期を構文に加えずに、開いた Compute 計算を reflection できる。

### Rf-App の domain annotation

Rf-App の二つの domain annotation は構文上同じ \(A\) とする。この条件を完全に外すと、target
側で二つの reflected type が convertible であっても source application \(f@a\) が型付けできるとは
限らず、Rf-App の右辺に Rf-Term rule を適用できない。

各 base type に fresh な reflected type を割り当てることで reflection の injectivity を示せる
可能性はあるが、type constructor、reduction、conversion を含む injectivity lemma が必要になる。
この版の Rf-App はその補題に依存しない。

## Sort separation と一般再帰関数の利用

typing derivation に関する帰納法で次を示す。

> **Sort separation.**  
> \(\Gamma\vdash t:T:*^c\) ならば、\(t\) と \(T\) の型付き部分項には Set/Prop 専用の
> `Take`、`Power`、`Proof`、refinement は現れない。

`Run` と `RunCase` の provability premise は derivation に現れるが、Compute term の部分項ではない。
特に `run(f,Take(...))` は Compute typing を持たない。

既に typing された一般再帰関数を、後から定義する一段遷移 \(f\) の本体で呼び出してよい。
その呼び出しに現れる内側の `run` は、外側の Run derivation の proper premise に含まれる。
Run-Enter 後は第三引数の compatible reduction により、その内側の `run` も通常の reduction で進む。

## Reduction と confluence

### closure condition の除去

Run reduction の適用可能性は raw term の root constructor だけで決まる。

| rule | root | condition |
| --- | --- | --- |
| Run-Enter | `run` | なし |
| RunCase-Right | `runCase` with `right` third argument | なし |
| RunCase-Left | `runCase` with `left` third argument | なし |

一段計算 \(f@a\) の評価は `runCase` の第三引数に対する compatible reduction である。
reduction の定義が自身の反射推移閉包を premise として参照しないため、旧 Run-End/Run-Step にあった
confluence proof の循環は生じない。

### 主な critical pair

Run-Enter と引数内部の reduction を考える。\(f\to f'\) のとき、二つの path は

\[
\begin{aligned}
\operatorname{run}(f,a)
&\to
\operatorname{runCase}(f,a,f@a)
\to^*
\operatorname{runCase}(f',a,f'@a),\\
\operatorname{run}(f,a)
&\to
\operatorname{run}(f',a)
\to
\operatorname{runCase}(f',a,f'@a)
\end{aligned}
\]

で合流する。Run-Enter が \(f\) を二箇所に複製するため、一方の path では compatible reduction を
それぞれの copy に適用する。\(a\to a'\) も同じである。

RunCase-Right と第三引数内部の reduction は、constructor argument \(b\to b'\) に対して

\[
\operatorname{runCase}(f,a,\operatorname{right}(b))
\to b\to b'
\]

と

\[
\operatorname{runCase}(f,a,\operatorname{right}(b))
\to
\operatorname{runCase}(f,a,\operatorname{right}(b'))
\to b'
\]

で合流する。RunCase-Left も \(a'\to a''\) に対して同様である。`left` と `right` は異なる raw
constructor なので、二つの RunCase root rule は overlap しない。

基礎 reduction の parallel reduction に、Run-Enter と二つの RunCase root contraction、および
それらと immediate subterm の parallel reduction を同時に行う規則を加えることで complete
development proof を拡張できる見込みがある。旧規則と異なり、constructor 到達性や既に示したい
confluence を parallel rule の premise に使わない。

## 閉項の停止と reducibility の範囲

Run-Enter が常に適用できるため、閉じた `run` の一段 progress 自体は直接得られる。必要な停止性は、
Run-Enter と RunCase-Left を繰り返した後に RunCase-Right へ到達することである。

任意の well-formed context に対する strong normalization は成り立たない。例えば

\[
f:=\lambda x:A.\operatorname{left}_{A,B}(x)
\]

とし、context で

\[
p:\operatorname{Terminates}_{A,B}(f,a):*^p
\]

を仮定すると `run(f,a)` を型付けできるが、

\[
\begin{aligned}
\operatorname{run}(f,a)
&\to
\operatorname{runCase}(f,a,f@a)\\
&\to^*
\operatorname{runCase}(f,a,\operatorname{left}(a))\\
&\to
\operatorname{run}(f,a)
\end{aligned}
\]

という cycle がある。

従って fundamental reducibility theorem は、Set/Prop の仮定を意味論的に満たす closing
substitution に相対化して次の形にする。

> **期待する fundamental theorem.**  
> \(\Gamma\vdash t:T:*^c\) とし、\(\rho\) が \(\Gamma\) の Compute variable を閉じた reducible
> term に写し、Set/Prop premise を真にする closing substitution ならば、\(t\rho\) は
> \(T\rho\) の reducibility candidate に属する。

Compute non-dependency により candidate は単純型の構造に沿って定義できる。

- base type では strong normalization と canonical value を要求する。
- \(A+B\) では normalization 後の `left` / `right` の payload が対応する candidate に属することを
  要求する。
- \(A\to B\) では reducible な \(A\) の引数への application が \(B\) で reducible であることを
  要求する。
- Run case では \(\operatorname{Acc}(R_f,-)\) に関する well-founded induction を使う。

空 context には偽の accessibility assumption がないため、基礎 Set/Prop calculus と `Acc` の
soundness を仮定すれば、この theorem から閉じた Compute 項の停止が従う見込みがある。
証明には sum canonicity、substitution、nested `run` の candidate closure、reflection が Compute
reduction を追跡することが必要である。

## 最小不動点によるモデル

Compute type \(A,B\) の carrier をそれぞれ集合 \(X,Y\) とし、一段遷移の denotation を

\[
f:X\to X+Y
\]

とする。reflection は同じ carrier を Set 側で参照するものとして説明する。

### Accessibility

\(\mathcal P(X)\) 上の monotone operatorを

\[
\Phi_f(S)
:=
\{x\in X\mid
  \forall y\in X.\ f(x)=\operatorname{left}(y)\Rightarrow y\in S
\}
\]

と定義する。accessible states は最小不動点

\[
\operatorname{AccPart}(f)
:=
\mu\Phi_f
=
\bigcap
\{S\subseteq X\mid\Phi_f(S)\subseteq S\}
\]

である。\(\Phi_f\) は monotone なので Knaster--Tarski によりこの intersection は fixed point に
なる。model では

\[
\llbracket\operatorname{Acc}(R_f,a)\rrbracket
=
\begin{cases}
1,&\llbracket a\rrbracket\in\operatorname{AccPart}(f),\\
0,&\text{otherwise}
\end{cases}
\]

と解釈する。

### `run` の graph

\(\mathcal P(X\times Y)\) 上の operatorを

\[
\begin{aligned}
\Psi_f(G)
:={}&
\{(x,b)\mid f(x)=\operatorname{right}(b)\}\\
&\cup
\{(x,b)\mid
  \exists y.\ f(x)=\operatorname{left}(y)\land(y,b)\in G
\}
\end{aligned}
\]

とし、

\[
G_f
:=
\mu\Psi_f
=
\bigcap
\{G\subseteq X\times Y\mid\Psi_f(G)\subseteq G\}
\]

と置く。\(f\) が関数なので \(G_f\) は partial function の graph であり、

\[
\operatorname{dom}(G_f)
=
\operatorname{AccPart}(f)
\]

が成り立つ。

raw term の interpretation を全域な \(W\)-valued operation にするため、\((a,b)\in G_f\) を満たす
一意な \(b\) があるときはその \(b\)、ないときは外部モデルの既定値 \(0\) を返す
\(\operatorname{runVal}(f,a)\) を定義する。Run typing の accessibility premise が真なら
\(a\in\operatorname{dom}(G_f)\) なので、typed term では必ず前者になり \(Y\) の元を返す。

\[
\llbracket\operatorname{run}(f,a)\rrbracket
:=
\operatorname{runVal}(\llbracket f\rrbracket,\llbracket a\rrbracket).
\]

### `runCase`

\(a\in\operatorname{AccPart}(f)\) かつ \(u=f(a)\) のとき、

\[
\operatorname{runCaseVal}(f,a,u)
:=
\begin{cases}
b,&u=\operatorname{right}(b),\\
\operatorname{runVal}(f,a'),&u=\operatorname{left}(a')
\end{cases}
\]

とする。left の場合、fixed point equation と \(u=f(a)\) から
\(a'\in\operatorname{AccPart}(f)\) が従う。premise が成立しない入力には外部モデルの既定値 \(0\) を
割り当てる。

RunInv の soundness により、well-typed な `runCase` の第三引数の値は \(f(a)\) と等しい。従って

\[
\operatorname{runVal}(f,a)
=
\operatorname{runCaseVal}(f,a,f(a))
\]

で Run-Enter が意味を保存する。\(u=\operatorname{right}(b)\) と
\(u=\operatorname{left}(a')\) の二場合は、それぞれ RunCase-Right と RunCase-Left の意味保存を
与える。

この解釈では `run` の値を accessibility proof の構造に依存させない。異なる proof derivation から
同じ Run term が型付けされても、決定的な graph \(G_f\) が与える値は一意である。

## Set 側での利用

Run rule と Rf-Term から

\[
\Gamma\vdash
\operatorname{RfTerm}_B(\operatorname{run}_{A,B}(f,a))
:
\operatorname{RfType}(B):*^s_0
\]

を得る。Rf-Cong により Run-Enter と `runCase` の reduction は payload 内でも進む。

\[
\begin{aligned}
\operatorname{RfTerm}_B(\operatorname{run}(f,a))
&\to
\operatorname{RfTerm}_B(\operatorname{runCase}(f,a,f@a))\\
&\to^*
\operatorname{RfTerm}_B(b)
\end{aligned}
\]

従って Compute 側の停止計算と Set 側の reflected computation は同じ小ステップ列を共有する。

## Variable の sort annotation と freshness

`system.md` の raw variable は \(x^s\) であり、context entry \(x:A:s\) は \(x^s\) を bind する。
free variable も sort annotation を含む raw variable の集合として定義する。

\[
\operatorname{FV}(t)
\subseteq
\{x^s\mid x\in\operatorname{Name},\ s\in\mathcal S'\}.
\]

name stem の集合を

\[
\operatorname{Names}(V)
:=
\{x\mid\exists s.\ x^s\in V\}
\]

とする。binder に fresh な name \(z\) を取るとは、対象の free variable と context domain に現れる
name stem の集合に \(z\) が属さないことをいう。必要なら alpha-renaming によってこの条件を満たす。

本文中の

\[
\lambda x:A.m,
\qquad
(x:A)\to B
\]

は、\(\Gamma\vdash A:s\) が明らかな箇所での

\[
\lambda x^s:A.m,
\qquad
(x^s:A)\to B
\]

の略記である。Compute binder では \(s=*^c\)、reflected Set binder では \(s=*^s_0\) になる。

Rf-Arrow では source binder \(x^{*^c}\) の superscript を張り替えず、target に fresh な name
\(z\) を取って \(z^{*^s_0}\) を bind する。Compute non-dependency から
\(x^{*^c}\notin\operatorname{FV}(B)\) なので、source codomain に variable translation は発生しない。

`RfTerm` は glued form なので、payload 内の Compute variable は
\(\operatorname{RfTerm}_A(x^{*^c})\) のように元の annotation を保持する。Set 側の普通の variable
\(x^{*^s_0}\) への置換は行わない。substitution と alpha-equivalence も full raw variable \(x^s\) に
対して capture-avoiding に定義する。

## 必要なメタ定理

`system.md` に統合する前に必要な項目を整理する。

- Compute non-dependency と sort separation
- `left`、`right`、`runCase` を含む substitution
- base calculus、sum formation/introduction、reflection、Run-Enter、RunCase-Cong、
  RunCase-Left/Right の subject reduction
- RunInv の reduction・substitution による保存
- Acc-Descent の soundness
- Rf-Type/Rf-Term/Rf-App の typing preservation
- Run-Enter と compatible reduction、RunCase root rule の critical-pair analysis
- 拡張した parallel reduction の complete development
- 妥当な closing substitution に相対化した Compute reducibility theorem
- 閉じた一段計算の sum canonicity
- accessibility induction による閉じた `run` の停止
- reflected computation の停止
- \(\operatorname{dom}(G_f)=\operatorname{AccPart}(f)\) と graph の一意性
- Run、RunCase、reflection reduction の model soundness
