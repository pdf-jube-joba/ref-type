# 非階層の単純型付き Compute sort と accessibility を用いた再帰

ここでは、階層化しない単一の Compute sort を追加し、Compute 側の型付けを非依存な単純型付き lambda calculus に制限する。停止性は Set/Prop 側の accessibility によって記述する。

主な方針は次のとおりである。

| item | treatment |
| --- | --- |
| Compute | Set/Prop とは別の sort として残す |
| Compute 側の product | \((*^c,*^c,*^c)\) だけを認め、非依存に制限する |
| `Rf` | pure Compute 構文から Set 構文へのメタレベル変換とする |
| reflection judgement | 導入しない |
| reduction | Set/Prop/Compute に共通の \(\to\) だけを使う |
| `terminates` | accessibility `Acc` を用いた略記とする |
| `End`, `Step` | 追加しない |
| `run` | non-structural recursion 固有の項として追加する |

## 1. Sort

`system.md` の sort に Compute 用の sort を追加する。

\[
\begin{aligned}
\mathcal{S}'
:={}&
\{*^s_i,\square^s_i\mid i\in\mathbb{N}\} \\
&\cup \{*^p,\square^p\}
\cup \{*^c,\square^c\}.
\end{aligned}
\]

それぞれの意味は次のとおりである。

| sort | meaning |
| --- | --- |
| \(*^s_i,\square^s_i\) | description 用の Set |
| \(*^p,\square^p\) | proposition |
| \(*^c,\square^c\) | computation |

axiom は次のように拡張する。

\[
\mathcal{A}'
:=
\mathcal{A}
\cup
\{(*^c,\square^c)\}.
\]

Compute 用の product rule は次の組だけとする。

\[
\mathcal{R}_c
:=
\{(*^c,*^c,*^c)\}.
\]

\[
\mathcal{R}' := \mathcal{R}\cup\mathcal{R}_c.
\]

ただし、PTS の通常の dependent-product formation にこの triple をそのまま使うと、codomain \(B\) が \(x\) に依存する \(\Pi x:A.B\) も形成できる。Compute 側を単純型付きにするため、Compute product の formation には次の side condition を加える。

\[
x\notin\operatorname{FV}(B).
\]

したがって、Compute product は \(\Pi x:A.B\) ではなく \(A\to B\) と書く。その formation rule は次のとおりである。

\[
\dfrac{
  \Gamma\vdash A:*^c
  \qquad
  \Gamma\vdash B:*^c
}{
  \Gamma\vdash A\to B:*^c
}.
\]

この段階では、Compute universe を domain とする product、Compute 側の type-level function、Compute 項に依存する型は認めない。

\(\square^c\) は \(*^c:\square^c\) を述べるためだけに使う。\(\square^c\) 自身に対する axiom や、\(\square^c\) を domain または codomain に持つ product rule は追加しない。

## 2. Compute 側の型と項

Compute 側の型は、base type、非依存関数型、非依存な代数的データ型からなる。

\[
A,B ::= X \mid A\to B \mid I(A_1,\ldots,A_n).
\]

\(X\) は base type、\(I\) は Compute 側の非依存な inductive type constructor を表す。

Compute 項には、`run` を含まない pure Compute term \(p\) と、`run` を含み得る general Compute term \(m\) の二種類を設ける。これは専用の typing judgement ではなく、raw syntax の区別である。

### 2.1 Pure Compute term

\[
\begin{aligned}
p ::= {}&
x
\mid \lambda x:A.p
\mid p\,p \\
&\mid C(p_1,\ldots,p_n)
\mid \operatorname{elim}_I(p,p_1,\ldots,p_n).
\end{aligned}
\]

\(C\) は Compute 側の inductive constructor、\(\operatorname{elim}_I\) はその recursor である。この構文に `run` は現れない。

### 2.2 General Compute term

\[
\begin{aligned}
m ::= {}&
p
\mid \lambda x:A.m
\mid m\,p \\
&\mid C(m_1,\ldots,m_n)
\mid \operatorname{elim}_I(m,m_1,\ldots,m_n) \\
&\mid \operatorname{run}_{A,B}(p,p).
\end{aligned}
\]

最後の生成規則により、`run` の一段遷移関数と初期状態は pure Compute term に制限される。

Compute 項の variable、lambda、application、constructor、recursor の typing rule は、非依存性の制限を除いて `system.md` の通常の typing rule と同じである。`run` の typing rule は後で定義する。

## 3. Compute 側の sum 型

Compute 側に通常の sum 型を置く。

| category | conclusion | premises |
| --- | --- | --- |
| sum formation | \(\Gamma\vdash A+B:*^c\) | \(\Gamma\vdash A:*^c\)<br>\(\Gamma\vdash B:*^c\) |
| left introduction | \(\Gamma\vdash\operatorname{left}(a):A+B:*^c\) | \(\Gamma\vdash a:A:*^c\)<br>\(\Gamma\vdash B:*^c\) |
| right introduction | \(\Gamma\vdash\operatorname{right}(b):A+B:*^c\) | \(\Gamma\vdash A:*^c\)<br>\(\Gamma\vdash b:B:*^c\) |

`left` と `right` は non-structural recursion 固有の項ではなく、通常の sum 型の constructor である。

## 4. Reflection

### 4.1 Reflection はメタレベル変換である

\(\operatorname{Rf}\) は object-language の term constructor ではなく、pure Compute の raw syntax から Set の raw syntax へのメタレベル関数とする。

\[
\operatorname{Rf}
:
\text{PureComputeSyntax}
\longrightarrow
\text{SetSyntax}.
\]

したがって、次は導入しない。

| omitted item | reason |
| --- | --- |
| reflection 用の term constructor | \(\operatorname{Rf}\) は object term ではない |
| \(\vdash_{\operatorname{Rf}}\) | reflectability は pure Compute grammar によって表す |
| reflection 専用の reduction | \(\operatorname{Rf}\) の各 clause は reduction rule ではなく、メタ関数の定義である |

### 4.2 Type reflection

Compute 型の reflection を構造的に定義する。

| Compute type | reflected Set type |
| --- | --- |
| \(*^c\) | \(*^s_0\) |
| base type \(X\) | corresponding Set type \(\widehat{X}\) |
| \(A\to B\) | \(\operatorname{Rf}(A)\to\operatorname{Rf}(B)\) |
| \(I(A_1,\ldots,A_n)\) | \(\widehat{I}(\operatorname{Rf}(A_1),\ldots,\operatorname{Rf}(A_n))\) |

\(\widehat{I}\) は Compute 側の inductive type \(I\) に対応して生成される Set 側の inductive type である。

この定式化では、すべての Compute base type と Compute inductive type が \(*^s_0\) に reflection できることを仮定する。\(*^s_0\) は関数型と対応する inductive type formation について閉じているため、すべての reflected Compute type も \(*^s_0\) に属する。

### 4.3 Context reflection

Compute context の reflection を次のように定義する。

\[
\operatorname{Rf}(\varnothing):=\varnothing.
\]

\[
\operatorname{Rf}(\Gamma,x:A:*^c)
:=
\operatorname{Rf}(\Gamma),
\widehat{x}:\operatorname{Rf}(A):*^s_0.
\]

\(\widehat{x}\) は Compute 変数 \(x\) に対応する Set 変数である。

### 4.4 Term reflection

Pure Compute term の reflection を次のように定義する。

| pure Compute term | reflected Set term |
| --- | --- |
| \(x\) | \(\widehat{x}\) |
| \(\lambda x:A.M\) | \(\lambda\widehat{x}:\operatorname{Rf}(A).\operatorname{Rf}(M)\) |
| \(M\,N\) | \(\operatorname{Rf}(M)\,\operatorname{Rf}(N)\) |
| \(C(M_1,\ldots,M_n)\) | \(\widehat{C}(\operatorname{Rf}(M_1),\ldots,\operatorname{Rf}(M_n))\) |
| \(\operatorname{elim}_I(M,M_1,\ldots,M_n)\) | \(\operatorname{elim}_{\widehat I}(\operatorname{Rf}(M),\operatorname{Rf}(M_1),\ldots,\operatorname{Rf}(M_n))\) |

`run` は pure Compute grammar に含まれないため、\(\operatorname{Rf}(\operatorname{run}(f,a))\) の clause は定義しない。

### 4.5 Reflection typing theorem

reflection に専用の typing judgement は導入せず、次をメタ定理として示す。

\[
\Gamma\vdash p:A:*^c
\quad\Longrightarrow\quad
\operatorname{Rf}(\Gamma)
\vdash
\operatorname{Rf}(p):\operatorname{Rf}(A):*^s_0,
\]

ただし \(p\) は pure Compute term とする。証明は \(\Gamma\vdash p:A:*^c\) の typing derivation に関する帰納法で行う。

## 5. Reflection と reduction

### 5.1 Reduction relation は一つだけとする

Set/Prop/Compute ごとに reduction を分けず、全項に共通の reduction

\[
\to
\]

だけを定義する。通常の \(\beta\)-reduction、帰納型の recursor reduction、各項構文に対する congruence は、すべてこの関係に含める。

Compute 専用の \(\to_c\) や Set 専用の \(\to_s\) は導入しない。

### 5.2 Reflection の substitution lemma

Pure Compute term \(M,N\) に対して、次をメタ理論上で示す。

\[
\operatorname{Rf}(M[x:=N])
=
\operatorname{Rf}(M)
[\widehat{x}:=\operatorname{Rf}(N)].
\]

証明は \(M\) の構文に関する帰納法で行う。

### 5.3 Reflection の reduction simulation

例えば Compute 側の \(\beta\)-redex は次のように写る。

\[
\begin{aligned}
\operatorname{Rf}((\lambda x:A.M)\,N)
&=
(\lambda\widehat{x}:\operatorname{Rf}(A).\operatorname{Rf}(M))
\operatorname{Rf}(N) \\
&\to
\operatorname{Rf}(M)
[\widehat{x}:=\operatorname{Rf}(N)] \\
&=
\operatorname{Rf}(M[x:=N]).
\end{aligned}
\]

したがって、

\[
\dfrac{m\to m'}
      {\operatorname{Rf}(m)\to\operatorname{Rf}(m')}
\]

という primitive rule は追加しない。代わりに、pure Compute reduction について次をメタ定理として示す。

\[
p\to p'
\quad\Longrightarrow\quad
\operatorname{Rf}(p)\to^*\operatorname{Rf}(p').
\]

この証明は reduction derivation に関する帰納法で行う。

| source reduction | reflected reduction |
| --- | --- |
| \(\beta\) | reflection substitution lemma を使う |
| application congruence | 帰納法の仮定と Set 側の congruence を使う |
| constructor congruence | 帰納法の仮定と Set 側の congruence を使う |
| recursor computation | reflected recursor の computation rule を使う |

\(\operatorname{Rf}\) は object term ではないため、この simulation theorem は object-language の reduction rule を増やさない。

## 6. Accessibility

Set/Prop 側の一般的な帰納型として accessibility を定義する。

\[
\operatorname{Acc}_A
:
(A\to A\to *^p)
\to
A
\to
*^p.
\]

ここで \(A:*^s_i\) である。constructor は `acc` 一つだけである。

\[
\operatorname{acc}_{R,x}
:
\left(
  (y:A)
  \to
  R\,y\,x
  \to
  \operatorname{Acc}_A(R,y)
\right)
\to
\operatorname{Acc}_A(R,x).
\]

`Acc` と `acc` は non-structural recursion 固有の primitive ではなく、一般の well-founded relation に使う帰納型である。

## 7. 一段遷移と停止性

pure Compute term として一段遷移関数を与える。

\[
\Gamma\vdash f:A\to A+B:*^c.
\]

reflection typing theorem によって、

\[
\operatorname{Rf}(\Gamma)
\vdash
\operatorname{Rf}(f)
:
\operatorname{Rf}(A)
\to
\operatorname{Rf}(A)+\operatorname{Rf}(B)
:*^s_0
\]

を得る。

このとき、Set 側の関係 \(R_f\) を次のように定義する。

\[
R_f
:
\operatorname{Rf}(A)
\to
\operatorname{Rf}(A)
\to
*^p.
\]

\[
R_f(a',a)
:=
\operatorname{Rf}(f)\,a
=_{\operatorname{Rf}(A)+\operatorname{Rf}(B)}
\operatorname{left}(a').
\]

これは「状態 \(a\) の次の状態が \(a'\)」という関係である。

pure Compute term \(a:A\) の停止性は、新しい inductive family ではなく、次の略記とする。

\[
\operatorname{Terminates}_{A,B}(f,a)
:=
\operatorname{Acc}_{\operatorname{Rf}(A)}
\left(R_f,\operatorname{Rf}(a)\right).
\]

このため、`terminates`, `End`, `Step` は新しい項としては追加しない。

## 8. `run`

general Compute term の構文に次を追加する。

| category | syntax |
| --- | --- |
| execution | \(\operatorname{run}_{A,B}(f,a)\) |

ここで \(f\) と \(a\) は pure Compute term である。

### 8.1 Typing

`run` の typing rule は次のとおりである。

\[
\dfrac{
\begin{array}{c}
\Gamma\vdash f:A\to A+B:*^c
\\[2pt]
\Gamma\vdash a:A:*^c
\\[2pt]
f,a\text{ are pure Compute terms}
\\[2pt]
\operatorname{Rf}(\Gamma)
\vDash
\operatorname{Terminates}_{A,B}(f,a)
\end{array}
}{
\Gamma
\vdash
\operatorname{run}_{A,B}(f,a)
:
B:*^c
}.
\]

停止証明は `run` の引数に含めず、typing derivation の premise に置く。したがって、構文は \(\operatorname{run}(f,a,p)\) ではなく \(\operatorname{run}(f,a)\) だけである。

### 8.2 Reduction

`run` の二つの reduction rule を、既存の共通 reduction \(\to\) に追加する。

| category | reduction | condition |
| --- | --- | --- |
| Run-End | \(\operatorname{run}_{A,B}(f,a)\to b\) | \(f\,a\to^*\operatorname{right}(b)\) |
| Run-Step | \(\operatorname{run}_{A,B}(f,a)\to\operatorname{run}_{A,B}(f,a')\) | \(f\,a\to^*\operatorname{left}(a')\) |

\(f\) と \(a\) は pure Compute term であり、pure Compute grammar は通常の \(\beta\)/recursor reduction について閉じている。したがって、condition に現れる reduction derivation の中で Run-End または Run-Step が使われることはない。そのため、condition 用の専用 reduction を別に定義する必要はない。

`return` は追加しない。Compute 側の値 \(b:B\) は、そのまま `run` の結果である。

### 8.3 Subject reduction に必要な補題

Run-End の場合は、通常の subject reduction から次を得る。

\[
\Gamma\vdash f\,a:A+B:*^c,
\qquad
f\,a\to^*\operatorname{right}(b)
\]

\[
\Longrightarrow
\Gamma\vdash b:B:*^c.
\]

Run-Step の場合には、次の accessibility 補題を使う。

\[
\operatorname{Acc}_X(R,x)
\land
R(y,x)
\quad\Longrightarrow\quad
\operatorname{Acc}_X(R,y).
\]

reflection reduction simulation によって、

\[
f\,a\to^*\operatorname{left}(a')
\]

から

\[
\operatorname{Rf}(f)\,\operatorname{Rf}(a)
\to^*
\operatorname{left}(\operatorname{Rf}(a'))
\]

を得る。conversion によって

\[
R_f(\operatorname{Rf}(a'),\operatorname{Rf}(a))
\]

が導かれるため、

\[
\operatorname{Terminates}(f,a)
\quad\Longrightarrow\quad
\operatorname{Terminates}(f,a')
\]

である。したがって、Run-Step の後も `run` の typing premise が保存される。

## 9. 必要なメタ定理

この拡張については、少なくとも次を示す必要がある。

| property | statement |
| --- | --- |
| pure preservation | pure Compute term の reduct も pure Compute term である |
| reflection typing | pure Compute typing derivation は Set typing derivationへ写る |
| reflection substitution | \(\operatorname{Rf}(M[x:=N])=\operatorname{Rf}(M)[\widehat{x}:=\operatorname{Rf}(N)]\) |
| reflection reduction | \(p\to p'\) ならば \(\operatorname{Rf}(p)\to^*\operatorname{Rf}(p')\) |
| reflected inductives | Compute 側の constructor/recursor は Set 側の constructor/recursor に写る |
| accessibility descent | \(\operatorname{Acc}(R,x)\) と \(R(y,x)\) から \(\operatorname{Acc}(R,y)\) が得られる |
| subject reduction | 共通 reduction \(\to\) が typing を保つ |
| run termination | `run` の typing premiseから、対応する Run-Step 列が有限である |

reflection は object-language の機能ではないため、reflection typing、substitution、reduction はいずれも object-language の rule ではなくメタ定理である。

## 10. 無矛盾性に向けた解釈

reflectable な pure Compute fragment は、Set calculus の別コピーとして解釈できる。\(\operatorname{Rf}\) はその二つのコピー間の構文的な写像である。

`run` は、

\[
\operatorname{Acc}(R_f,\operatorname{Rf}(a))
\]

の証拠に基づく well-founded iteration としてメタ理論上で解釈する。一段遷移 \(f\) は pure Compute term なので、その reflection は Set 側の全関数である。Accessibility は、\(\operatorname{left}\) を返す遷移を無限に続けられないことを表す。

この解釈を構成できれば、Compute 側に `run` を追加しても Set/Prop 側に新しい矛盾は生じないことを示せる可能性がある。

## 11. 追加される項の整理

| name | status |
| --- | --- |
| Compute sort | 追加する |
| `left`, `right` | 通常の sum 型として共有する |
| `Acc`, `acc` | 一般的な accessibility として追加する |
| `Rf` | object term ではなく、pure syntax に対するメタレベル変換とする |
| `run` | non-structural recursion 用に追加する |
| `terminates` | \(\operatorname{Acc}(R_f,-)\) の略記とし、追加しない |
| `End`, `Step` | 追加しない |
| `quote`, `comp` | \(\operatorname{Rf}\) に対応するため追加しない |
| `return` | 追加しない |
| `Nat`, `0`, `Succ`, `iter` | 停止性のためには追加しない |
| \(\vdash_{\operatorname{Rf}}\) | 追加しない |
| \(\to_c\), \(\to_s\) | 追加しない |

したがって、object-language で non-structural recursion を支えるための最小候補は次の組である。

\[
\boxed{
  *^c,
  \quad
  \operatorname{Acc}/\operatorname{acc},
  \quad
  \operatorname{run}
}.
\]

\(\operatorname{Rf}\) は object-language の項に数えない。また、このうち non-structural recursion 固有の項は `run` だけである。`Acc` は一般の well-founded relation のための帰納型である。

---
代数的データ型を一般に導入することで、 Left と Right が項として必要なくなったと主張している。
そんなわけがない。
derivation で特別扱いされる必要があるのであれば、構文として build-in に入れておかないと意味がない。
ユーザーの定義した型に対して変な derivation がつく。

pure type system を思い出すと (*, *, *) の規則しか rule にないなら (x: A) -> B は B が x に非依存になるが、そのことを忘れて不要な仮定をわざわざ足している。

pure/compute が構文レベルで判定できるのはいいが、 Set 側で gcd が使えなくなりそう。
例えば `Rf(run(gcd, (n, m)))` は型付けできてもそれが計算結果として移ってこない。
`Rf(m) -> Rf(m')` を入れてないのはこっちの意向だが、それがなくなると目的を達成できないのであれば、言ってほしかった。

メタレベルの定理の話をしているが、まずは体系として欲しいことができるかをちゃんと確かめるべき。

Acc を用いる方法はいいと思った。確かに、 End と Step よりも本質的な気がする。
