# 再帰的代数的データ型と reflection

## 体系定義

ここでは system.md と 再帰7.md の体系に、有限個の constructor を持つ
非依存な再帰的代数的データ型を加える。最初に扱う範囲は次の有限正則 datatype である。

\[
I^c(\vec A)
=
C^c_0(\vec T_0)
\mid\cdots\mid
C^c_{k-1}(\vec T_{k-1}).
\]

各 field type \(T_{ij}\) は次のいずれかである。

- parameter \(A_\ell\)
- すでに Compute/Set の対応が定められた閉じた型 \(K\)
- 再帰的な self occurrence \(I^c(\vec A)\)

従って constructor は有限個の field を持ち、self occurrence は直接かつ正の位置にだけ
現れる。この範囲には natural number、list、option、finite tree が含まれる。

datatype 宣言は、Compute 側の \(I^c,C^c_i\) と同時に、fresh な Set 側の
鏡像 \(I^s,C^s_i\) を生成する。一般の代数的データ型の宣言から constructor を生成しても、
\(C^c_i\) と \(C^s_i\) はそれぞれ raw term constructor であり、それぞれの typing rule を持つ。

### 構文定義

sort、variable、context は 再帰7.md と同じものを使う。datatype 宣言環境を
\(\Delta\) と書き、各宣言の datatype 名と constructor 名は大域的に fresh であるとする。

term grammar に次を加える。

\[
\begin{aligned}
t::=\cdots
&\mid I^c(\vec A)
\mid C^c_i[\vec A](\vec m)\\
&\mid \operatorname{case}^c_{I,B}
       (m;g_0,\ldots,g_{k-1})\\
&\mid I^s(\vec S)
\mid C^s_i[\vec S](\vec u)\\
&\mid \operatorname{case}^s_{I,S}
       (u;h_0,\ldots,h_{k-1})\\
&\mid \operatorname{ind}^s_I
       (u;Q;d_0,\ldots,d_{k-1}).
\end{aligned}
\]

\(\operatorname{case}\) の branch は binder を内蔵する構文ではなく、curried function として
与える。constructor \(i\) の Compute branch type を

\[
\operatorname{Br}^c_i(B)
:=
T_{i1}\to\cdots\to T_{in_i}\to B
\]

と書く。鏡像 field type は

\[
\widehat T_{ij}
:=
\begin{cases}
S_\ell,&T_{ij}=A_\ell,\\
\widehat K,&T_{ij}=K,\\
I^s(\vec S),&T_{ij}=I^c(\vec A)
\end{cases}
\]

であり、Set branch type を

\[
\operatorname{Br}^s_i(S)
:=
\widehat T_{i1}\to\cdots\to\widehat T_{in_i}\to S
\]

とする。閉じた型 \(K\) とその鏡像 \(\widehat K\) には宣言時に

\[
\operatorname{RfType}(K)\equiv\widehat K
\]

となる対応を与える。

Set 側の induction branch も生成する。constructor \(i\) の recursive field の位置を
\(r_{i1},\ldots,r_{iq_i}\) とすると、

\[
\begin{aligned}
\operatorname{IndBr}^s_i(Q)
:={}&
(x_1:\widehat T_{i1})\to\cdots\to
(x_{n_i}:\widehat T_{in_i})\to\\
&Q@x_{r_{i1}}\to\cdots\to Q@x_{r_{iq_i}}\to
Q@\left(C^s_i(\vec x)\right).
\end{aligned}
\]

ここで \(Q:I^s(\vec S)\to *^p\) である。induction hypothesis は recursive field にだけ付く。

### Reduction 定義

通常の beta reduction、system.md の root reduction、およびすべての term constructor に対する
compatible closure に次を加える。

#### Datatype case

\[
\begin{aligned}
&\operatorname{case}^c_{I,B}
\left(C^c_i[\vec A](m_1,\ldots,m_{n_i});
g_0,\ldots,g_{k-1}\right)\\
&\qquad\Rightarrow
g_i@m_1@\cdots@m_{n_i},\\[4pt]
&\operatorname{case}^s_{I,S}
\left(C^s_i[\vec S](u_1,\ldots,u_{n_i});
h_0,\ldots,h_{k-1}\right)\\
&\qquad\Rightarrow
h_i@u_1@\cdots@u_{n_i}.
\end{aligned}
\tag{Case-C, Case-S}
\]

これは一層のケース分析である。一般再帰の一段関数が再帰的な状態を観察するには
これで十分である。

Set 側の induction は recursive field に対してだけ再帰する。

\[
\begin{aligned}
&\operatorname{ind}^s_I
\left(
  C^s_i(\vec u);Q;d_0,\ldots,d_{k-1}
\right)\\
&\qquad\Rightarrow
d_i@u_1@\cdots@u_{n_i}@
\operatorname{ind}^s_I(u_{r_{i1}};Q;\vec d)@
\cdots@
\operatorname{ind}^s_I(u_{r_{iq_i}};Q;\vec d).
\end{aligned}
\tag{Ind-S}
\]

#### Type reflection

従来の Rf-Arrow に加え、datatype 宣言ごとに次を生成する。

\[
\operatorname{RfType}
\left(I^c(A_1,\ldots,A_p)\right)
\Rightarrow
I^s
\left(
\operatorname{RfType}(A_1),\ldots,
\operatorname{RfType}(A_p)
\right).
\tag{Rf-Ind}
\]

この rule は再帰方程式を一層 unfold するのではなく、名前付き Compute datatype を
ペアになった Set datatype へ写す。

#### Term reflection

constructor ごとに次を生成する。

\[
\begin{aligned}
&\operatorname{RfTerm}_{I^c(\vec A)}
\left(C^c_i[\vec A](m_1,\ldots,m_{n_i})\right)\\
&\qquad\Rightarrow
C^s_i
\left[
  \operatorname{RfType}(A_1),\ldots,
  \operatorname{RfType}(A_p)
\right]
\left(
  \operatorname{RfTerm}_{T_{i1}}(m_1),\ldots,
  \operatorname{RfTerm}_{T_{in_i}}(m_{n_i})
\right).
\end{aligned}
\tag{Rf-Ctor}
\]

nullary constructor の場合、右辺は単に \(C^s_i\) である。recursive field の annotation は
\(I^c(\vec A)\) のままなので、再帰的な値全体を一度に変換する meta-level recursion は
必要ない。外側の constructor が観察されるたびに、必要な子だけが次の
RfTerm glued form として現れる。

従来どおり RfTerm の source type annotation と payload は compatible reduction の対象である。
従って

\[
m\Rightarrow^* C^c_i(\vec m)
\quad\Longrightarrow\quad
\operatorname{RfTerm}_{I^c(\vec A)}(m)
\Rightarrow^*
C^s_i(\overrightarrow{\operatorname{RfTerm}(m)}).
\]

Set 側の case に reflected Compute branch を与えた場合のために、Rf-App と同じ方向の次の
fusion rule を加える。

\[
\begin{aligned}
&\operatorname{case}^s_{I,\operatorname{RfType}(B)}
\left(
  \operatorname{RfTerm}_{I^c(\vec A)}(m);
  \operatorname{RfTerm}_{\operatorname{Br}^c_0(B)}(g_0),
  \ldots,
  \operatorname{RfTerm}_{\operatorname{Br}^c_{k-1}(B)}(g_{k-1})
\right)\\
&\qquad\Rightarrow
\operatorname{RfTerm}_B
\left(
  \operatorname{case}^c_{I,B}(m;g_0,\ldots,g_{k-1})
\right).
\end{aligned}
\tag{Rf-Case}
\]

Rf-Case は閉じた constructor を計算するだけなら冗長だが、
開いた glued form に対する Set case を Compute payload のケース分析へ戻せる。
後で示すように Rf-Ctor との critical pair は合流する。

#### Definitional equality

\[
\equiv
:=
(\Rightarrow\cup\Leftarrow)^*.
\]

### Judgement 定義

judgement は従来の四種類のままである。datatype 宣言は新しい judgement ではなく、
環境 \(\Delta\) の well-formedness condition として検査する。

\[
\operatorname{WF}(\Gamma),
\qquad
\Gamma\vdash t:s,
\qquad
\Gamma\vdash t:T:s,
\qquad
\Gamma\vDash P.
\]

### Derivation 定義

各 well-formed datatype 宣言は次の rule を生成する。

#### Compute datatype

| category | conclusion | premises |
| --- | --- | --- |
| inductive form | \(\Gamma\vdash I^c(\vec A):*^c\) | すべての \(\Gamma\vdash A_\ell:*^c\) |
| constructor | \(\Gamma\vdash C^c_i[\vec A](\vec m):I^c(\vec A):*^c\) | すべての \(\Gamma\vdash A_\ell:*^c\)<br>すべての \(\Gamma\vdash m_j:T_{ij}:*^c\) |
| case | \(\Gamma\vdash\operatorname{case}^c_{I,B}(m;\vec g):B:*^c\) | \(\Gamma\vdash m:I^c(\vec A):*^c\)<br>\(\Gamma\vdash B:*^c\)<br>すべての \(\Gamma\vdash g_i:\operatorname{Br}^c_i(B):*^c\) |

#### Set datatype

| category | conclusion | premises |
| --- | --- | --- |
| inductive form | \(\Gamma\vdash I^s(\vec S):*^s_0\) | すべての \(\Gamma\vdash S_\ell:*^s_0\) |
| constructor | \(\Gamma\vdash C^s_i[\vec S](\vec u):I^s(\vec S):*^s_0\) | すべての \(\Gamma\vdash S_\ell:*^s_0\)<br>すべての \(\Gamma\vdash u_j:\widehat T_{ij}:*^s_0\) |
| case | \(\Gamma\vdash\operatorname{case}^s_{I,S}(u;\vec h):S:*^s_0\) | \(\Gamma\vdash u:I^s(\vec S):*^s_0\)<br>\(\Gamma\vdash S:*^s_0\)<br>すべての \(\Gamma\vdash h_i:\operatorname{Br}^s_i(S):*^s_0\) |

Set 側の datatype は reflected parameter だけでなく、任意の \(S_\ell:*^s_0\) に対して使える。
Rf-Ind はその特別な instantiation を作る。

#### Set induction

| category | conclusion | premises |
| --- | --- | --- |
| induction | \(\Gamma\vdash\operatorname{ind}^s_I(u;Q;\vec d):Q@u:*^p\) | \(\Gamma\vdash u:I^s(\vec S):*^s_0\)<br>\(\Gamma\vdash Q:(x:I^s(\vec S))\to *^p:\sq^p\)<br>すべての \(\Gamma\vdash d_i:\operatorname{IndBr}^s_i(Q):*^p\) |

これは Prop 内への elimination である。特に、reflected state に対する
accessibility や measure の証明を datatype induction で構成できる。

Reflection の formation rule は従来のままである。

| category | conclusion | premises |
| --- | --- | --- |
| reflection type | \(\Gamma\vdash\operatorname{RfType}(A):*^s_0\) | \(\Gamma\vdash A:*^c\) |
| reflection term | \(\Gamma\vdash\operatorname{RfTerm}_A(m):\operatorname{RfType}(A):*^s_0\) | \(\Gamma\vdash m:A:*^c\) |

## 匿名の再帰型を直接 reflection する問題

例えば再帰型を匿名の

\[
\mu X^{\sq^c}.F(X)
\]

で表し、次を素朴に試みるとする。

\[
\operatorname{RfType}(\mu X.F(X))
\mathrel{\Rightarrow?}
\mu Y.\operatorname{RfType}(F(X)).
\]

再帰7.md の定義では型変数の
\(\operatorname{RfType}(X^{\sq^c})\) は neutral な glued form として残る。そのため右辺の
\(Y\) はこの occurrence を bind せず、上の式は reflection 後の再帰型にならない。

匿名の \(\mu\) に対しては、実際には次の binder-aware な変換が必要である。

\[
\operatorname{RfType}(\mu X.F)
\Rightarrow
\mu Y.\operatorname{RfType}^{X\mapsto Y}(F).
\]

これは現在の一項の raw constructor RfType とは別の機構である。
名前付き宣言とペアの \(I^c,I^s\) を使うと、self occurrence の対応は宣言環境
\(\Delta\) が保持するため、Compute binder を Set binder へ貼り替える必要がない。

また、再帰型の方程式を definitional equality とする equi-recursive な rule よりも、
名前付きの inductive type と constructor/case による iso-recursive な interface の方が、
constructor head の識別、generation、confluence の証明に合っている。

## 例

### Natural number

\[
\mathbb N^c
=
\operatorname{zero}^c
\mid
\operatorname{succ}^c(\mathbb N^c)
\]

に対して、宣言時に

\[
\mathbb N^s
=
\operatorname{zero}^s
\mid
\operatorname{succ}^s(\mathbb N^s)
\]

を生成する。reflection は次のように進む。

\[
\begin{aligned}
\operatorname{RfType}(\mathbb N^c)
&\Rightarrow\mathbb N^s,\\
\operatorname{RfTerm}_{\mathbb N^c}(\operatorname{zero}^c)
&\Rightarrow\operatorname{zero}^s,\\
\operatorname{RfTerm}_{\mathbb N^c}
  (\operatorname{succ}^c(n))
&\Rightarrow
\operatorname{succ}^s
  (\operatorname{RfTerm}_{\mathbb N^c}(n)).
\end{aligned}
\]

### List

\[
\operatorname{List}^c(A)
=
\operatorname{nil}^c
\mid
\operatorname{cons}^c
\left(A,\operatorname{List}^c(A)\right)
\]

の鏡像は

\[
\operatorname{List}^s(S)
=
\operatorname{nil}^s
\mid
\operatorname{cons}^s
\left(S,\operatorname{List}^s(S)\right)
\]

である。

\[
\begin{aligned}
\operatorname{RfType}
  (\operatorname{List}^c(A))
&\Rightarrow
\operatorname{List}^s(\operatorname{RfType}(A)),\\
\operatorname{RfTerm}_{\operatorname{List}^c(A)}
  (\operatorname{nil}^c[A])
&\Rightarrow
\operatorname{nil}^s[\operatorname{RfType}(A)],\\
\operatorname{RfTerm}_{\operatorname{List}^c(A)}
  (\operatorname{cons}^c[A](a,xs))
&\Rightarrow
\operatorname{cons}^s[\operatorname{RfType}(A)]
\left(
  \operatorname{RfTerm}_A(a),
  \operatorname{RfTerm}_{\operatorname{List}^c(A)}(xs)
\right).
\end{aligned}
\]

閉じた \(xs\) は外側から必要なだけ constructor を露出し、開いた
\(\operatorname{RfTerm}_{\operatorname{List}^c(A)}(x^{*^c})\) は neutral なまま残る。

### List を state にする一般再帰

\(\operatorname{Pair}^c\) も二 field の datatype として定義し、

\[
\operatorname{State}^c(A)
:=
\operatorname{Pair}^c(\operatorname{List}^c(A),\mathbb N^c)
\]

とする。一段関数を Compute case で

\[
\begin{aligned}
\operatorname{lenStep}
  (\operatorname{pair}^c(\operatorname{nil}^c,n))
&:=
\operatorname{finish}(n),\\
\operatorname{lenStep}
  (\operatorname{pair}^c(\operatorname{cons}^c(a,xs),n))
&:=
\operatorname{continue}
  (\operatorname{pair}^c(xs,\operatorname{succ}^c(n)))
\end{aligned}
\]

と定義する。Set 側の list induction を使うと

\[
(xs:\operatorname{List}^s(\operatorname{RfType}(A)))
\to
(n:\mathbb N^s)
\to
\operatorname{Acc}_{\operatorname{State}^c(A),\mathbb N^c}
\left(
  \operatorname{lenStep},
  \operatorname{pair}^s(xs,n)
\right)
\]

を証明できる。これを reflected Compute state に適用すれば Run rule の premise が得られ、

\[
\operatorname{length}^c(xs)
:=
\operatorname{run}
\left(
  \operatorname{lenStep},
  \operatorname{pair}^c(xs,\operatorname{zero}^c)
\right)
:
\mathbb N^c
\]

を定義できる。閉じた \(xs\) では

\[
\operatorname{RfTerm}_{\mathbb N^c}
\left(\operatorname{length}^c(xs)\right)
\Rightarrow^*
\operatorname{succ}^s(\cdots\operatorname{zero}^s)
\]

となる。state と result の双方に datatype を使っても、Run/RunCase の規則自体は変わらない。

## Rf-Ctor、Rf-Case の型保存

Rf-Ctor の source の typing generation から、すべての

\[
\Gamma\vdash m_j:T_{ij}:*^c
\]

を回収できる。Rf-Term により

\[
\Gamma\vdash
\operatorname{RfTerm}_{T_{ij}}(m_j)
:
\operatorname{RfType}(T_{ij}):*^s_0
\]

である。field の三つの場合に対し、Rf-Ind と既存の type reflection から

\[
\operatorname{RfType}(T_{ij})
\equiv
\widehat T_{ij}
\]

を得る。従って Set constructor rule により Rf-Ctor の右辺は

\[
I^s(\overrightarrow{\operatorname{RfType}(A)})
\]

を型に持つ。これは source の表示型
\(\operatorname{RfType}(I^c(\vec A))\) と Rf-Ind で convertible なので、subject reduction が成り立つ。

Rf-Case では、既存の Rf-Arrow と Rf-Ind を反復すると

\[
\operatorname{RfType}(\operatorname{Br}^c_i(B))
\equiv
\operatorname{Br}^s_i(\operatorname{RfType}(B))
\]

となる。左辺の Set case と右辺の RfTerm はどちらも
\(\operatorname{RfType}(B)\) を型に持つ。

## Confluence で増える peak

datatype 自体が再帰的であることは、raw reduction が再帰方程式を無条件に unfold することを
意味しない。constructor/case の root rule は有限個で、異なる constructor tag は overlap しない。

調べる必要がある新しい peak は次である。

### Rf-Ctor と payload congruence

\(m_j\Rightarrow m'_j\) ならば、

\[
\begin{aligned}
\operatorname{RfTerm}_{I^c(\vec A)}
  (C^c_i(\ldots,m_j,\ldots))
&\Rightarrow
\operatorname{RfTerm}_{I^c(\vec A)}
  (C^c_i(\ldots,m'_j,\ldots))\\
&\Rightarrow
C^s_i(\ldots,\operatorname{RfTerm}_{T_{ij}}(m'_j),\ldots),
\end{aligned}
\]

一方 root を先に使うと

\[
\begin{aligned}
\operatorname{RfTerm}_{I^c(\vec A)}
  (C^c_i(\ldots,m_j,\ldots))
&\Rightarrow
C^s_i(\ldots,\operatorname{RfTerm}_{T_{ij}}(m_j),\ldots)\\
&\Rightarrow
C^s_i(\ldots,\operatorname{RfTerm}_{T_{ij}}(m'_j),\ldots).
\end{aligned}
\]

従って合流する。type parameter や annotation が複数の位置に複製される場合は、
proof.md 3.2 節の同期つき parallel development と同じ方法で共通 reduct へ合わせる。

### Rf-Ctor と Rf-Case

次の term を考える。

\[
\operatorname{case}^s
\bigl(
  \operatorname{RfTerm}_{I^c(\vec A)}(C^c_i(\vec m));
  \overrightarrow{\operatorname{RfTerm}(g)}
\bigr).
\]

Rf-Case を先に使う path は

\[
\operatorname{RfTerm}_B
\left(\operatorname{case}^c(C^c_i(\vec m);\vec g)\right)
\Rightarrow^*
\operatorname{RfTerm}_B(g_i@\vec m)
\]

へ進む。Rf-Ctor を先に使う path は Set case の reduction と Rf-App を使って

\[
\begin{aligned}
&\operatorname{case}^s
\left(C^s_i(\overrightarrow{\operatorname{RfTerm}(m)});
\overrightarrow{\operatorname{RfTerm}(g)}\right)\\
&\qquad\Rightarrow^*
\operatorname{RfTerm}_B(g_i@\vec m)
\end{aligned}
\]

となる。従ってこの peak も合流する。

Rf-Ind と parameter の compatible reduction、Case-C/Case-S/Ind-S と constructor argument の
compatible reduction も同様である。従って、有限な宣言ごとに complete development の
clause を生成すれば、proof.md の confluence proof を拡張できる見込みがある。

## 集合モデル

proof.md 2.1 節は

\[
D_{*^c}=U_0,
\qquad
D_{*^s_0}=U_0
\]

とし、2.5 節は well-typed な input に対して

\[
\operatorname{RfType}(A)=A,
\qquad
\operatorname{RfTerm}(A,m)=m
\]

と解釈する。再帰的 datatype に対しても、Compute 側と Set 側の carrier を同じ
集合に選べばこの定義を変える必要がない。

### 有限多項式関手

一つの datatype 宣言と parameter carrier の列 \(\vec A\) から、関手

\[
P_{\vec A}(X)
:=
\bigcup_{i<k}
\left(
  \{i\}\times
  \prod_{j<n_i}E_{ij}(X)
\right)
\]

を定める。field の意味は

\[
E_{ij}(X)
:=
\begin{cases}
A_\ell,&T_{ij}=A_\ell,\\
K,&T_{ij}=K,\\
X,&T_{ij}=I^c(\vec A)
\end{cases}
\]

である。tag \(i\) により異なる constructor の image は disjoint である。

次の鎖を作る。

\[
X_0:=\varnothing,
\qquad
X_{n+1}:=P_{\vec A}(X_n),
\qquad
\mu P_{\vec A}:=\bigcup_{n\in\omega}X_n.
\]

\(P_{\vec A}\) は有限多項式なのでこの \(\omega\)-chain の union を保存し、

\[
P_{\vec A}(\mu P_{\vec A})
=
\mu P_{\vec A}
\]

となる。これは constructor tag と有限個の field を持つ有限高さの木の集合であり、
\(P_{\vec A}\) の最小不動点である。

すべての parameter carrier と閉じた field carrier が \(U_0\) の要素ならば、
Grothendieck universe の finite product、finite sum、replacement、\(\omega\)-indexed union への閉包性から

\[
\mu P_{\vec A}\in U_0.
\]

従ってこの範囲の datatype のために、proof.md の universe tower より強い仮定は
必要ない。

### Type、constructor、case、induction の解釈

Compute 側と Set 側の型を同じ集合に解釈する。

\[
\begin{aligned}
\llbracket I^c(\vec A)\rrbracket
&:=\mu P_{\llbracket\vec A\rrbracket},\\
\llbracket I^s(\overrightarrow{\operatorname{RfType}(A)})\rrbracket
&:=\mu P_{\llbracket\vec A\rrbracket}.
\end{aligned}
\]

両方の constructor も同じ tagged tuple を返す。

\[
\llbracket C^c_i(\vec m)\rrbracket
=
\llbracket C^s_i(\overrightarrow{\operatorname{RfTerm}(m)})\rrbracket
:=
(i,\llbracket\vec m\rrbracket).
\]

case は tag を読み、対応する branch graph を field に適用する。malformed な input に対しては
proof.md の graph application と同じく既定値 \(0\) を返して \(W\)-valued な全域演算にする。
well-typed な input は必ずいずれかの tag と正しい field を持つため、この既定値分岐に入らない。

induction term の値は proof-irrelevant な \(\bullet\) とする。すべての
constructor branch の命題値が \(1\) なら、\(\mu P_{\vec A}\) の tree height に関する
well-founded induction により、すべての \(u\in\mu P_{\vec A}\) で \(Q(u)=1\) となる。
従って induction typing の membership law が成り立つ。Ind-S の両辺の項値はともに
\(\bullet\) なので reduction も意味を保存する。

この選び方で次の law が成り立つ。

\[
\begin{aligned}
\operatorname{RfType}(I^c(\vec A))
&=
I^s(\overrightarrow{\operatorname{RfType}(A)}),\\
\operatorname{RfTerm}
\left(I^c(\vec A),C^c_i(\vec m)\right)
&=
C^s_i(\overrightarrow{\operatorname{RfTerm}(m)}),\\
\operatorname{case}^s
\left(\operatorname{RfTerm}(m);\overrightarrow{\operatorname{RfTerm}(g)}\right)
&=
\operatorname{RfTerm}
\left(\operatorname{case}^c(m;\vec g)\right).
\end{aligned}
\tag{ind-rf-laws}
\]

第一式は Rf-Ind、第二式は Rf-Ctor、第三式は Rf-Case の意味保存である。
Compute 側と Set 側に別々の「同型だが等しくない」carrier を選ぶと、関数型の reflection には
順方向の map だけでなく逆方向も必要になる。同じ carrier と同じ functional graph を使うことが、
proof.md の恒等的な reflection を保つ要点である。

### run の解釈との組み合わせ

proof.md の Acc と run の解釈は、state carrier \(A\in U_0\)、result carrier
\(B\in U_0\)、および全関数

\[
F:A\to\operatorname{RunStep}(A,B)
\]

だけを使う。\(A\) または \(B\) が \(\mu P\) として作った再帰的 datatype の carrier で
あっても定義は変わらない。一段関数 \(f\) が datatype case を使う場合も、
モデル上では単なる functional graph \(F\) である。

従って

- state に list や tree を含める
- result として list や tree を返す
- 一段関数の中で constructor によるケース分析を行う
- 停止が証明された別の run を一段関数から使う
- RfTerm で返り値の constructor を Set 側から観察する

これらはすべて同じ well-founded recursion モデルで解釈できる。

さらに \(\operatorname{RunStep}(A,B)\) 自体が

\[
\operatorname{continue}:A\to\operatorname{RunStep}(A,B),
\qquad
\operatorname{finish}:B\to\operatorname{RunStep}(A,B)
\]

という非再帰的な二 constructor datatype である。一般の datatype 宣言からこの型と
constructor rule を生成できる。その場合も run と runCase はこの特定の datatype 名と
constructor 名を参照する specialized な項として残る。

## proof.md の soundness proof への追加

集合モデルの演算を与えるだけでは、proof.md 全体の定理にはならない。
同じ proof architecture を保つ場合、次を追加する必要がある。

### 構文的メタ理論

- datatype parameter、constructor field、case/induction の引数に対する renaming、weakening、substitution
- datatype 名と constructor 名の宣言環境内での一意性
- datatype formation、constructor typing、case/induction typing の generation lemma
- constructor tag の no-confusion と injectivity
- Case-C、Case-S、Ind-S、Rf-Ind、Rf-Ctor、Rf-Case の subject reduction
- 前節の peak を含む同期つき parallel development
- datatype の raw head を追加した sort/term-sort uniqueness

Compute datatype を作る rule の premise は Compute に、Set datatype を作る rule の premise は
Set に閉じている。Rf-Ind、Rf-Ctor、Rf-Case の向きも Compute から Set だけである。
従って 再帰6.md の sort separation は保たれ、Set の Take が Compute constructor field や
Compute run の引数に入る rule は生じない。

### 導出に沿う解釈

proof.md 5 節の解釈に次の clause を追加する。

- datatype formation は \(\mu P_{\vec A}\)
- constructor は tagged tuple
- Compute/Set case は tag に対応する branch graph の application
- Set induction は tree height に関する well-founded induction と proof value \(\bullet\)
- Rf-Ind、Rf-Ctor、Rf-Case は ind-rf-laws

declaration の signature が一意なので、同じ raw datatype term から異なる多項式関手を
回収することはない。異なる導出が与える parameter、field、branch の値は、
より低い rank の coherence で合わせる。datatype 演算はそれらの表示値にだけ依存するため、
proof.md 6 節の強い rank 帰納法に同じ形で追加できる。

Case-C/Case-S の reduction invariance は case の定義式、Ind-S は proof irrelevance と
induction の定義式、reflection の三規則は ind-rf-laws を使う。constructor membership と
case/induction elimination も有限多項式の定義から直接従う。
従って上の構文的補題を追加できれば、proof.md の Soundness と falseProp の意味計算は
そのまま保存される。

## 構造再帰と一般再帰

上の \(\operatorname{case}\) は一層のケース分析だけを行う。これでも run 用の一段関数は定義できる。
tail recursive でない traversal では、未処理の subtree と continuation stack を state datatype に含める
state-machine elaboration を使える。これは 再帰6.md と 補足.md の defunctionalization と同じである。

通常の構造再帰も primitive recursor または fold として生成できる。モデルでは
有限高さの tagged tree に対する整礎再帰として解釈でき、新しい集合論的仮定は必要ない。
Compute recursor の閉じた redex は RfTerm の payload congruence だけで Set 側からも計算できる。

一方、依存 motive を持つ一般の IndElim を Set 構文として外へ展開する reflection rule は、
motive、index、recursive hypothesis の Compute/Set binder を対応させる必要がある。
それは Rf-Ind/Rf-Ctor だけより大きな機構であり、再帰7.md で回避した synchronized context の問題が
再び現れる。最初の安定な範囲は非依存 case、および glued payload の内側で計算する
Compute recursor である。

## 適用範囲

| datatype | 集合モデル | reflection | 追加の論点 |
| --- | --- | --- | --- |
| 有限な非再帰 sum/product | finite tagged sum/product | Rf-Ind/Rf-Ctor | ほぼ RunStep と同じ |
| 有限正則再帰型 | 有限多項式の \(\mu P\) | 名前付き鏡像型へ写す | 上記のメタ理論の追加 |
| mutual な有限正則型 | \(U_0^n\) 上の同時最小不動点 | ペアの宣言列が必要 | generation/coherence を mutual にする |
| \(K\to I\) の形の無限分岐 strictly-positive field | W-type | 宣言に沿った鏡像 | transfinite な W-type 構成 |
| nested datatype | family の上の不動点 | parameter 変換を含む宣言 reflection | 単一の有限多項式より強い構成 |
| indexed family / GADT | indexed W-type に相当 | index と motive の reflection | 依存 elimination と coherence |
| negative recursion | 単調関手にならない | 定義できない | strict positivity で拒否 |

例えば

\[
D\simeq(D\to\mathbf 2)
\]

を許すと、集合の関手 \(X\mapsto 2^X\) は再帰変数に対して正でなく、
上の最小不動点構成を適用できない。さらに集合の同型として読むなら、
Cantor の定理から二要素集合への関数全体 \(2^D\) は \(D\) より真に大きく、
そのような carrier は与えられない。

## 結論

有限で非 indexed な正則 strictly-positive datatype に対しては、一般再帰と reflection は
うまく組み合わせられる。構成の中心は次の三点である。

1. Compute datatype 宣言と同時に、fresh な Set datatype 宣言を生成する。
2. RfType は再帰定義を unfold せず、ペアになった datatype 名へ簡約する。
3. RfTerm は constructor を一層ずつ Set constructor として露出し、recursive field は次の glued form として保持する。

proof.md のモデルでは、Compute 型とその Set 鏡像を同じ
\(\mu P\in U_0\) に解釈できる。これにより RfType / RfTerm の恒等解釈、
Acc の最小不動点解釈、run の整礎再帰解釈をそのまま組み合わせられる。
この範囲では新しい集合論的公理は要らない。

ただし、これでモデルの方針が与えられたことと、拡張後の proof.md の
soundness が完全に証明されたことは区別が必要である。完全な証明には、datatype 宣言の
well-formedness、追加 reduction の confluence/subject reduction、および導出に沿う解釈の
coherence を上の補題に沿って追加する必要がある。
