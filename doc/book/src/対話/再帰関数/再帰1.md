# 停止性の証明を用いた再帰の定式化

まず無矛盾性を検討するための最小体系としてなら、かなり正確に定式化できます。

以下では `system.md` の Set/Prop calculus をそのまま \(D\) と呼び、その外側に「停止性が証明された遷移系を実行する computation judgement」を追加します。重要なのは、最初の定式化では `quote` を object term にせず、一段遷移関数を最初から \(D\) 側に置くことです。

この範囲なら、`system.md` に手を入れず、拡張の構文・簡約・judgement をすべて列挙できます。

## 1. 前提とする通常の帰納型

`system.md` に将来追加される通常の strictly positive inductive type として、次を仮定します。

| category | definition |
| --- | --- |
| natural number type | \(\mathbb{N} : *^s_0\) |
| zero | \(0 : \mathbb{N}\) |
| successor | \(S : \mathbb{N} \to \mathbb{N}\) |
| sum type | \(A + B : *^s_{\max(i,j)}\) |
| left injection | \(\operatorname{left} : A \to A+B\) |
| right injection | \(\operatorname{right} : B \to A+B\) |

積 \(A \times B\) とその射影も同様です。これらは non-structural recursion 固有の primitive ではなく、通常の帰納型ライブラリの項とみなします。

## 2. 一段遷移と有限反復

以下を \(D\) 内の構造再帰関数として定義します。

\[
\begin{aligned}
\operatorname{advance}_{A,B}
  &:\left(A \to A+B\right) \to \left(A+B\right) \to \left(A+B\right), \\
\operatorname{advance}\ f\ (\operatorname{left}\ a)
  &:= f\,a, \\
\operatorname{advance}\ f\ (\operatorname{right}\ b)
  &:= \operatorname{right}\ b.
\end{aligned}
\]

次に、

\[
\operatorname{iter}_{A,B}
  : \mathbb{N} \to \left(A \to A+B\right) \to \left(A+B\right) \to \left(A+B\right)
\]

を次のように定義します。

\[
\begin{aligned}
\operatorname{iter}\ 0\ f\ q
  &:= q, \\
\operatorname{iter}\ (S\,n)\ f\ q
  &:= \operatorname{advance}\ f\left(\operatorname{iter}\ n\ f\ q\right).
\end{aligned}
\]

これは \(\mathbb{N}\) に関する通常の構造再帰です。\(\operatorname{right}\ b\) に到達した後は、その後もずっと \(\operatorname{right}\ b\) のままです。

## 3. 停止性命題

次の judgement を仮定します。

\[
\Gamma \vdash A : *^s_i,
\qquad
\Gamma \vdash B : *^s_j,
\]

\[
\Gamma \vdash f : A \to A+B : *^s_k,
\qquad
\Gamma \vdash a : A : *^s_i.
\]

このとき、停止 witness の型を次のように定義します。

\[
\begin{aligned}
\operatorname{HaltWitness}_{A,B}(f,a)
:=
\bigl\{z : \mathbb{N} \times B \mathrel{\big|} {}&
  \operatorname{iter}\ (\operatorname{fst}\ z)\ f\ (\operatorname{left}\ a) \\
  &={}_{A+B} \operatorname{right}(\operatorname{snd}\ z)
\bigr\}.
\end{aligned}
\]

停止性命題は、`system.md` にある non-emptiness を用いて次のように定義します。

\[
\operatorname{Halts}_{A,B}(f,a)
:=
\exists \operatorname{HaltWitness}_{A,B}(f,a).
\]

したがって、\(\operatorname{Halts}\) は新しい term constructor ではなく、単なる略記です。`End` と `Step` も不要です。有限回の遷移列は、自然数 \(n\) と \(\operatorname{iter}\) が表現します。

### 停止性に関する補題

上の定義から、次の命題を \(D\) 内で証明できます。

| case | assumption | conclusion |
| --- | --- | --- |
| End | \(f\,a =_{A+B} \operatorname{right}\ b\) | \(\operatorname{Halts}(f,a)\) |
| Step | \(f\,a =_{A+B} \operatorname{left}\ a'\) | \(\operatorname{Halts}(f,a) \leftrightarrow \operatorname{Halts}(f,a')\) |

Step の補題は `run` の subject reduction に使います。

## 4. Computation term

Set/Prop term とは別に、computation term を追加します。

| category | syntax |
| --- | --- |
| pure value | \(\operatorname{return}(t)\) |
| variable | \(x\) |
| lambda abstraction | \(\lambda^c x:A.e\) |
| application | \(e \mathbin{@^c} t\) |
| execution | \(\operatorname{run}_{A,B}(f,a)\) |

ここで、次のように区別します。

| metavariable | meaning |
| --- | --- |
| \(t,A,B,f,a\) | \(D\) の項 |
| \(e\) | computation term |

Computation term は \(D\) の型や命題の中には出現しません。

Computation typing judgement は次の形です。

\[
\Gamma \vdash_c e : A.
\]

これは「computation \(e\) を実行すると、\(D\) の型 \(A\) の値を返す」という意味です。新しい \(\operatorname{comp}(A)\) という object-level type constructor は導入しません。Comp であることは judgement の添字 \(\vdash_c\) が表します。

## 5. Computation typing rules

| category | conclusion | premises |
| --- | --- | --- |
| pure value | \(\Gamma \vdash_c \operatorname{return}(t) : A\) | \(\Gamma \vdash t : A : *^s_i\) |
| computation variable | \(\Gamma,x:A:*^s_i \vdash_c x : A\) | \(\operatorname{WF}(\Gamma,x:A:*^s_i)\) |
| lambda | \(\Gamma \vdash_c (\lambda^c x:A.e) : \Pi x:A.B\) | \(\Gamma \vdash A:*^s_i\)<br>\(\Gamma,x:A:*^s_i \vdash_c e:B\)<br>\(\Gamma,x:A:*^s_i \vdash B:*^s_j\) |
| application | \(\Gamma \vdash_c e \mathbin{@^c} t : B[x:=t]\) | \(\Gamma \vdash_c e:\Pi x:A.B\)<br>\(\Gamma \vdash t:A:*^s_i\) |
| run | \(\Gamma \vdash_c \operatorname{run}_{A,B}(f,a):B\) | \(\Gamma \vdash A:*^s_i\)<br>\(\Gamma \vdash B:*^s_j\)<br>\(\Gamma \vdash f:A\to A+B:*^s_k\)<br>\(\Gamma \vdash a:A:*^s_i\)<br>\(\Gamma \vDash \operatorname{Halts}_{A,B}(f,a)\) |

必要なら computation context \(\Delta\) を追加できますが、最小体系では computation lambda の変数を \(D\) の値変数とします。Computation variable \(x\) は、暗黙に \(\operatorname{return}(x)\) と同じです。Application の引数は description 側の値に制限します。

停止証明は `run` の引数に含めず、typing derivation の premise に置いています。これは `system.md` の `Proof` や `Take` と同じスタイルです。証明を構文に明示したければ、

\[
\operatorname{run}(f,a,p)
\]

としても本質は変わりません。

## 6. Computation reduction

\(D\) の reflexive-transitive reduction を \(\to_D^*\) とします。Computation reduction \(\to_c\) は次の規則と、それらの compatible closure によって生成します。

| category | reduction | condition |
| --- | --- | --- |
| computation \(\beta\) | \((\lambda^c x:A.e) \mathbin{@^c} t \to_c e[x:=t]\) | なし |
| Run-End | \(\operatorname{run}_{A,B}(f,a) \to_c \operatorname{return}(b)\) | \(f\,a \to_D^* \operatorname{right}\ b\) |
| Run-Step | \(\operatorname{run}_{A,B}(f,a) \to_c \operatorname{run}_{A,B}(f,a')\) | \(f\,a \to_D^* \operatorname{left}\ a'\) |

compatible closure には、例えば次の規則が含まれます。

\[
\dfrac{e \to_c e'}
      {e \mathbin{@^c} t \to_c e' \mathbin{@^c} t}.
\]

\(f\) と \(a\) は \(D\) の項なので、その内部の簡約は \(\to_D\) で扱います。

## 7. Subject reduction

示すべき定理は次のとおりです。

\[
\Gamma \vdash_c e:A,
\qquad
e \to_c e'
\qquad\Longrightarrow\qquad
\Gamma \vdash_c e':A.
\]

Run-Step の場合だけ少し仕事が必要です。仮定から、

\[
\Gamma \vDash \operatorname{Halts}(f,a)
\]

および

\[
f\,a \to_D^* \operatorname{left}\ a'
\]

が得られます。\(D\) の conversion と先ほどの停止性補題から、

\[
\Gamma \vDash \operatorname{Halts}(f,a')
\]

を導けます。したがって、

\[
\Gamma \vdash_c \operatorname{run}(f,a'):B
\]

です。

Run-End の場合は、

\[
f\,a \to_D^* \operatorname{right}\ b
\]

から \(b:B\) が得られ、

\[
\Gamma \vdash_c \operatorname{return}(b):B
\]

となります。

## 8. 無矛盾性との関係

この最小拡張には、computation judgement から既存の typing/provability judgement へ戻る規則がありません。つまり、次のような規則は追加しません。

| excluded rule | rule schema |
| --- | --- |
| computation-to-Set | \(\dfrac{\Gamma \vdash_c e:A}{\Gamma \vdash e:A:*^s}\) |
| computation-to-Prop | \(\dfrac{\Gamma \vdash_c e:P}{\Gamma \vDash P}\) |

したがって、既存の命題 \(P\) について

\[
\Gamma \vDash_{\mathrm{extended}} P
\]

という derivation があれば、その derivation には computation rule が現れません。よって、そのまま

\[
\Gamma \vDash_D P
\]

の derivation です。

したがって、この段階の拡張は provability に関して \(D\) の保守拡張です。特に \(D\) が無矛盾なら、この拡張も同じ意味で無矛盾です。

これは `run` の停止性定義そのものを詳しく解析しなくても成り立ちます。`run` が論理側の inhabitant を新しく作らないからです。

## 9. `Take` による description 側の値

計算結果を description 側でも参照したい場合は、新しい reflection 規則を追加するのではなく、既存の `Take` を使えます。

\[
X_{f,a} := \operatorname{HaltWitness}(f,a)
\]

とし、

\[
g:X_{f,a}\to B,
\qquad
g(z):=\operatorname{snd}\ z
\]

とします。遷移が決定的なので、

\[
z_1:X_{f,a},
\quad
z_2:X_{f,a}
\quad\Longrightarrow\quad
g(z_1)=_B g(z_2)
\]

を証明できます。すると既存の規則から、

\[
\operatorname{Take}(X_{f,a},B,g):B
\]

が得られます。これを次のように略記できます。

\[
\operatorname{denote}(f,a)
:=
\operatorname{Take}(X_{f,a},B,g).
\]

したがって、次の対応が得られます。

| layer | term |
| --- | --- |
| computation | \(\operatorname{run}(f,a)\) |
| description | \(\operatorname{denote}(f,a)\) |

新しい「Comp から Set への reflection rule」はまだ必要ありません。

## 10. 必要な項の整理

この定式化では、質問にあった項は次のようになります。

| name | treatment |
| --- | --- |
| `Left`, `Right` | 通常の sum 型の constructor |
| `terminates` | `Halts` という定義上の略記 |
| `End`, `Step` | 不要 |
| `quote` | 不要 |
| `comp` | 別 judgement \(\vdash_c\) に吸収 |
| `run` | 唯一の recursion 固有 computation term |

`return` と computation lambda/application は、computation language を独立した言語として書くための一般的な構文です。Non-structural recursion 固有の追加は、実質的に `run` だけです。

## 11. この定式化が表せる範囲

直接には、

\[
f:A\to A+B
\]

という tail-recursive な状態遷移を扱います。

Nested recursion や一般の call-by-value プログラムは、状態 \(A\) を

\[
A
=
\text{local variables}
\times
\text{continuation stack}
\]

のような configuration にすることで表現します。その変換自体は、当面 meta-level の elaboration として扱えます。

最初から「任意の Comp 項を `quote` して、その構文や実行について論じる」ところまで入れると、コード表現・substitution・environment・評価関係まで一度に定義する必要があります。無矛盾性を調べる最初の calculus としては、上の「一段遷移を \(D\) の全関数として与える」版が最も小さく、しかも完全に形式化しやすいと思います。
