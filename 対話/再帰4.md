# Set 上の accessibility による一般再帰

## 0. 結論

これまでの案では、一般再帰を Compute 側の `run` として定義し、その結果を `Rf` で Set 側へ移していた。しかし、この構成では次の二つを同時に満たそうとするたびに、`pure Compute term` の制限と `Rf(run(-,-))` の簡約を特別扱いする必要があった。

1. 停止が証明された一般再帰関数を、後から定義する一般再帰関数の一段遷移の中で使う。
2. 一般再帰関数の結果を Set 項として使う。

ここでは Compute sort を追加せず、停止性を typing premise に持つ `run` を直接 Set 項として追加する。

一般再帰に固有な追加構文は次の `run` 一つだけである。

\[
\operatorname{run}_{A,B}(f,a)
\]

`run` の一段遷移 `f` は、`run` を含まない pure 項に制限しない。したがって、すでに typing 済みの `run` を `f` の本体に書ける。

`Acc` と sum 型は `run` だけのための機構ではなく、通常の帰納型として使う。ただし、`system.md` には帰納型がまだ完全に定式化されていないため、ここでは `run` に必要な部分の rule も明記する。

## 1. 基本方針

この拡張では次のものを追加しない。

- Compute sort $*^c$
- reflection `Rf`
- `Take` を経由した計算結果の取り出し
- computation 専用の typing judgement
- computation 専用の reduction
- fuel としての $\mathbb{N}$
- `Terminate` とその `End`, `Step`

`system.md` の judgement

\[
\operatorname{WF}(\Gamma),
\qquad
\Gamma\vdash t:s,
\qquad
\Gamma\vdash t:T:s,
\qquad
\Gamma\vDash P
\]

はそのまま使う。簡約も Set/Prop 項と `run` に共通の一つの関係 $\to$ だけを使う。

`run` は「停止証明から Set の値を作る」が、Prop から証明項を返す演算ではない。結果の sort は必ず $*^s_j$ とし、$*^p$ を結果にする `run` は追加しない。

## 2. Sum 型

$A:*^s_i$ と $B:*^s_j$ に対し、sum 型とその constructor を項の構文に含める。`left` と `right` は代数的データ型の存在を仮定しただけでは消えない。少なくとも次の項と derivation が必要である。

| category | conclusion | premises |
| --- | --- | --- |
| sum form | $\Gamma\vdash A+B:*^s_{\max(i,j)}$ | $\Gamma\vdash A:*^s_i$<br>$\Gamma\vdash B:*^s_j$ |
| left intro | $\Gamma\vdash \operatorname{left}_{A,B}(a):A+B:*^s_{\max(i,j)}$ | $\Gamma\vdash a:A:*^s_i$<br>$\Gamma\vdash B:*^s_j$ |
| right intro | $\Gamma\vdash \operatorname{right}_{A,B}(b):A+B:*^s_{\max(i,j)}$ | $\Gamma\vdash A:*^s_i$<br>$\Gamma\vdash b:B:*^s_j$ |

非依存な eliminator は、例えば次の型を持つ。

\[
\operatorname{case}_{A,B,C}
:
(A+B)\to(A\to C)\to(B\to C)\to C.
\]

その簡約は次のとおりである。

\[
\begin{aligned}
\operatorname{case}(\operatorname{left}(a),l,r)&\to l@a,\\
\operatorname{case}(\operatorname{right}(b),l,r)&\to r@b.
\end{aligned}
\]

一般の帰納型宣言からこれらの rule が生成されるときは、sum 型を別の primitive とする必要はない。その場合でも、`left` と `right` 自体は生成された constructor 項であり、raw syntax 上に存在する。

## 3. Accessibility

### 3.1 Formation と introduction

$A:*^s_i$ 上の関係を

\[
R:(y:A)\to(x:A)\to *^p
\]

とする。次の帰納的な命題を用いる。

\[
\operatorname{Acc}_A(R,a):*^p.
\]

formation rule は次である。

\[
\dfrac{
  \Gamma\vdash A:*^s_i
  \qquad
  \Gamma\vdash R:(y:A)\to(x:A)\to *^p:\square^p
  \qquad
  \Gamma\vdash a:A:*^s_i
}{
  \Gamma\vdash\operatorname{Acc}_A(R,a):*^p
}.
\tag{Acc-Form}
\]

constructor `acc` は次の型を持つ。

\[
\operatorname{acc}_{A,R,a}
:
\left(
  (y:A)\to
  R@y@a\to
  \operatorname{Acc}_A(R,y)
\right)
\to
\operatorname{Acc}_A(R,a).
\tag{acc}
\]

これは「$a$ より一段小さいすべての $y$ が accessible なら、$a$ も accessible である」と述べる。

### 3.2 Prop 内への elimination

`run` の subject reduction には次の descent lemma が必要である。

\[
\Gamma\vDash\operatorname{Acc}_A(R,a),
\qquad
\Gamma\vDash R@y@a
\quad\Longrightarrow\quad
\Gamma\vDash\operatorname{Acc}_A(R,y).
\tag{Acc-Descent}
\]

これは `Acc` の追加公理ではなく、帰納型の Prop 内への eliminator から得られる。導出を直接書くなら、`system.md` の `proof term` rule で

\[
p:=\Proof\operatorname{Acc}_A(R,a)
\]

を得て、$p$ を `acc(h)` として Prop 内で分解し、$h@y@(\Proof(R@y@a))$ を作ればよい。

帰納型の一般的な eliminator をまだ仮定しないなら、同じ操作を次の destructor と計算規則として明記できる。

\[
\operatorname{outAcc}(p,y,q):\operatorname{Acc}_A(R,y),
\]

\[
\operatorname{outAcc}(\operatorname{acc}(h),y,q)
\to h@y@q.
\]

`Acc` は計算結果の Set を直接作るために elimination しない。`Acc-Descent` は Prop 内の elimination だけで導出できる。Set の結果を作る機構は、次に追加する、停止証明を typing premise に持つ `run` に限定する。

## 4. 一段遷移と停止性

次を仮定する。

\[
\Gamma\vdash A:*^s_i,
\qquad
\Gamma\vdash B:*^s_j,
\]

\[
\Gamma\vdash f:A\to A+B:*^s_k,
\qquad
\Gamma\vdash a:A:*^s_i.
\]

$f$ が一段で $x$ から $y$ へ遷移することを表す Set 側の関係を次で定義する。

\[
\begin{aligned}
R_f&:(y:A)\to(x:A)\to *^p,\\
R_f@y@x
&:=
f@x
=_{A+B}
\operatorname{left}_{A,B}(y).
\end{aligned}
\]

停止性は新しい項を追加せず、次の略記とする。

\[
\operatorname{Terminates}_{A,B}(f,a)
\;:=\;
\operatorname{Acc}_A(R_f,a).
\]

$f@x$ が `left(y)` を返した場合だけ $y$ が $x$ の predecessor になる。`right(b)` を返す状態に predecessor はない。したがって、決定的な全関数 $f:A\to A+B$ に対する $\operatorname{Acc}(R_f,a)$ は、$a$ から `left` を返し続ける無限列がないことを表す。

## 5. `run`

### 5.1 構文

Set 項に次を追加する。

\[
t::=\cdots\mid\operatorname{run}_{A,B}(f,a).
\]

$f$ と $a$ は任意の Set 項である。特に、

- `run` を含んでよい。
- value でなくてよい。
- 閉項でなくてよい。

とする。

ただし、`run` を含む $f$ が typing されるためには、その内側の各 `run` の停止性 premise がすでに導出されていなければならない。これが「停止が証明された他の一般再帰関数を使ってよい」という順序を typing derivation 上で表す。

### 5.2 Typing

`run` に対し、次の rule を追加する。

\[
\dfrac{
\begin{array}{c}
\Gamma\vdash A:*^s_i
\qquad
\Gamma\vdash B:*^s_j
\\[2pt]
\Gamma\vdash f:A\to A+B:*^s_k
\qquad
\Gamma\vdash a:A:*^s_i
\\[2pt]
\Gamma\vDash\operatorname{Acc}_A(R_f,a)
\end{array}
}{
\Gamma\vdash
\operatorname{run}_{A,B}(f,a)
:B:*^s_j
}.
\tag{Run}
\]

停止証明は `run(f,a,p)` のように raw term の引数に含めない。これは `system.md` の `subset intro` や `Take` と同じく、provability を derivation の premise として使う形である。

ただし、`Take` と異なり `run` の結果には計算規則がある。停止証明は実行時に消去され、計算結果は $f$ の遷移だけで決まる。

### 5.3 Reduction

全項に共通の簡約関係 $\to$ に次の root rule を追加する。

| category | reduction | condition |
| --- | --- | --- |
| Run-End | $\operatorname{run}_{A,B}(f,a)\to b$ | $f@a\to^*\operatorname{right}_{A,B}(b)$ |
| Run-Step | $\operatorname{run}_{A,B}(f,a)\to\operatorname{run}_{A,B}(f,a')$ | $f@a\to^*\operatorname{left}_{A,B}(a')$ |

条件に現れる $\to^*$ も同じ簡約関係の反射推移閉包である。$f$ の内部にすでに typing 済みの `run` があれば、その簡約も一段遷移の計算の一部になる。

この条件は現在の外側の `run(f,a)` 自身を簡約するために使ってはならない。しかし、$f@a$ は外側の redex の真の部分項ではなく、通常の非再帰的な定義の環境では外側の redex 自身を含まない。大域的な定義も宣言順に限定し、未定義の名前や定義中の自分自身を参照する展開規則は追加しない。自分自身の繰り返しは `left(a')` と Run-Step だけが表す。

`run` の引数の内部での compatible reduction も認める。例えば $f\to f'$ なら

\[
\operatorname{run}(f,a)\to\operatorname{run}(f',a)
\]

である。$f\equiv f'$ なら $R_f\equiv R_{f'}$ なので、この congruence の前後で停止性 premise は conversion によって保存される。状態 $a$ の内部を簡約する場合も同様である。

### 5.4 Definitional equality

`run` を Set 側で計算結果として使うため、Run-End/Run-Step を単な実行関係にはしない。この二つを含む共通簡約の対称・反射・推移閉包を $\equiv^{\beta\operatorname{run}}$ と書き、`system.md` の conversion rule で使われている $\equiv^\beta$ をこれに拡張する。

これにより、例えば閉じた計算が $b$ を返すなら、

\[
\operatorname{run}(f,a)\equiv^{\beta\operatorname{run}}b
\]

を type conversion や等式の証明に使える。

## 6. Subject reduction

追加した規則に対して示すべき命題は次である。

\[
\Gamma\vdash t:T:s,
\qquad
t\to t'
\quad\Longrightarrow\quad
\Gamma\vdash t':T:s.
\]

### 6.1 Run-End

typing premise から

\[
\Gamma\vdash f@a:A+B:*^s_{\max(i,j)}
\]

である。$f@a\to^*\operatorname{right}(b)$ と既存部分の subject reduction、sum introduction の inversion から

\[
\Gamma\vdash b:B:*^s_j
\]

を得る。よって Run-End は型を保存する。

### 6.2 Run-Step

$f@a\to^*\operatorname{left}(a')$ なら、同様に

\[
\Gamma\vdash a':A:*^s_i
\]

を得る。また、conversion と equality introduction から

\[
\Gamma\vDash
f@a=_{A+B}\operatorname{left}(a')
\]

である。これは定義により $\Gamma\vDash R_f@a'@a$ である。Run rule の premise と `Acc-Descent` から

\[
\Gamma\vDash\operatorname{Acc}_A(R_f,a')
\]

を得るため、もう一度 Run rule を使って

\[
\Gamma\vdash\operatorname{run}_{A,B}(f,a'):B:*^s_j
\]

を導出できる。

## 7. 停止性

### 7.1 閉項に対する `run` の停止

基礎の Set/Prop calculus が strong normalization と sum 型の canonicity を満たすと仮定する。このとき、空 context で typing された

\[
\operatorname{run}_{A,B}(f,a)
\]

は有限回の Run-Step の後に Run-End する。

証明の中心は $\operatorname{Acc}_A(R_f,a)$ に関する well-founded induction である。

1. $f@a$ を sum 型の canonical form まで簡約する。
2. `right(b)` なら Run-End する。
3. `left(a')` なら $R_f@a'@a$ が成り立つ。
4. `Acc-Descent` で $\operatorname{Acc}_A(R_f,a')$ を得て、well-founded induction の仮定を $a'$ に使う。

### 7.2 内側の `run` がある場合

$f$ に他の `run` を認めると、上の 1 で $f@a$ 自体が停止することも示す必要がある。ここで pure 制限の代わりに typing derivation の整礎性を使う。

typing derivation $D$ の run depth $d(D)$ を次のように定める。

- Run rule 以外では premise の run depth の最大値。
- Run rule では、停止性証明を含むすべての proper premise の run depth の最大値に $1$ を加えた値。

そして、

1. run depth に関する帰納法と、
2. 現在の `run` の $\operatorname{Acc}$ 導出に関する well-founded induction

を組み合わせる。現在の Run rule の premise にある $f$ と $a$ の typing derivation は、結論の `run(f,a)` より小さい run depth を持つ。よって $f@a$ の計算に必要な既存 `run` は外側の帰納法の仮定で停止する。現在の `run` 自身の Run-Step の列は内側の $\operatorname{Acc}$ 帰納で停止する。

大域的な定義名を使う場合は、透明な定義の typing derivation も参照側の derivation の proper premise とみなす。同値な言い方として、宣言順に各定義の run depth を記録し、定義名の参照にその depth を与えてもよい。これにより、定義名 $g$ を経由した既存 `run` も、後で定義する `run` より小さいことが保たれる。

完全な strong-normalization proof では substitution と $\beta$-reduction による複製も扱うため reducibility argument が必要になるが、整礎性の順序は上の二重帰納で与えられる。

### 7.3 仮定を含む context

次のように停止性を context で仮定した場合、

\[
\Gamma,p:\operatorname{Acc}_A(R_f,a):*^p
\vdash
\operatorname{run}(f,a):B:*^s_j,
\]

その context が実際に inhabit されなければ raw reduction が停止するとは限らない。これは `fixpoint.md` にある「context に false が入った場合の停止性は一旦要求しない」という方針と同じである。

要求する定理は次のどちらかである。

- 空 context の well-typed term は停止する。
- より一般に、意味論的に inhabit された context の well-typed term は停止する。

## 8. 一般再帰関数の定義

入力型を $X$ 、内部状態を $A$ 、結果型を $B$ とする。

\[
\begin{aligned}
\operatorname{init}&:X\to A,\\
\operatorname{step}&:A\to A+B.
\end{aligned}
\]

次の停止定理を別に証明する。

\[
\Gamma\vDash
(x:X)\to
\operatorname{Acc}_A
(R_{\operatorname{step}},\operatorname{init}@x).
\tag{total}
\]

このとき、一般再帰関数を通常の Set 関数として次のように定義できる。

\[
g
:=
\lambda x:X.
\operatorname{run}_{A,B}
(\operatorname{step},\operatorname{init}@x)
:
X\to B.
\]

関数の本体に停止証明は現れない。証明 `(total)` は $g$ の typing derivation にだけ使われる。

### 8.1 他の一般再帰関数の利用

すでに次が定義・typing されているとする。

\[
g:X\to Y
:=
\lambda x:X.\operatorname{run}(\operatorname{step}_g,
                                  \operatorname{init}_g@x).
\]

後から定義する関数 $h:U\to V$ の一段遷移は、例えば次の形でよい。

\[
\begin{aligned}
\operatorname{step}_h
&:C\to C+V,\\
\operatorname{step}_h@c
&:=
\operatorname{let}\ y:=g@(u@c)\ \operatorname{in}\
M(c,y).
\end{aligned}
\]

$g@(u@c)$ は展開すると `run(step_g,init_g(u(c)))` である。しかし `step_h` の引数に pure 制限はないので、これは正しい Set 項である。`step_h` の typing derivation には $g$ の Run rule が部分導出として現れ、$h$ の Run rule より厳密に内側にある。

これにより、最後の要求

> 一般再帰関数は、すでに停止性が証明された他の一般再帰関数を利用できる。

が構文上ではなく typing derivation の有限性によって表現される。

同時再帰のように、まだ typing されていない関数同士を相互に呼ぶことはこの rule から直接には得られない。その場合は呼び出し側を tagged sum にした一つの状態遷移にまとめ、停止性をまとめて証明する。

### 8.2 Set 側での利用

$g$ は最初から

\[
\Gamma\vdash g:X\to B:*^s_k
\]

である。したがって、

- Set 関数の引数に渡す。
- refinement の述語の中で $g@x$ を使う。
- equality $g@x=b$ を述べる。
- PTS の product rule が許す範囲で、$g@x$ を含む型を作る。
- 閉じた入力なら definitional reduction で結果まで計算する。

これらのために `Rf(g)` や `Take` を作る必要はない。

## 9. 例: Euclidean algorithm

二つの自然数の状態を $A:=\mathbb{N}\times\mathbb{N}$ 、結果を $B:=\mathbb{N}$ とする。一段遷移を次のように定義する。

\[
\operatorname{eucStep}(n,m)
:=
\begin{cases}
\operatorname{right}(n),&m=0,\\
\operatorname{left}(m,n\bmod m),&m\ne0.
\end{cases}
\]

$m\ne0$ の分岐で $n\bmod m<m$ であることから、第二成分の大きさを measure にして次を証明する。

\[
(n:\mathbb N)\to(m:\mathbb N)\to
\operatorname{Acc}_{\mathbb N\times\mathbb N}
(R_{\operatorname{eucStep}},(n,m)).
\]

その後で、

\[
\operatorname{gcd}
:=
\lambda n:\mathbb N.
\lambda m:\mathbb N.
\operatorname{run}_{\mathbb N\times\mathbb N,\mathbb N}
(\operatorname{eucStep},(n,m))
:
\mathbb N\to\mathbb N\to\mathbb N
\]

と定義する。`gcd` は Set 関数なので、その後の別の一段遷移の中でも通常の項として呼び出せる。

## 10. Tail recursion 以外

primitive `run` が直接に実行するのは次の状態機械である。

\[
f:A\to A+B.
\]

これは表面構文としては tail recursion である。しかし、nested recursion や非 tail recursion は、局所変数と continuation stack を状態 $A$ に含めることで表現できる。

\[
A
=
\text{control state}
\times
\text{local variables}
\times
\text{continuation stack}.
\]

McCarthy 91 のような nested call では、内側の呼び出しの結果を待つ continuation を stack に積む。rose tree map のような higher-order/nested traversal では、未処理の subtree と再構成用の continuation を状態に持たせる。この state-machine 化はまず elaboration として扱い、core calculus に別の再帰項を追加しない。

## 11. 意味論と無矛盾性

Set/Prop 側のモデルと、そのモデル上の sum 型と `Acc` が与えられているとする。Run rule の derivation に含まれる

\[
p:\operatorname{Acc}_A(R_f,a)
\]

によって $R_f$ が $a$ の下で well-founded であることを得て、`run` をメタ理論上で次の well-founded recursion として解釈する。

\[
\operatorname{wfRun}(f,a,p)
:=
\begin{cases}
b,&f@a=\operatorname{right}(b),\\
\operatorname{wfRun}(f,a',p'),
  &f@a=\operatorname{left}(a'),
\end{cases}
\]

ただし $p'$ は $p$ と $R_f@a'@a$ に `Acc-Descent` を使って得られる。証明項を保持するメタ理論では、これを $p$ の accessibility derivation に関する構造再帰として構成できる。Prop を proof-irrelevant に解釈するモデルでは $p$ 自体を再帰引数にせず、$\operatorname{Acc}(R_f,a)$ が表す well-foundedness に対するメタ理論上の well-founded recursion として同じ関数を定義する。

$f$ は決定的な関数なので、異なる accessibility proof を使っても到達する `right(b)` は同じである。したがって、項上で停止証明を消去した `run(f,a)` の解釈は typing derivation の選び方に依存しない。

この解釈により、Run rule は「証明があるという理由だけで任意の Set の元を作る」規則ではなく、実際に $f$ が到達する $B$ の元を作る規則であることがわかる。基礎の Set/Prop calculus のモデルからこの解釈を構成できれば、拡張後の体系の無矛盾性を基礎体系の無矛盾性に相対化できる。

## 12. Confluence に必要な条件

Run-End と Run-Step の条件が同時に成り立たないことには、次が必要である。

- 基礎の reduction が confluent である。
- sum 型の `left` と `right` が異なる canonical form である。
- 内側の、より小さい run depth の `run` の簡約が confluent である。

これらを run depth に関する帰納法で使えば、well-typed な $f@a$ が `left(a')` と `right(b)` の両方へ簡約することはない。`run` の引数内部を先に簡約する場合と root の Run rule を先に使う場合の critical pair も、$f@a$ の一意な canonical form で合流する。

ここで run depth は typing derivation に対して定義したので、直接得られるのは well-typed term 上の confluence である。すべての raw term 上の confluence も必要なら、定義名の非再帰性と `run` の構文的な nesting depth を使った別の証明が必要である。

## 13. `system.md` に追加するもの

この案を `system.md` に取り込むときの差分は次のとおりである。

### Term

- sum type $A+B$
- constructor $\operatorname{left}_{A,B}(a)$
- constructor $\operatorname{right}_{A,B}(b)$
- sum eliminator $\operatorname{case}$
- accessibility proposition $\operatorname{Acc}_A(R,a)$
- accessibility constructor `acc` と Prop 内の eliminator
- execution $\operatorname{run}_{A,B}(f,a)$

### Derivation

- sum 型の formation/introduction/elimination rule
- `Acc` の formation/introduction/Prop-elimination rule
- `(Run)`

### Reduction

- sum eliminator の二つの computation rule
- `Acc` eliminator の computation rule
- Run-End
- Run-Step
- 上記を含む共通 reduction による definitional equality

### 必要なメタ定理

- sum と `Acc` を含む subject reduction
- `Acc-Descent`
- Run-End/Run-Step の subject reduction
- run depth と accessibility による閉項の停止性
- run depth に関する帰納法を用いた well-typed term 上の confluence
- accessibility proof に依存しない `wfRun` のモデル解釈

## 14. 要求との対応

| requirement | realization |
| --- | --- |
| 他の停止証明済み一般再帰を使う | `f` と `a` の pure 制限をなくし、内側の `run` を通常の Set 部分項として認める |
| 定義した一般再帰を Set 側で使う | `run` 自体の結論を $B:*^s_j$ にし、`Rf` や `Take` を経由しない |
| 停止証明を関数本体から分ける | `Acc(R_f,a)` を `(Run)` の derivation premise に置き、raw term には含めない |
| 一つの reduction を使う | Run-End/Run-Step を Set/Prop と共通の $\to$ に追加する |
| `system.md` に追加できる形にする | 追加構文、derivation、reduction、必要なメタ定理を分けて列挙した |

この定式化で重要な制限は「一段遷移が pure であること」ではない。重要なのは、

1. 内側で使う各 `run` が、現在の Run rule より小さい typing derivation を持つことと、
2. 現在の `run` の Run-Step が $\operatorname{Acc}(R_f,a)$ に沿って厳密に降下すること

の二つである。
