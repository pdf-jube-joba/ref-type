## 再検査の内訳と照合

main の編集時は結果キャッシュに187件ヒットしても、証明環境を復元できず17,277ステップを実行した。
全パッケージの426件の prefix は編集前のパッケージ入力キーにのみ登録され、編集済みの末端自身も含んでいた。
取得候補に残った依存 prefix は331件中147件、398件中163件しか要求に重ならず、いずれも既存の候補選択条件から外れた。
実行は複数パッケージ用の native checker で、モジュール単位のチェックポイント復元には進まなかった。

変更版が追加保存するのは、単一のローカルパッケージで選択順の末尾にある独立した外部ファイルの直前の環境である。
復元時にはそのファイル以外の全入力、ヘッダー、解決済みの構文、検証済みの範囲と証明環境を照合し、条件が合わなければ従来の検査に戻る。
この計測では末端の本体を未解決のまま保存し、編集後の構文に差し替えて16ステップを実行した。
現在の依存閉包の187件がすべて検証済みであることを確認してから環境を復元した。
編集時のワーカー最大 RSS は3回中最大で636.3 MiBから483.4 MiB。無変更の Examples は両版とも実検査ゼロで、軽い std 編集は両版とも148ステップだった。

空キャッシュで同じ編集を調べると34.860秒で188件すべてを実検査し、3回の再利用時と検証済みのパス集合が一致した。
末端に未定義名を追加した場合は、再利用時（5.027秒）と空キャッシュ（33.16秒）が同じ位置・メッセージで拒否し、両方ともその末端を検証済みに含めなかった。

同じ未定義名で main と比較すると、温まったシードから拒否までの時間は14.527秒から5.027秒、空キャッシュでは14.265秒から33.160秒になった（各1回）。
main はローカルパッケージの名前解決で先に停止し、前提163件を検証済みと報告する。
変更版は末端に入る前に同一パッケージ内の前提24件も検査するため、空キャッシュのこのエラーでは2,742ステップが17,261ステップに増える。
4通りとも同じエラーを報告し、`Examples` の判定は失敗である。
