## 初回調査時に記録した候補（第2・3回で検証）

`front/src/parse/term_parse.rs` の `parse_sexp_withgoals` は、矢印式を試した後に
矢印がなければカーソルを戻して `parse_combined` を再実行する。
矢印の左辺も `parse_combined` なので、括弧・キーワード引数の入れ子では
同じ部分式を繰り返し読む。`load/library` の約 2.5 秒にも関係する可能性がある。
まず第1回の結果を取り、構文解析の変更は別の比較として実施する。

別の候補として、`Arena::get` はノードを clone するため、Program の
`Case` を評価するときに全分岐の `Vec` と束縛子名の `Vec` を複製する。
実際に必要なのは選ばれた分岐の body ハンドルだけ。
`unfold_value` も定義かどうかを見るだけでコンストラクタの fields を clone する。
参照での読み出しと、割り当て前の借用解除により、この一時的な複製を減らせる可能性がある。

## 第1回: Set/Prop のゼロ幅シフト

### コードから立てた仮説（変更前）

`kernel/src/calculus.rs` の `instantiate_telescope_at` は変数への代入時に
`shift_bound_indices` を呼ぶ。束縛子の内側でなければシフト量は 0 だが、
現実装はこの場合も引数全体を `transform` でたどる。
恒等関数の連鎖では、残りの連鎖を毎回たどるため二次的な仕事が生じる。
また自由変数を同じ添字で再割り当てしてしまう。
Program 側のシフトにはすでに量 0 の早期 return がある。

シフト量 0 なら元の項をそのまま返すことで、意味を変えず走査・割り当てを省けるはず。
主な予測対象は `normalize/beta256`。束縛下の非ゼロシフトと変数捕獲の回避は維持する。

### 変更

`shift_bound_indices` に量 0 の早期 return を追加。
開いた引数をラムダの下へ代入するテストも追加し、必要な非ゼロシフトが
引き続き行われ、変数捕獲を起こさないことを確認する。
基準のプロセスは変更前のビルド済みバイナリで継続しており、完了後に再ビルドする。

## 第2回: 矢印のない式を読み直さない

### 仮説（変更前）

前述の `parse_arrow_expr` は通常の式も左辺として解析済みである。
矢印がなく、左辺が無名の `RightBind` なら、その中の式を返せば再解析が不要になる。
名前付き束縛子や subset 束縛子は単独の式として受理せず、従来の失敗経路を残す。
矢印の右辺の再帰も維持し、右結合と演算子優先順位を変えない。
`parse/mccarthy91` と `load/library`、それらを含む pipeline の大幅改善を予測する。

### 変更と検証

無名の左辺で矢印がなければ解析済みの `SExp` を返す8行を追加。
48段の括弧・`return` の入れ子、application と矢印の優先順位、右結合、
矢印なしの名前付き/subset 束縛子や不完全な式を拒否する回帰テストを追加。
`cargo test --offline --workspace`: 100 テスト成功（CLI 10、front 70、kernel 20）。

## 第3回: Program 評価で読み取り専用のノードを借用する

### 仮説（変更前）

上述の `Case` の全分岐 clone と `unfold_value` の不要な fields clone を省く。
Arena に crate 内限定の借用 API を追加し、簡約ではハンドルだけ取り出す。
新しいノードを割り当てる前に computations の借用を明示的に解除する。
簡約規則・簡約回数・fuel 判定はそのままなので、途中停止する項も変わらないはず。
予測対象は `evaluate/countdown*` と `pipeline/mccarthy91`。

### 変更と検証

`exp.rs` に `borrow_value` / `borrow_computation` を追加。
`reduce_computation_once` はノードを借用し、選ばれた body をコピーしてから
借用を解除する。定義展開の判定と force の thunk 判定も参照で読む。
割り当てや再帰の前に借用を解除し、`RefCell` の実行時借用違反を避ける。

既存100テスト成功。追加した `program_case_preserves_field_order_and_fuel_boundary` も成功。
2つのフィールドを持つ2番目の分岐を選び、代入で新たなノードを割り当てても
引数順序を維持することと、fuel 0/1/2 に対する終了・途中停止を検証した。
